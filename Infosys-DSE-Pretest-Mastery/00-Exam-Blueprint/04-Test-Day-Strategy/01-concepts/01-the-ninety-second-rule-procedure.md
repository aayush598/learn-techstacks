# The 90-Second Rule Procedure

> Section 00 · Exam Blueprint · Test Day Strategy · _Estimated reading time: 16 min_
> **Prerequisite:** [../README.md](../README.md)

## In one sentence
**The procedure is four steps: read the stem, decide by 45 seconds, eliminate by 70 seconds, flag and move by 90 seconds — and never, ever exceed 90 seconds.**

## Why the pre-test tests this
- **The average is exactly 90 seconds** per question, so any question over 90 steals directly from another.
- **Decision over perfection:** the test scores answers, not effort.
- **Recoverability:** flagged questions can be revisited later; lost seconds cannot be recovered.
- **Repetition:** the procedure must be automatic, not something you recall under pressure.

## Core concept

### The four steps
| Step | Time | Action | Exit condition |
|------|------|--------|----------------|
| 1. Read stem | 0-10s | Read the question before the options | You know what is asked |
| 2. Decide | 10-45s | If the method is clear → solve and mark | Answer selected → move |
| 3. Eliminate | 45-70s | Cut wrong options; if a clear answer emerges, mark | Answer selected or 2 options left |
| 4. Flag & move | 70-90s | Best answer, flag, next question | Moved on. **Hard stop at 90s** |

### Section adaptations
| Section | Adaptation |
|---------|------------|
| Aptitude | Skip long DI at step 3 if no clear path |
| English & L&D | Fast reads; the behavioural answer is often obvious |
| DBMS / SQL | Trace small joins; if the table is large, eliminate |
| Java | Trace with a variable table; spot compile errors first |

### The practice protocol
1. Run a 10-question set with a visible 90-second timer per question.
2. Mark every over-run (any question past 90 seconds).
3. Review why you over-ran: knowledge gap or pacing gap.
4. Repeat until a full set has zero over-runs.

### Why the boundaries are where they are
| Boundary | Reason |
|----------|--------|
| 10s to read stem | Reading options first wastes time on distractors |
| 45s to decide | If the method is not visible by 45s, it rarely appears later |
| 70s to flag | Flagging is action; staring is not |
| 90s hard stop | In practice, treat it as absolute so the real test stays on budget |

## Worked example
**Ananya's number series.**

The series: `2, 6, 12, 20, 30, ?`

- **20s:** no pattern visible.
- **45s:** she notes the differences are 4, 6, 8, 10 — increasing by 2.
- **60s:** the next difference is 12, so `30 + 12 = 42`.
- **70s:** she marks **42**, flags it (she wants to verify in review), and moves.

**Outcome:** she used 60 of her 90 seconds and banked 30 seconds she later spent on an easy percentage question. Had she stared to 150 seconds to "be sure", she would have lost the percentage question's guaranteed mark. The rule converted a potential cascade into a net gain.

### The cascade math
| Behaviour | Time on the series | Effect on the next question |
|-----------|--------------------|-----------------------------|
| Follow the rule | 60s | 30s surplus → percentage answered correctly |
| Stall to 150s | 150s | 60s deficit → percentage rushed and wrong |

## Quick rules
- **Read the stem first.**
- **45 seconds is the decision point.**
- **70 seconds is the flag point.**
- **90 seconds is the hard cap.**
- **Review only with surplus time.**
- **Never restart a question mid-way.**

## Common traps
- **Solving slowly instead of deciding** at 45 seconds.
- **Treating 90 seconds as a target** instead of a ceiling.
- **Not practicing with a timer**, so the rule stays theoretical.
- **Ignoring over-runs in practice**, which trains the exact habit that fails the real test.

## Checklist
- [ ] You can run all four steps automatically.
- [ ] You use a visible timer in practice.
- [ ] You never exceed 90 seconds in drills.
- [ ] You know your review rule (flagged only).
- [ ] You track over-runs and drive them to zero.
- [ ] You never restart a question mid-way.
