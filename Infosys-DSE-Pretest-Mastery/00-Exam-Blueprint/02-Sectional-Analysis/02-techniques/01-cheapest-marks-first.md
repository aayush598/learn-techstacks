# Cheapest Marks First

> Section 00 · Exam Blueprint · Sectional Analysis · _Estimated reading time: 15 min_
> **Prerequisite:** [../01-concepts/05-score-model-building-39.md](../01-concepts/05-score-model-building-39.md)

## In one sentence
**Attack the cheapest marks first — the fastest, highest-certainty questions across all sections — before any expensive derivation.**

## Why the pre-test tests this
- **ROI:** the points-per-minute differs by two to three times across archetypes, so order matters as much as knowledge.
- **Confidence:** early sure marks reduce panic, which matters for candidates like Meera.
- **Margin:** cheap marks build the buffer above 39 that lets you absorb mistakes later.
- **Time:** every expensive question you do first steals time from two cheap ones.

## Core concept

### The cheap-marks ranking (across all sections)
| Rank | Archetype | Section | Why cheap |
|------|-----------|---------|-----------|
| 1 | ACID / normalization definitions | DBMS | Recall, no calculation |
| 2 | Behavioural / etiquette scenarios | English & L&D | A single intended answer, fast read |
| 3 | Data sufficiency | Aptitude | Structured, low calculation |
| 4 | Compile/execute identification (obvious errors) | Java | Spot the single error |
| 5 | Ranking / inequalities | Aptitude | Symbol logic, no arithmetic |
| 6 | Common collections output | Java | Memorised behaviour |
| 7 | Error correction | English & L&D | Find the one flawed part |
| 8 | Basic JOIN output | DBMS | Trace two small tables |
| 9 | Percentages | Aptitude | Formula plus a shortcut |
| 10 | Standard pseudo-code output | Java | Trace with a variable table |

### The expensive archetypes (do last, if at all)
- Long data interpretation (Aptitude).
- Obscure number series (Aptitude).
- Multi-condition two-table query writing (DBMS).
- Nested inner-class scoping output (Java).

### The procedure
1. On each question, classify it in about two seconds: **cheap / medium / expensive**.
2. Do all cheap questions across the paper first, if the section order allows it.
3. Do the medium ones next.
4. Attempt expensive ones only with surplus time or when you are close.
5. Flag rather than force when an expensive one resists.

### Classification cues
| Cue you see | Likely class |
|-------------|--------------|
| "Which of the following is a property of..." | Cheap |
| A short SQL snippet with two tables | Medium |
| A data table with four columns and three questions | Expensive |
| Code with nested classes and access modifiers | Expensive |
| A behavioural workplace scenario | Cheap |

## Worked example
**Ananya's first eight minutes.** She starts the paper and deliberately ignores section order. In her first eight minutes she completes:
- 3 DBMS theory questions (ACID, normalization, keys) — 3 marks.
- 3 English behavioural questions — 3 marks.
- 2 data-sufficiency questions — 2 marks.

That is **8 marks banked in about six minutes** — 1.33 marks per minute, well above the pace line. She now has a margin over the 39 line and spends the rest of the test protecting it.

**Contrast:** a candidate who starts with the long DI set burns five minutes for one mark (0.2 marks per minute). Over ten such questions, that candidate is 10+ minutes behind with the same marks.

### When NOT to chase cheap marks
If the section order is fixed and you cannot jump between sections, then classify *within* the current section: do the cheap items in that section first, then the medium, then flag the expensive.

## Quick rules
- **Classify each question in about two seconds.**
- **Do cheap questions first, across the whole paper if allowed.**
- **Attempt expensive questions only with surplus time.**
- **Flag, do not force.**
- **Bank margin early, defend it late.**
- **Aim for 1+ mark per minute in the harvest phase.**

## Common traps
- **Section-order lock-in** — finishing a section before jumping to a cheaper one elsewhere.
- **Misclassifying a data-interpretation set as cheap** because the question looks short.
- **Forgetting to revisit medium questions** you deferred.
- **Spending cheap-marks time on review loops** instead of new cheap marks.

## Checklist
- [ ] You can rank the archetypes by cost from memory.
- [ ] You classify each question in roughly two seconds.
- [ ] You do cheap questions first.
- [ ] You attempt expensive ones only with surplus time.
- [ ] You defend your early margin rather than gambling it.
- [ ] You know how to classify within a section when order is fixed.
