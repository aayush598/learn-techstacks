# The Two Variants

> Section 00 · Exam Blueprint · Pretest History And Variants · _Estimated reading time: 15 min_
> **Prerequisite:** [01-how-the-pretest-evolved.md](01-how-the-pretest-evolved.md)

## In one sentence
**Candidates report two formats — the off-campus DSE pre-test and the broader standard online assessment — and you should prepare the shared core, not one specific version.**

## Why the pre-test tests this
- **Different drives, different formats.**
- **The overlap is large:** the topics barely change between variants.
- **Adaptation:** the first two minutes of any test tell you which variant you are in.
- **Resource efficiency:** the overlap is the highest-return study area.

## Core concept

### The variant comparison
| Aspect | Off-campus DSE pre-test | Standard online assessment |
|--------|-------------------------|----------------------------|
| Primary purpose | Gate to DSE stream selection | Broad screening (aptitude + logic + coding) |
| Sections | Aptitude, English & L&D, DBMS/SQL, Java problem-solving | Aptitude/logical + English + (sometimes) coding |
| Java weight | Highest (25 reported) | May be lower or coding-round based |
| DBMS / SQL | Present (10 reported) | May be absent or folded into technical |
| Gate | 39/60 unlocks stream selection | Varies by drive |
| Topics | Recurring archetypes | Recurring archetypes |

### The overlap (study this)
| Area | Present in both? |
|------|------------------|
| Aptitude (series, percentages, ranking, inequalities) | ✅ |
| English (error correction, usage) | ✅ |
| Logical reasoning | ✅ |
| Java / programming fundamentals | ✅ (in technical or coding form) |
| DBMS / SQL | ⚠️ DSE-specific more likely |
| Behavioural / L&D | ⚠️ DSE-specific more likely |

### The adaptation procedure
1. Read the live instructions (0:00-0:02).
2. Identify the variant from the section names and counts.
3. Re-plan your time budgets against the actual sections.
4. Protect the largest section, whatever its name.
5. Apply the 90-second rule throughout.

### Why the overlap is where to invest
If you study only the DSE-specific parts (behavioural, DBMS), you are exposed if the drive uses the broader format. If you study only the broad parts (aptitude, logic), you are exposed if the drive uses the DSE format. The overlap is the safe, high-return core.

## Worked example
**Ananya expected the DSE variant** — four sections — but the live test shows a single aptitude-plus-coding layout (the standard variant).

1. She notes the change within 90 seconds.
2. She re-plans: bank the aptitude questions first, then move to the coding output/compile questions she recognises.
3. Because she drilled topics rather than counts, she adapts within three minutes and loses almost no marks.
4. Had she expected a DBMS section and found none, she redirects that time to the coding section instead of waiting.

**Net:** the surprise cost her roughly 90 seconds, not three minutes of panic, because her preparation was topic-first.

### Common variant mixes
| Observed mix | Prepare |
|--------------|---------|
| Four DSE sections | The full DSE core |
| Aptitude + English only | Focus aptitude and language |
| Aptitude + coding | Add Java compile/output |

## Quick rules
- **Two variants, one overlap.**
- **The advantage is the shared core, not shared counts.**
- **Identify the variant in the first two minutes.**
- **Re-plan budgets to the live sections.**
- **Protect the largest section.**
- **Prepare topics, not counts.**

## Common traps
- **Preparing only for one variant.**
- **Refusing to adapt when the format differs.**
- **Ignoring coding if you expected only MCQs.**
- **Wasting time mourning the expected format.**

## Checklist
- [ ] You know both variants.
- [ ] You know the overlap.
- [ ] You have an adaptation procedure ready.
- [ ] You will identify the variant fast.
- [ ] You protect the largest section.
- [ ] You prepared topic-first, not count-first.
