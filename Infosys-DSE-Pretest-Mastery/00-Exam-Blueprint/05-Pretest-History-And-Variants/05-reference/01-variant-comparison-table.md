# Variant And Constants Reference

> Section 00 · Exam Blueprint · Pretest History And Variants · _Estimated reading time: 12 min_
> **Prerequisite:** [../01-concepts/02-the-two-variants.md](../01-concepts/02-the-two-variants.md)

## In one sentence
**One page: the two variants side by side, the constants, and the live-config checklist.**

## Why the pre-test tests this
- **Single-page revision:** the variant facts in one place.
- **Mid-test reference:** the constants and the live-config checklist.
- **Calm under variance:** a reminder that topics are constant.
- **Practice calibration:** check a mock's format against these tables.

## Core concept

### The variants
| Aspect | Off-campus DSE pre-test | Standard online assessment |
|--------|-------------------------|----------------------------|
| Sections | Aptitude, English & L&D, DBMS/SQL, Java | Aptitude/logical + English (+ coding) |
| Java weight | Highest (25 reported) | Varies |
| DBMS / SQL | Reported ~10 | May be absent |
| Gate | 39/60 unlocks stream selection | Varies by drive |

### Constants vs variables
| Constant | Variable |
|----------|----------|
| 90-second pressure in a 60×90 format | Counts |
| Core topics (aptitude, English, SQL, Java) | Order |
| Stream selection gated by clearing | Negative marking |
| Recurring archetypes | Section presence |

### The guaranteed core topics
| Section | Topics |
|---------|--------|
| Aptitude | data sufficiency, percentages, DI, ranking, inequalities, series, mixtures |
| English & L&D | behavioural, professionalism/etiquette, error correction |
| DBMS / SQL | SQL up to JOINs, two-table query, output ID, normalization, ACID, theory |
| Java | OOPs, interfaces/inner classes, packages/access modifiers, collections, exceptions, output prediction, compile/execute |

### The live-config checklist
- [ ] Penalty / marks per question noted
- [ ] Actual counts noted
- [ ] Largest section identified
- [ ] Budgets set
- [ ] Start with cheap marks

## Worked example
**Applying the reference to a surprise.** A candidate expecting the DSE variant (10/15/10/25) finds the live test is 12/13/8/25 with a −0.25 penalty and Java first. Using this page:
- Constants confirm the topics are unchanged, so no knowledge is wasted.
- Variables confirm the counts changed, so budgets shift: 16 / 20 / 14 / 34 minutes.
- The largest section is still Java (25), so it is still protected.
- The penalty changes the guess rule to "eliminate two, then guess".

**Result:** the candidate re-plans in under two minutes and starts with cheap marks. The reference page turned a surprise into a routine adjustment.

## Quick rules
- **Two variants, one overlap.**
- **Constants: pressure, topics, gate.**
- **Variables: counts, order, penalties.**
- **Two-minute live config.**
- **Topic-first preparation.**
- **Protect the largest section.**

## Common traps
- **Trusting one variant's counts.**
- **Skipping the live-config step.**
- **Ignoring the constant core.**

## Checklist
- [ ] You know both variants.
- [ ] You know the constants.
- [ ] You will run live config.
- [ ] You prepare the core.
- [ ] You adapt calmly.
- [ ] You protect the largest section.
