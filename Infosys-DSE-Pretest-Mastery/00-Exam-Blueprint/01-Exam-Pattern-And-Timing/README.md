# 01 - Exam Pattern And Timing

> Section 00 · Exam Blueprint · Exam Pattern And Timing · _Estimated reading time: 10 min_
> **Prerequisite:** [../README.md](../README.md)

## In one sentence
**Treat the pre-test as a 90-minute time puzzle:** 60 questions at 90 seconds average with asymmetric section weights and batch-varying details.

## Why the pre-test tests this
- **Pacing:** forces you to choose between "solve fully" and "move on" repeatedly.
- **Prioritisation:** 25 Java questions vs 10 Aptitude — allocation must match weight.
- **Discipline:** the 90-second rule is the only sustainable way across all sections.
- **Honesty:** reading live instructions is required due to batch variation.

## Core concept

### Pattern table
| Item | Value | Notes |
|------|-------|-------|
| Questions | 60 | MCQ objective |
| Time | 90 minutes | No stated universal extra time guaranteed |
| Per question avg | 90 seconds | Mathematical average |
| Pass | 65% (39/60) | Unlocks stream selection |
| Negative marking | Varies by batch | Assume possible until live states otherwise |
| Order | Can vary | Do not rely on fixed order |

### Per-second/section budget (planning baseline)
| Section | Q | Reported budget | Seconds/Q (budget) | Focus |
|---------|---|-----------------|--------------------|-------|
| Aptitude | 10 | ~15 min (900s) | 90s | Pick easiest 5-7 first |
| English & L&D | 15 | ~22 min (1320s) | 88s | Fastest scoring if accurate |
| DBMS/SQL | 10 | ~18 min (1080s) | 108s | Slightly more headroom, predictable |
| Java problem-solving | 25 | ~35 min (2100s) | 84s | Largest pool, do known output-prediction first |
| **Total** | **60** | **90 min** | **90s avg** | Balance by weight |

### Minute-by-minute feel
| Phase | Time | Goal |
|-------|------|------|
| 0-10 min | Warm up | Read instructions fully; do 6-8 questions you know well (don't stall) |
| 10-30 min | Build rhythm | Hit easy ones across sections if order allows; flag hard ones |
| 30-60 min | Mid-game | Cover weaker-but-doable; avoid new long derivations |
| 60-75 min | Tighten | Review flagged; prefer high-probability to time sinks |
| 75-90 min | Final sweep | Fill safe guesses only if instructed; verify no unmarked easy ones |

## Worked example
**Karthik's retrospective:** "In my attempt, Java looked long. I wasted 110s on one inheritance question at 40 min and had to rush 5 Java output questions. Next time I would flag at 70s and take 2 safe ones later if time remained. I passed, but I left points on table."

**Apply:** set a mental timer. If unsure at 70s, eliminate to best guess, flag, move. Do not cross 90s.

## Quick rules
- **90-second rule:** know→mark+move (<=45s), unsure→eliminate (45-70s), stuck→best guess+flag+move (70-90s), never >90s.
- **Read stem first:** saves time on long options.
- **Order is fluid:** attack by solvability, not section order blindly.
- **Budget by weight:** Java 25 deserves protection from time sinks.
- **Live instructions win:** if live says negative marking different, adjust guessing strictly.

## Common traps
- **Averaging trap:** 90s average means some take 60s, some need 90s — you cannot "save" for all.
- **Section lock-in:** refusing to leave a section at cost of easier questions later.
- **Counting minutes, not questions:** track "questions left / minutes left" at checkpoints.
- **Assuming fixed timing:** budgets above are planning baselines, not mandates.

## Checklist
- [ ] You can recite 60/90 and 90s.
- [ ] You have a 70s flag point.
- [ ] You plan to read live instructions first.
- [ ] You will track questions-left every 15 min.
- [ ] You know Java is 25 questions.
