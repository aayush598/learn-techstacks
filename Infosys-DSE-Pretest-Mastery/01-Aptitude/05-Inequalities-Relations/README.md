# Inequalities & Relations — Topic Guide

> Section 1 · Aptitude · Inequalities & Relations · _Estimated reading time: 30 min for the full topic_

## What the pre-test asks in this topic

The DSE pre-test's aptitude section includes **1 inequality/relation question**, usually one of these
formats:

1. **Chain decoding** — "If `a > b < n ≥ i < p`, which of the following is definitely true?" with four
   relational options.
2. **Always / sometimes true** — "Which statement is always true?" / "Which is sometimes true?"
3. **Coded relations** — a symbol key (`p # q` means p is greater than q) applied to a chain.
4. **Statements I and II** — "Statement I: … Statement II: … A. Only I  B. Only II  C. Both  D.
   Neither".
5. **Ordering with names** — "Rahul > Meera > Ananya. Who scored the least?" applied to marks, ages or
   ranks.

All five reduce to the same five moves. Learn the moves, not the questions.

## Learning objectives

After this topic you should be able to:

- Decode a mixed chain such as `a > b < n ≥ i < p` into its four component relations.
- Apply the **"the sign points at the smaller element"** rule to find local minima and maxima.
- Use transitivity correctly — and know exactly when it does **not** apply.
- Track strict (`>`) versus non-strict (`≥`) relations through a chain.
- Identify which element is the minimum or maximum of a group, and which claims are merely local.
- Reject an "always true" claim by constructing **one** counterexample that still satisfies the chain.
- Confirm a "sometimes true" claim with one valid example.
- Decode a coded relation and then solve it as a plain chain.
- Answer the Statements-I-and-II format by testing each statement independently.
- Finish an inequality question in **30–45 seconds**.

## Quick 3-step solving procedure

1. **Split** the chain into pairs at every symbol (5 s) and **point** at the smaller element in each
   pair (5 s).
2. **Chain** inside one direction only, keeping `>` and `≥` distinct (10 s).
3. **Test** each option against the pair list, and for every "definitely true" option you reject,
   build one counterexample (10–15 s). Then mark.

## Key takeaways

- ✅ **Split into pairs first.** It stops the "read the whole chain as one run" error.
- ✅ **The sign points at the smaller value.** Two signs pointing at one element ⇒ local minimum.
- ✅ **Transitivity runs one way only.** A direction change ends the chain.
- ✅ **One strict link makes the conclusion strict.** `≥` + `>` ⇒ `>`.
- ✅ **Equality kills strictness.** `b ≥ c = d` ⇒ `b ≥ d`.
- ✅ **Reject "always true" with one counterexample**; confirm "sometimes true" with one example.
- ✅ **A maximum must dominate every element** mentioned.
- ⚠️ **Meera's warning:** she tries to "feel" which option is true. Feeling fails; pairs do not.
