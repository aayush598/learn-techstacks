# Compliance Consulting: SOC 2, HIPAA, GDPR, PCI-DSS

## Overview

Compliance consulting is the highest-paying cybersecurity freelancing niche. Companies MUST achieve and maintain compliance certifications to:
1. Close enterprise deals (customers require SOC 2)
2. Process payments (PCI DSS)
3. Handle health data (HIPAA)
4. Operate in the EU (GDPR)
5. Get cyber insurance (increasingly requires compliance)

This demand creates a massive opportunity for consultants who understand compliance frameworks AND can help companies implement the technical controls.

3. **Recurring revenue**: Compliance is annual/continuous — not one-time
4. **High barrier**: Most developers don't understand compliance
5. **Premium clients**: Funded startups and enterprises have budget

## Understanding the Compliance Market

### SOC 2 (Biggest Market)

**What it is**: Service Organization Control 2 — a framework for managing customer data. Most SaaS companies NEED SOC 2 to sell to enterprise.

**Why companies pursue SOC 2**:
- Enterprise customers demand it
- Acts as competitive differentiator
- Cyber insurance often requires it
- Shows security maturity to investors

**Who needs SOC 2**:
- B2B SaaS companies (any that handle customer data)
- Cloud service providers
- Data processing companies

**Market size**: Thousands of startups get SOC 2 certified every year. Each needs a consultant.

**Typical timeline**: 4-12 months from start to certification
**Audit cost**: $15-40K/year (auditor fee, separate from your fee)
**Your fee**: $30-100K for end-to-end engagement

### HIPAA (Highest Stakes)

**What it is**: Health Insurance Portability and Accountability Act — US healthcare data regulation.

**Why companies need it**:
- Handling protected health information (PHI)
- Working with healthcare providers, insurers, or patients
- Fines up to $1.5M/year for violations

**Who needs HIPAA compliance**:
- Healthcare SaaS companies
- Medical device companies
- Telehealth platforms
- Health insurance technology
- Companies that process health data (even fitness apps in some cases)

**Key challenge**: HIPAA is more prescriptive than SOC 2. Specific technical controls required.

### GDPR (European Market)

**What it is**: General Data Protection Regulation — EU data privacy law.

**Why companies need it**:
- Serving EU customers
- Processing EU personal data
- Fines up to 4% of global revenue or 20M euros (whichever is higher)

**Who needs GDPR compliance**:
- Any company with EU users/customers
- Companies that process EU personal data
- Often combined with other compliance frameworks

### PCI DSS (Payment Processing)

**What it is**: Payment Card Industry Data Security Standard.

**Why companies need it**:
- Processing credit card payments
- Fines for non-compliance
- Increased transaction fees if non-compliant

**Who needs PCI DSS**:
- E-commerce companies
- Payment processors
- Any business accepting credit cards

**Note**: Using Stripe/Braintree/etc. reduces scope significantly. Most SaaS companies only need SAQ A (simplest level) if they use a third-party payment processor.

## Technical Skills Required

### Compliance Knowledge (Core)

1. **SOC 2**: Understand Trust Service Criteria (Security, Availability, Processing Integrity, Confidentiality, Privacy). Most clients only need the Security category (common criteria).
2. **HIPAA**: Understand Privacy Rule, Security Rule (Administrative, Physical, Technical Safeguards), Breach Notification Rule. Know what PHI is.
3. **GDPR**: Understand lawful basis for processing, data subject rights, consent, DPIA, breach notification, cross-border data transfers.
4. **PCI DSS**: Understand the 12 requirements, SAQ levels, scope reduction.
5. **Risk assessment methodology**: NIST RMF, ISO 31000, or similar.

### Technical Skills (For Implementation)

**Identity and Access Management**:
- SSO providers: Okta, Azure AD, Google Workspace, OneLogin
- MFA implementation
- Provisioning/deprovisioning automation (SCIM)
- Just-in-time access, privileged access management

**Cloud Security**:
- AWS: IAM, CloudTrail, GuardDuty, Security Hub, Config, KMS
- GCP: Cloud Audit Logs, Security Command Center, IAM, Cloud KMS
- Azure: Defender for Cloud, Azure AD, Key Vault, Monitor

**Monitoring and Logging**:
- SIEM: Splunk, ELK, Sumo Logic, Datadog Security
- Audit logging: CloudTrail, Azure Monitor, GCP Audit Logs
- Intrusion detection: WAF, IDS/IPS

**Data Protection**:
- Encryption at rest: KMS, Cloud KMS, Azure Key Vault
- Encryption in transit: TLS configuration
- Data classification and DLP
- Backups and disaster recovery

**Vulnerability Management**:
- Scanning tools: Qualys, Nessus, Wiz, Lacework, Snyk
- Penetration testing (partner with pentesters)
- Patch management

8. **Business continuity plan template**
9. **Audit preparation checklist** (what to have ready)
10. **Project plan template** (timeline for SOC 2/HIPAA/etc.)

### Create a Compliance Automation Package

Instead of manually gathering evidence, set up automation:
- Cloud resource configuration checks (Terraform + Sentinel, AWS Config rules)
- Automated user access reviews (script checks all accounts)
- Automated vulnerability scanning schedule
- Automated log retention and archival
- Automated backup verification

## Common Mistakes

### Mistake 1: Making Compliance Too Hard

**Problem**: You recommend every control possible. Client is overwhelmed.

**Solution**: Focus on what's REQUIRED, not what's possible. SOC 2 is flexible. You can choose which controls to implement based on risk. Start with the minimum viable compliance and expand.

### Mistake 2: Not Understanding the Business

**Problem**: You recommend controls that break engineering velocity.

**Solution**: Understand how the company operates. Recommend controls that work with their workflow, not against it. Example: Instead of mandatory code review (slows down engineering), use automated scanning and post-deployment monitoring.

### Mistake 3: Doing Everything Manually

**Problem**: You manually collect evidence each quarter.

**Solution**: Automate evidence collection from day one. Use Vanta/Drata/SecureFrame. Write scripts to collect infrastructure evidence. This saves you AND the client time.

### Mistake 4: Overpromising Timeline

**Problem**: "You can get SOC 2 in 2 months!" (reality: 6+ months)

**Solution**: Be realistic. SOC 2 Type I takes 3-6 months minimum. Type II takes 6-12 months. Better to underpromise and overdeliver.

### Mistake 5: Ignoring the Human Element

**Problem**: You write policies but don't train employees.

**Solution**: Compliance is 20% controls, 80% culture. Spend time training employees, building security awareness, and creating a culture of compliance.
