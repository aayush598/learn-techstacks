# 05 - AFTER-REPAIR VERIFICATION

**Folder:** `05-MAINTENANCE-REPAIR/02-Breakdown-Repair/`

---

## 1. PURPOSE

Payment is the point where abuse hides. In the old system money left the
pocket on the repairer's word. This rule makes **proof a precondition of
payment** (P6): the work is verified first, by someone who did not do it, and
only then is a rupee released.

## 2. THE VERIFICATION PRINCIPLE

> **The repairer never verifies their own work. The payer never pays without
> verification. Verification is performed by a member who was not the
> repairer.**

## 3. WHO VERIFIES

1. Verification is done by a **member who did not perform the repair** and who
   is not a party to it — preferably the witness from the approval step, or a
   member drawn for the purpose.
2. If the repair was done by a skilled member, verification is done by a
   different member; if it was done by a vendor, verification is done by a
   member or by a second technician named in the fault record.
3. The verifier is not paid by the repairer and holds no personal relation to
   the repairer's vendor.

## 4. WHAT VERIFICATION INCLUDES

| Check | Detail |
|-------|--------|
| **Against the diagnosis and quote** | Was the fault from the record actually addressed? Was the quoted part actually replaced? |
| **Visual inspection** | Workmanship, wiring, joints, cleanliness, panel closed and locked |
| **Test run** | Motor started and run for a test period; water flows to the end taps; current draw and noise normal |
| **Warranty note** | Vendor's written warranty with date and scope, kept with the fault record |
| **Before/after photos** | Where photos exist in the fault record, the end state is matched |
| **Documents** | Invoice matches the approved quote; no extra unapproved line items |

## 5. VERIFICATION RECORD

The verifier signs a short verification note under the fault number:

| Field | Value |
|-------|-------|
| Fault number | |
| Repair claimed complete on | |
| Verified on | |
| Verified by (name, not the repairer) | |
| Items verified | |
| Test-run result (amps, flow, noise) | |
| Warranty note captured (Y/N) | |
| Result: PASS / DEFECT / PARTIAL | |
| Remarks | |

## 6. OUTCOMES

| Result | Consequence |
|--------|-------------|
| **PASS** | Payment is authorized; voucher raised (`06-FINANCE/03-Bookkeeping/02-Expense-Voucher-Rule.md`) |
| **DEFECT** | Repairer returns; the fault record stays open; deadlines restart for the defect only |
| **PARTIAL** | Payment for the verified portion only; balance withheld until the rest passes |

A fault is **closed** only when the verification note says PASS and is signed.

## 7. PAYMENT ONLY AFTER VERIFICATION

1. The Finance Committee releases payment only on: an approved fault record,
   a PASS verification note, the vendor invoice, and a voucher.
2. **No verification, no payment** — regardless of how loudly the vendor or
   anyone else presses.
3. If the repairer demands advance payment for large parts, the assembly may
   authorize up to 30% advance against a written receipt and a written
   delivery date; the balance is paid only after verification. The advance is
   recorded under the fault number.

## 8. SCENARIO — THE UNVERIFIED "REPAIR"

A vendor says the motor is rewound and demands full payment. A member who was
not the repairer checks: the winding test reads low, the noise is unchanged,
and the flow is no better than before. Verification is DEFECT. The vendor
returns, the real fault is found, and payment is released only after the test
run passes. Had the colony paid first, the money would have been gone and the
"repair" would have been invisible.
