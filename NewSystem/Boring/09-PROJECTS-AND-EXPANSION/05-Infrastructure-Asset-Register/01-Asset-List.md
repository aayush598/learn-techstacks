# INFRASTRUCTURE ASSET REGISTER — ASSET LIST

**Folder:** `09-PROJECTS-AND-EXPANSION/05-Infrastructure-Asset-Register/`

---

## 1. WHY THIS FILE EXISTS

In the old system nobody knew what the colony owned. A motor bought by a
committee member vanished into "his" shed; a boring drilled by a family was
"their" boring; scrap sales went unrecorded. The Asset Register makes every
physical asset visible, numbered, and common property on paper (P1, P6).

## 2. WHAT THE REGISTER CONTAINS

Every asset of the system, including:

| Category | Examples |
|----------|----------|
| Water source | Boring(s), casing, screen, well head |
| Pumping | Motor, pump, control panel, starter, MCB |
| Delivery | Delivery pipe, check valve, cable |
| Network | Distribution pipes by section, joints, valves |
| Connections | Taps, standpipes, meters |
| Storage | Overhead tank, sump, covers |
| Tools and instruments | Wrenches, pressure gauge, test instruments, keys |
| Other | Filtration/treatment units, shed, lockers |

A boring, motor, or tank bought by an individual and later taken over by the
system is entered with its full history — date, cost, and the resolution by
which it became common property.

## 3. THE FIELDS

| Field | Meaning |
|-------|---------|
| Asset ID | Unique number, e.g., A-001 |
| Description | Motor, 1.5 HP, make X |
| Make / model | |
| Serial number | From invoice or body stamp |
| Purchase date | |
| Cost | Invoice value |
| Warranty end | From warranty register |
| Location | Motor room / tank / plot etc. |
| Status | In service / spare / condemned / sold |
| Remarks | Repairs, history |

The warranty register (`02-New-Motor-Installation/04-Warranty-Management.md`)
is cross-linked by asset ID.

## 4. WHO MAINTAINS IT — NO SINGLE POINT OF FAILURE (P3)

1. A rotating **Asset Register Keeper** maintains the register, with one backup
   keeper, in the same spirit as the Registry Keeper
   (`01-MEMBERSHIP/04-Member-Registry/02-Registry-Keeper-Rotation.md`).
2. No single family holds the only copy: the register exists in the physical
   file and in digital copies (`11-LEGAL-AND-COMPLIANCE/03-Records-Retention/03-Digital-and-Physical-Backup.md`).
3. Every member may inspect the register at any time (P6).

## 5. UPDATES

| Event | Action |
|-------|--------|
| New asset (boring, motor, tank, meter) | Entered at project close-out (`01-New-Boring-Installation/05-Project-Close-Out.md`) |
| Repair / replacement part | Remark added with date and cost |
| Warranty change | Updated via the warranty register |
| Disposal / condemnation / scrap sale | Assembly resolution recorded with reason, date, and amount |
| Location move | Updated with date |

A disposal without a recorded assembly resolution is treated as loss or theft
and investigated.

## 6. EXAMPLE FROM COLONY LIFE

Last year's old motor "disappeared." The register shows it: purchase date,
cost, warranty, date condemned, and the scrap sale resolution with the amount
credited to the Common Fund. Nothing was quiet because the register makes the
asset's whole life traceable — and anyone who tries to sell a system asset
without a resolution is found by the paper trail.

## 7. AUDIT

- The register is verified physically at the annual audit: every listed asset
  exists, and every existing asset is listed
  (`06-FINANCE/04-Audit/`).
- A mismatch is a Level 3 matter under the enforcement rules
  (`07-CONFLICT-RESOLUTION/05-Enforcement/`).

---

*What is not on the register is not the system's — and what is on it belongs
to every member, not to the one holding the key.*
