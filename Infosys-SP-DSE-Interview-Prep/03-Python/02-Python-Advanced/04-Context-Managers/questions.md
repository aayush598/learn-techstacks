# Python Advanced — Context Managers Interview Questions and Answers

## Q1: What is a context manager?
**A:** An object with __enter__/__exit__ used with `with` — guaranteeing setup and teardown (files, locks, connections) even on exceptions.

## Q2: What does __exit__ receive?
**A:** (self, exc_type, exc_val, exc_tb); returning True swallows the exception, False propagates it — precise error policy in cleanup.

## Q3: How do you write a context manager with a function?
**A:** @contextlib.contextmanager: yield splits enter/exit; code before yield is setup, after is teardown; try/finally inside handles exceptions.

## Q4: What are common built-in context managers?
**A:** open(), threading.Lock, decimal context, socket closing, subprocess.Popen, tempfile.TemporaryDirectory — the stdlib roster.

## Q5: How do you manage multiple resources at once?
**A:** with A() as a, B() as b: — or contextlib.ExitStack for a dynamic, unknown-at-write-time number of resources.

## Q6: What is contextlib.redirect_stdout?
**A:** Temporarily replaces sys.stdout to capture output — used in CLI testing without patching globals manually.

## Q7: What is the difference between a context manager and a decorator?
**A:** Context managers wrap a block's lifetime with enter/exit; decorators wrap function calls — complementary: timing can be done either way.

## Q8: What is a database transaction context example?
**A:** A context manager that opens a connection, commits on success, rolls back on exception, and always closes — the transactional wrapper pattern.

## Q9: How do you make an object usable in a with statement?
**A:** Implement __enter__ returning the managed object and __exit__ doing cleanup; or use @contextmanager to wrap setup/teardown functions.

## Q10: What is suppress vs catch-and-ignore?
**A:** contextlib.suppress(FileNotFoundError) swallows specified exceptions around a block — clearer than a bare except for expected absence cases.
