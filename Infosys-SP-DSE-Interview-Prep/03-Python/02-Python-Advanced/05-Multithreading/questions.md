# Python Advanced — Multithreading Interview Questions and Answers

## Q1: What is a thread?
**A:** A lightweight unit of execution sharing the process's memory; Python threads enable concurrency for I/O-bound tasks but not CPU parallelism (GIL).

## Q2: What is the GIL and its consequences?
**A:** The Global Interpreter Lock allows one thread to execute Python bytecode at a time — safe but serial; CPU-bound work needs processes (multiprocessing) or native extensions.

## Q3: What is the threading module's basic API?
**A:** threading.Thread(target=fn, args=...), .start(), .join(); lock.acquire/release; Event for signalling; current_thread() for identification.

## Q4: What is a race condition in Python threads?
**A:** Two threads read-modify-write a shared variable concurrently; without a lock, updates can be lost — non-atomic += on a list of shared ints is the classic demo.

## Q5: What is a Lock and how do you use it?
**A:** lock = threading.Lock(); with lock: guards the critical section; a RLock can be re-acquired by the same thread safely.

## Q6: What is the difference between Lock, Condition, and Event?
**A:** Lock: mutual exclusion. Condition: wait/notify on a predicate. Event: a one-shot flag threads wait on — pick per coordination need.

## Q7: What is a Semaphore?
**A:** A counter allowing at most N threads in a section simultaneously (rate-limiting concurrent downloads); primitives from the OS concepts apply.

## Q8: How do threads share data safely?
**A:** Locks, queues.queue (thread-safe FIFO), threading.local() for per-thread data; ThreadPoolExecutor simplifies bounded parallelism.

## Q9: When are threads preferable to asyncio or processes?
**A:** Threads: blocking I/O without rewriting code as async (though GIL shares the core). Processes: true CPU parallelism. asyncio: many concurrent I/O tasks.

## Q10: What is ThreadPoolExecutor?
**A:** concurrent.futures.ThreadPoolExecutor maps calls over a fixed pool — collecting results in order while bounding concurrency; the pragmatic parallelism API.
