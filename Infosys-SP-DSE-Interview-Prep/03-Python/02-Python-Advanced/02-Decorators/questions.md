1. **What is a decorator?**
   - A callable that takes a function/class and returns a modified version: @deco is syntactic sugar for f = deco(f). Used for logging, timing, auth, caching.

2. **How do you write a decorator preserving metadata?**
   - @functools.wraps(f) copies __name__, __doc__, signature from the original onto the wrapper — essential for debugging and introspection.

3. **What is the difference between a decorator taking args and one that doesn't?**
   - A plain decorator receives the function; a parametrised producer (@retry(3)) is a function returning the real decorator — three nested levels.

4. **What is a functools.lru_cache decorator?**
   - Memoises a function's results by arguments — turning recursive Fibonacci/DP calls from exponential to linear with one line.

5. **How do decorators interact with methods?**
   - On methods the decorator sees the (self + args) tuple; classmethod/staticmethod/property themselves are decorators.

6. **What is a class-based decorator?**
   - A class implementing __call__ acts as a stateful decorator — handy when the decoration needs its own attributes and methods.

7. **What is decorator stacking/order?**
   - @a then @b means a(b(f)): decorators apply bottom-up, wrappers execute top-down — remember for layered middleware-style decorators.

8. **What is a property decorated getter/setter?**
   - @property makes accessor logic look like attribute access; @x.setter captures assignment — clean encapsulation with validation.

9. **How do you time a function with decorators?**
   - Wrapping the call in time.perf_counter() and printing the delta — the canonical decorator example used for profiling bottlenecks.

10. **What is a @singledispatch decorator?**
   - Generic function dispatch on first-argument type: @singledispatch registers @f.register(int) implementations — polymorphism without isinstance chains.
