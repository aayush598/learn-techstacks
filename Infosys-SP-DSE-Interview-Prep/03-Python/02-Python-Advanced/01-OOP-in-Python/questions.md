1. **What is a class attribute vs instance attribute?**
   - Class attributes are shared across instances (defined in the class body); instance attributes live per-instance (set in __init__). Assignment to self.x shadows the class attr.

2. **What is __init__ vs __new__?**
   - __new__ constructs/allocates the instance (called first, classmethod); __init__ initialises it. Override __new__ for immutable subclasses or custom allocation.

3. **What is self?**
   - The instance reference passed automatically as the first argument; `self.custom_method()` is `Klass.custom_method(self)` under the hood.

4. **What is inheritance and MRO?**
   - A class inherits attributes from its bases; the MRO (method resolution order) via C3 linearisation decides which attribute wins in diamond patterns — use Klass.__mro__.

5. **What is super()?**
   - super() returns a proxy to the next class in the MRO — enabling cooperative multiple inheritance and correct __init__ chaining.

6. **What is the difference between overloading and overriding?**
   - Override: redefine a method in a subclass (Python supports). Overload: same name multiple signatures — Python has none; emulate with *args/defaults or typing.overload stubs.

7. **What is an abstract base class?**
   - abc.ABC + @abstractmethod forces subclasses to implement methods; instantiation is blocked — enforcing an interface contract.

8. **What is a property and @classmethod/@staticmethod?**
   - property makes methods look like attributes with get/set/del logic; classmethod receives cls (alternate constructors); staticmethod has no implicit first arg.

9. **What is __slots__?**
   - Declaring allowed attributes replaces the per-instance dict with descriptors — less memory and faster attribute access, at the cost of flexibility.

10. **What is duck typing and when is isinstance reasonable?**
   - If it walks and quacks treat it as a duck: rely on behaviour, not type. isinstance(x, abc) is acceptable against ABCs for clear contracts.

11. **What is composition vs inheritance?**
   - Composition (has-a: hold another object) is flexible and preferred; inheritance (is-a) couples hierarchies — the design discussion for maintainable OOP.
