# Python Advanced — Generators And Iterators Interview Questions and Answers

## Q1: What is the difference between an iterator and an iterable?
**A:** Iterable has __iter__ returning an iterator (list, dict, str); iterator has __next__ producing values until StopIteration — every iterator is iterable of itself.

## Q2: What is a generator?
**A:** A function with yield that suspends and resumes — producing a sequence lazily without building a list; memory-efficient streaming.

## Q3: What is the difference between yield and return in a generator?
**A:** yield suspends and returns one value, resuming at the next next(); return raises StopIteration with an optional value (in StopIteration.value).

## Q4: What are generator expressions?
**A:** (x*x for x in range(n)) — lazy counterpart of a list comprehension; no list materialised until consumed; sum/any/all accept them.

## Q5: What is the itertools module and its key functions?
**A:** chain, product, permutations, combinations, groupby, count, islice, takewhile — lazy composition tools for iteration logic.

## Q6: How do you iterate two lists in lockstep efficiently?
**A:** zip(it1, it2) (generator-like) or zip_longest for unequal lengths; avoids manual index bookkeeping.

## Q7: What is a potential infinite generator?
**A:** def naturals(): n=0; while True: yield n; n+=1 — must be consumed with islice/takewhile to avoid unbounded loops.

## Q8: What is StopIteration and how do you manually iterate?
**A:** The signal that a sequence is exhausted; manual pattern: item = next(it, sentinel) to avoid the exception.

## Q9: What is the producer-consumer with generator.send()?
**A:** send() injects values back into a running generator (co-routines pre-async); throw()/close() control lifecycle — the advanced generator API.

## Q10: What is the performance benefit of generators for big data?
**A:** Constant memory: process a chunk, discard it. Loading a 10GB file line-by-line (generator) vs whole list — the core streaming argument.
