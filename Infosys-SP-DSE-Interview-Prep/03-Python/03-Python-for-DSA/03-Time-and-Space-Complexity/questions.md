# Python For Dsa — Time And Space Complexity Interview Questions and Answers

## Q1: What is Big-O notation?
**A:** An asymptotic upper bound characterising how runtime/memory scale with input size: O(1), O(log n), O(n), O(n log n), O(n^2), O(2^n) — ignoring constants and lower-order terms.

## Q2: How do you compute the complexity of nested loops?
**A:** Multiply the iteration counts when inner counts are independent; when inner depends on outer, sum them (e.g., 1+2+...+n = O(n^2)).

## Q3: What is amortised analysis and why are append/pop O(1)?
**A:** Occasional costly resizing is spread over the many cheap operations; dynamic arrays have amortised O(1) append — the 'average over a sequence' view.

## Q4: What is the difference between O(n) and Omega(n)?
**A:** O is an upper bound (worst-case-ish), Omega a lower bound, Theta the tight bound; interviews mostly probe O, but explaining worst vs average vs expected is a win.

## Q5: What is the time complexity of sorting algorithms?
**A:** Quick/Merge/Heap O(n log n) worst (merge/heap guaranteed); Bubble/Insertion O(n^2); Counting/Radix O(n + k) for restricted domains.

## Q6: What is the space complexity of recursion?
**A:** Each active frame occupies O(depth); DFS recursion depth n -> O(n) stack space; converting to iteration or DP usually drops that.

## Q7: How do you analyse a two-pointer algorithm?
**A:** Each pointer moves at most once across the array -> O(n) total even with a nested-ish look — the linear-time argument for sliding-window/2sum-sorted.

## Q8: What does O(log n) usually come from?
**A:** Halving each step: binary search, balanced BST depth, divide-and-conquer merges — logarithmic behaviour signals a halving structure.

## Q9: What is a complexity blow-up example in recursion?
**A:** Naive Fibonacci is O(2^n); memoisation collapses the DAG of overlapping subproblems to O(n) — the cleanest DP motivation interviewers use.

## Q10: What is the trade-off of memoisation/bi-time?
**A:** DP/caching trades memory (O(state) table or dict) for speed; hash collisions keep true worst case O(n) per op but average O(1).
