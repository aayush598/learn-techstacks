1. **What is pytest and how does it differ from unittest?**
   - pytest: function-based tests, plain asserts, fixtures, parametrise, plugins — less boilerplate and richer diagnostics than unittest's class-based style.

2. **How do you write a basic test?**
   - def test_add(): assert add(2,3) == 5 — functions named test_* are discovered automatically; failing asserts show diff-friendly output.

3. **What is a fixture?**
   - @pytest.fixture yields shared setup/teardown (DB, client, model) with scopes (function/module/session) — dependency injection for tests.

4. **What is parametrisation?**
   - @pytest.mark.parametrize('x,y,expected', [(1,1,2),(2,2,4)]) runs the same test over cases — covering edge inputs without duplication.

5. **What is mocking and when do you use it?**
   - unittest.mock.patch replaces external calls (HTTP, DB) with controlled fakes — testing logic without network/flakey dependencies.

6. **What is the difference between assert, and testing exceptions?**
   - with pytest.raises(ValueError): validates that code raises — the negative-path test habit recruiters love.

7. **How do you test a FastAPI/Flask app?**
   - FastAPI: TestClient (httpx) with monkeypatched dependencies; Flask: app.test_client() — both exercise the full request stack.

8. **What is the testing pyramid?**
   - Many unit tests (fast, isolated) -> fewer integration tests (real DB/HTTP) -> few end-to-end tests — proportioning coverage cost/confidence.

9. **What is code coverage and how do you use it?**
   - pytest --cov=app --cov-report=term-missing shows uncovered branches — a metric, not a goal; 100% isn't the point.

10. **How do tests integrate into CI?**
   - GitHub Actions job runs pytest on each PR, failing merges on red — the quality gate wired into your CI/CD pipeline on the resume.

11. **What is a golden/snapshot test?**
   - Storing expected output and comparing — great for serialisation/AI outputs where you freeze known-good behaviour.
