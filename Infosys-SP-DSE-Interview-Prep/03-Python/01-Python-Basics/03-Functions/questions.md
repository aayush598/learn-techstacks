# Python Basics — Functions Interview Questions and Answers

## Q1: What is a function and its components in Python?
**A:** A callable block with parameters, body, and optional return. def defines it; the def line runs at definition time binding a name.

## Q2: What is the difference between positional and keyword arguments?
**A:** Positional: matched by order. Keyword: name=value matched by name — order-free and self-documenting; both can be combined (positional first).

## Q3: What are *args and **kwargs?
**A:** *args collects extra positional args into a tuple; **kwargs collects extra keyword args into a dict; also used for unpacking when calling (*iterable, **mapping).

## Q4: What are default arguments and the mutable-default pitfall?
**A:** Defaults evaluated once at def time; a mutable default (list/dict) persists across calls — the classic shared-state bug. Fix: use None and create inside.

## Q5: What is a lambda?
**A:** An anonymous single-expression function: lambda x: x*2; limited to expressions, no statements/annotations — use for short callbacks (sorted key).

## Q6: What is the difference between return and yield?
**A:** return ends the function giving one value; yield suspends it making a generator — each yield produces one value across multiple next() calls.

## Q7: What is a closure?
**A:** A nested function capturing free variables from its enclosing scope, which persist after the outer returns — the basis of decorators and factory functions.

## Q8: What is the difference between positional-only, keyword-only params?
**A:** / marks positional-only; * marks keyword-only. def f(a, /, b, *, c) forces a positional, b either, c keyword — for clear APIs.

## Q9: What is pure function / side effects?
**A:** Pure: same input -> same output, no external mutation. Side effects: I/O, global mutation, prints. Pure functions are testable and cacheable.

## Q10: How do you type-hint a function?
**A:** def add(x: int, y: int) -> int: — annotations are metadata (not enforced); checked by mypy/pyright. Optional[T], list[T], Callable[...] cover richer signatures.

## Q11: What is the difference between shallow and deep copy related to functions?
**A:** Passing a list into a function passes the reference — mutations leak out. Use copy.copy (shallow) or copy.deepcopy to decouple objects.
