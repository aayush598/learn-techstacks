1. **What is Flask-SQLAlchemy?**
   - The Flask extension wrapping SQLAlchemy with db = SQLAlchemy(app) — models subclass db.Model; sessions bound to request contexts.

2. **What is db.create_all vs migrations?**
   - create_all builds tables from models (dev/tests only); Flask-Migrate (Alembic) version-migrates in production — never create_all against real data.

3. **How do you query in Flask-SQLAlchemy?**
   - Model.query.filter_by(...).all(), .filter(Model.col == x), .order_by(desc(Model.date)), .limit(10).offset(0) — the CRUD query vocabulary.

4. **How do you insert/update/delete rows?**
   - db.session.add(obj) / commit; obj.col = new; commit; db.session.delete(obj); commit — the ORM session/transaction unit.

5. **What is lazy loading in SQLAlchemy?**
   - Relationships load on first access (default) unless eager_loaded with .options(joinedload(...)) — N+1 queries are the main SQLAlchemy perf trap.

6. **What is the N+1 query problem?**
   - Loading N parents then accessing a relation issues N more queries; fix with selectinload/joinedload or explicit joins — a must-know ORM efficiency point.

7. **How do you write raw SQL alongside the ORM?**
   - db.session.execute(text('SELECT ...')) for complex queries — the pragmatic escape hatch when the ORM abstracts too much.

8. **What is a backref and relationship?**
   - db.relationship('Post', backref='author') gives two-way access Post.author and author.posts — concise relational mapping.

9. **How do you handle transactions in Flask?**
   - Each request gets a session; commit at the end or rollback on 500; flask-shell propagates exceptions requiring explicit savepoints for partial success.

10. **What is the JSON column vs normalised tables?**
   - JSON for flexible/semi-structured data; normalised tables for queryable relations — the schema-space trade-off in design discussions.
