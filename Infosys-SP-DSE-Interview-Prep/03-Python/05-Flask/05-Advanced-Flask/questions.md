# Flask — Advanced Flask Interview Questions and Answers

## Q1: How do you secure a Flask API?
**A:** JWT/Flask-JWT-Extended for tokens, password hashing (bcrypt), rate limits, HTTPS, and input validation — the same trust boundary as FastAPI routes.

## Q2: How do you run Flask asynchronously?
**A:** Flask is sync WSGI; async views exist but the threading model stays — gunicorn with gevent/eventlet workers for concurrent I/O at scale.

## Q3: What is a Flask extension you'd recommend and why?
**A:** Flask-SQLAlchemy, Flask-Migrate, Flask-Login, Flask-Session, Flask-CORS — the standard batteries for CRUD apps and APIs.

## Q4: How do you structure a large Flask application?
**A:** Blueprints per feature + app factory + service/repository layers + config module — the scaling structure micro-frameworks require by hand.

## Q5: How do you implement caching in Flask?
**A:** Flask-Caching with in-memory or Redis backend, cached() route decorators, and key invalidation — reducing DB chatter for hot endpoints.

## Q6: How do you send background email in Flask?
**A:** Celery/RQ tasks with a broker (Redis), queued from the view and processed by workers — offloading slow side-effects from the request.

## Q7: How do you write tests for Flask?
**A:** app.test_client() with GET/POST calls, assert status_code/data; separate test DB; pytest fixtures rebuild schema — the unittest discipline you have.

## Q8: What is Flask deploy monitoring?
**A:** Structured logs, request metrics, health endpoints, and error trackers (Sentry) — observability requirements mirror FastAPI deployment.

## Q9: How do you handle file uploads in Flask?
**A:** request.files['file']; validate secure_filename(); stream to storage; never trust client filenames — upload security patterns.

## Q10: What is Flask session vs cookies?
**A:** session is a signed cookie (client-side store, validated server-side); Flask-Session moves it server-side — the auth-state design discussion.

## Q11: How do you version Flask APIs?
**A:** Blueprint per version (/api/v1, /api/v2) or Accept header; keep old versions during deprecation — the same API-evolution guidance as FastAPI.
