# Flask — Routing Interview Questions and Answers

## Q1: How do you define routes with dynamic segments?
**A:** @app.route('/items/<int:item_id>') — converters parse path segments; unmatched types give 404 automatically.

## Q2: How do you read query strings in a view?
**A:** request.args.get('q', '') — werkzeug MultiDict handles duplicate keys; request.values merges form + args.

## Q3: How do you accept POST/form data?
**A:** request.form for urlencoded, request.json (or request.get_json()) for JSON — method='POST' on the route controls access.

## Q4: What are HTTP methods on a single route?
**A:** @app.route('/', methods=['GET','POST']) with request.method branching inside, or separate functions per method via a dispatch.

## Q5: How do you build URLs / redirects?
**A:** url_for('view_name', arg=1) generates URLs by endpoint name; redirect(url_for(...)) sends 302 — reverse routing keeps links stable.

## Q6: What is a 404 handler?
**A:** @app.errorhandler(404) customises the not-found page/JSON — building friendly errors audiences expect.

## Q7: What are route names and how does Flask look them up?
**A:** Each view's name becomes an endpoint; blueprints prefix it (bp.view); url_for uses that full name — naming discipline matters in templates.

## Q8: How do you handle trailing slashes?
**A:** Flask redirects /path/ -> /path depending on route definition strict_slashes — a common gotcha in mounting.

## Q9: What is before_request vs after_request?
**A:** @app.before_request hooks run pre-route (auth, db); @app.after_request post-route (headers, caching) — Flask's middleware-style hooks.

## Q10: What is an errorhandler exception type?
**A:** @app.errorhandler(MyError) custom exception -> response mapping; combining with raise lets views fail cleanly.
