# Flask — Flask Basics Interview Questions and Answers

## Q1: What is Flask and its design philosophy?
**A:** A micro web framework with just routing/request/response core; extensions add DB, auth, forms — simple and explicit, WSGI-based.

## Q2: What is the app object and application factory?
**A:** Flask(__name__) creates the WSGI app; a create_app() factory builds and returns it — supporting configurations per environment and testability.

## Q3: What is the difference between a route decorator and a route with rules?
**A:** @app.route('/user/<int:user_id>') maps paths with converters (int, string, float) — Flask's URL parameter handling.

## Q4: How does Flask serve requests?
**A:** The built-in dev server (app.run) is for development; production uses gunicorn/waitress/uWSGI — WSGI servers, not threaded toy servers.

## Q5: What is the Flask request/response cycle?
**A:** WSGI hands the environ -> Flask builds a request context -> view function -> response -> WSGI returns it; teardown frees the context.

## Q6: What are Flask blueprints?
**A:** Modular route/staticmethod groups registered on the app — organising large apps into features instead of one monolithic file.

## Q7: What is the Jinja2 relationship to Flask?
**A:** Flask's default template engine — server-side rendering variables, loops, conditions, and template inheritance for HTML pages.

## Q8: What is the app context vs request context?
**A:** App context: app-wide globals (current_app). Request context: per-request data (request, session). Both push/pop around request handling.

## Q9: How do you configure Flask?
**A:** app.config from dicts/env files; SECRET_KEY, DEBUG, DATABASE_URL — configuration segregation across environments.

## Q10: How does Flask compare to FastAPI?
**A:** Flask: simple, sync, WSGI, huge plugin ecosystem. FastAPI: async, typed, auto-docs. Migrating adds async loudly only where needed.
