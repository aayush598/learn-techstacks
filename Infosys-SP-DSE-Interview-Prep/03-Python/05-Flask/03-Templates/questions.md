# Flask — Templates Interview Questions and Answers

## Q1: What is template inheritance?
**A:** A base.html with {% block content %} regions; child templates {% extends 'base.html' %} and override blocks — DRY page layout.

## Q2: What is the Jinja2 variable escaping?
**A:** {{ user.name }} auto-escapes HTML by default to prevent XSS; use |safe only for trusted content — the security-critical detail.

## Q3: How do you loop and branch in templates?
**A:** {% for item in items %} ... {% endfor %} and {% if cond %}: template control flow mirroring Python minus the colons.

## Q4: How do you pass context to templates?
**A:** render_template('x.html', name=name) exposes variables; global template utils (config, url_for) are always available.

## Q5: What are template filters?
**A:** |lower, |date('%Y-%m-%d'), |default('n/a') post-process values in the template — keep formatting in the view layer.

## Q6: What is a macro in Jinja2?
**A:** {% macro input(name) %} reusable template fragments with parameters — rendering components without a JS framework.

## Q7: How do you avoid duplicate HTML with partials?
**A:** {% include '_item.html' %} reuses a snippet; macros parametrise it further — componentising server-rendered pages.

## Q8: What is the difference between {{ }} and {% %}?
**A:** {{ expression }} prints a value; {% statement %} executes logic (if/for/extends/block) — the two Jinja syntactic classes.

## Q9: How does template rendering relate to XSS?
**A:** Auto-escaping neutralises injected <script>; the |safe escape hatch reopens it — never mark user input safe.

## Q10: How do you internationalise templates?
**A:** Jinja2 i18n extensions with gettext-style translations and locale selection — not every app needs it, but the pattern exists.
