1. **How do you connect FastAPI to PostgreSQL?**
   - SQLAlchemy engine + sessionmaker with a DATABASE_URL ('postgresql+psycopg' or asyncpg for async); SQLAlchemy models map tables to classes.

2. **What is SQLAlchemy ORM vs raw SQL?**
   - ORM maps Python classes to tables with sessions and query builders; raw SQL (psycopg/asyncpg) gives full control — ORM for productivity, raw for hot paths.

3. **What is the dependency-injected DB session pattern?**
   - def get_db(): db = SessionLocal(); try: yield db; finally: db.close() — Depends(get_db) gives each request an isolated session.

4. **How do you run migrations?**
   - Alembic generates versioned migration scripts (autogenerate from model diffs), upgraded via alembic upgrade head — the schema-evolution standard.

5. **What is SQLite vs PostgreSQL in local dev?**
   - SQLite: file-based, zero-config, good for tests/prototyping. PostgreSQL: server, concurrency, JSONB, production. Use SQLite for devs, PG for deployment — the ResumeSQLite->PG path.

6. **How do you handle async database access?**
   - asyncpg/SQLAlchemy async or FastAPI's Depends with an async session; synchronous sessions work automatically in threadpool endpoints.

7. **What is a transaction in a FastAPI endpoint?**
   - Session wraps statements in one transaction; commit on success, rollback on exception — ACID compliance via the ORM session pattern.

8. **How do you prevent SQL injection?**
   - SQLAlchemy parameterised queries / bound parameters; never f-string interpolate raw SQL — validator + ORM layers make injection a non-issue.

9. **What is connection pooling?**
   - psycopg2 pool or asyncpg pool reused across requests instead of opening per-request connections — bootleneck-free concurrency under load.

10. **How do you seed/init a database on startup?**
   - lifespan handler runs create_all/seed scripts once at boot — or Alembic handles it in deployment; testing uses fresh in-memory SQLite.
