1. **What is background task processing in FastAPI?**
   - BackgroundTasks (run after response) for emails/reports; heavier jobs go to Celery/RQ with a broker — decide by durability needs.

2. **What are WebSockets in FastAPI?**
   - @app.websocket('/ws') with WebSocket accept/send/receive — real-time bidirectional streaming for chat/live dashboards.

3. **What is rate limiting on FastAPI?**
   - slowapi or a middleware using Redis counters per IP/user — protecting public endpoints from abuse (the DBMS/network security interplay).

4. **How do you paginate results?**
   - Query params limit/offset (or cursor) backed by SQL LIMIT/OFFSET; response_model returns total too — the standard read-API pattern.

5. **What is a caching layer for FastAPI responses?**
   - In-process TTL cache, Redis, or CDN for GET endpoints; invalidate on writes — reducing DB load for hot reads.

6. **What is request validation beyond types?**
   - Pydantic validators, Field(min/max)/regex, and custom validation in model @field_validator — enforcing business rules at the boundary.

7. **How do you version an API?**
   - URL prefixes (/v1/...) or header negotiation; keep old versions live during a deprecation window — graceful evolution.

8. **What is the difference between a dependency and a middleware?**
   - Dependencies are per-endpoint resolution (auth, DB); middleware wraps the whole app (logging, CORS) — distinct but complementary layers.

9. **How do you add OpenAPI customisation?**
   - title/version/description on the app, tags per router, and response examples — documentation quality as a selling point.

10. **What is the repository/CRUD pattern in FastAPI apps?**
   - Routers (HTTP) -> services (business logic) -> repositories (data access) separation — testability and maintainability at scale.
