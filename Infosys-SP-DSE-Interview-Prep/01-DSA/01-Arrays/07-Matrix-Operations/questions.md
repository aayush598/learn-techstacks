# Arrays — Matrix Operations Interview Questions and Answers

## Q1: What are the common matrix traversal patterns?
**A:** Row-major loops, spiral traversal (boundary shrinking), diagonal traversal, and BFS/DFS on 2D grids with directional arrays — the interview matrix toolkit.

## Q2: How do you transpose a matrix?
**A:** For square matrices swap (i,j) with (j,i) for j>i; for rectangles build a new matrix swapping dimensions — O(mn) time with a new allocation.

## Q3: How do you rotate a matrix 90 degrees?
**A:** Transpose, then reverse each row (for clockwise) — O(mn) two passes in place; or rotate layers by four-way swaps — the classic interview rotation.

## Q4: How do you search in a row-and-column-sorted matrix?
**A:** Start at top-right: if target < cell move left, if > move down — O(m+n), the classic staircase search avoiding O(log) overcomplication.

## Q5: How do you flatten a matrix in spiral order?
**A:** Shrink the boundaries (top, bottom, left, right) as you traverse; stop when they cross — printing the four edges each cycle, O(mn).

## Q6: How does BFS work on a grid (shortest path in matrix)?
**A:** A queue of (r,c) with a distance array and four-direction moves — unweighted grid shortest paths in O(mn); the standard islands/caves framework.

## Q7: What is the difference between DFS and BFS on a grid?
**A:** DFS reaches deep first (recursion/stack, useful for island-count and connected components); BFS guarantees shortest steps (distance problems). Pick by target metric.

## Q8: How do you compute the number of islands?
**A:** Scan all cells; on each unvisited '1', BFS/DFS flood-fill it to '0' and increment count — O(mn); the flagship matrix-graph problem.

## Q9: What is matrix multiplication and its naive cost?
**A:** C[i][j] = Σ_k A[i][k]*B[k][j] costs O(mnp) for dims (m,n)×(n,p); Strassen improves to ~O(n^2.807) for large square matrices — the flat answer vs the deep one.

## Q10: What are the common pitfalls in matrix problems?
**A:** Off-by-one in boundary conditions, reading rows vs columns, accidentally revisiting cells (needs a visited set for flood-fills), and treating the grid as a graph without directions.

## Q11: What is the intuition behind the 07 matrix operations technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q12: Write the brute-force approach for a typical 07 matrix operations problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q13: State the time and space complexity of the optimal solution for most 07 matrix operations problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q14: What common edge cases must be handled in 07 matrix operations implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q15: How would you dry-run your 07 matrix operations code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q16: Give a real-world analogy for 07 matrix operations.
**A:** Analogy: 07 matrix operations is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q17: How do you decide between a hash map, sorting, or two pointers as tools for 07 matrix operations?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q18: What is the role of a prefix/suffix precomputation in 07 matrix operations?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q19: Explain the optimisation step you would mention after writing the naive version for 07 matrix operations.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
