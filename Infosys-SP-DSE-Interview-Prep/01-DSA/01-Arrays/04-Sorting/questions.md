1. **State the common array sorting algorithms and complexities.**
   - Bubble/Insertion O(n^2); Merge O(n log n) stable; Quick O(n log n) average (O(n^2) worst with bad pivots); Heap O(n log n) in-place; Counting/Radix O(n+k) for bounded domains.

2. **What is the difference between stable and unstable sorting?**
   - Stable sorting preserves the relative order of equal elements (merge, insertion, bubble); unstable does not (quick, heap). Stability matters for multi-key sorts.

3. **Explain merge sort.**
   - Divide the array in half, sort each side recursively, then merge the two sorted halves with the two-pointer merge — O(n log n) time, O(n) auxiliary space, stable.

4. **Explain quick sort and how to pick a pivot.**
   - Pick a pivot, partition so smaller elements go left and larger right, recurse; average O(n log n). Random/median-of-three pivots avoid the O(n^2) worst case on sorted input.

5. **What is the difference between quicksort and mergesort?**
   - Quick sorts in place (O(1) extra space, average O(n log n), not stable, cache-friendly); merge is stable but needs O(n) auxiliary space. Choose per requirements.

6. **How does counting sort work?**
   - Count element frequencies over the value range, then place elements in order — O(n + k) where k is the range; only works for bounded integers.

7. **What is radix sort?**
   - Sort by each digit place (LSD to MSD) using a stable sub-sort (counting) — O(d × (n+k)) — bypassing the comparison lower bound for integer inputs.

8. **What is the best/worst-case of insertion sort and when is it used?**
   - O(n) best (nearly sorted), O(n^2) worst; ideal for tiny or nearly-sorted inputs and part of hybrid sorts (Timsort uses it for small runs).

9. **Why is O(n log n) the comparison-sort lower bound?**
   - There are n! permutations and each comparison splits the decision tree in two — height must be at least log2(n!) = Ω(n log n). Known as the comparison lower bound.

10. **What is a custom sort key in Python?**
   - sorted(arr, key=lambda x: x[1]) or key=operator.itemgetter, plus reverse=True — Python's Timsort is stable, so multi-key sorts chain correctly.

11. **What is the intuition behind the 04 sorting technique used in coding interviews?**
   - The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

12. **Write the brute-force approach for a typical 04 sorting problem and analyse it.**
   - Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

13. **State the time and space complexity of the optimal solution for most 04 sorting problems.**
   - The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

14. **What common edge cases must be handled in 04 sorting implementations?**
   - Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

15. **How would you dry-run your 04 sorting code on a small example in an interview?**
   - Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

16. **Give a real-world analogy for 04 sorting.**
   - Analogy: 04 sorting is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

17. **How do you decide between a hash map, sorting, or two pointers as tools for 04 sorting?**
   - Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

18. **What is the role of a prefix/suffix precomputation in 04 sorting?**
   - Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

19. **Explain the optimisation step you would mention after writing the naive version for 04 sorting.**
   - First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
