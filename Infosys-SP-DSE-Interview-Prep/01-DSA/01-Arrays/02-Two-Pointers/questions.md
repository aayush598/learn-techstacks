# Arrays — Two Pointers Interview Questions and Answers

## Q1: What is the two-pointer approach on arrays?
**A:** Using two indices — often from opposite ends or differing speeds — to scan an array in O(n) instead of O(n^2) nested loops, exploiting sortedness or monotonicity.

## Q2: How do you solve two-sum on a sorted array with two pointers?
**A:** l=0, r=n-1: sum < target → l++; sum > target → r--; equal → return pair. O(n) time, O(1) space, unlike the hash-map solution on unsorted input.

## Q3: How do you find if a pair with a given sum exists in an unsorted array?
**A:** Use a hash set: for each x, check if target-x is already seen, else add x — O(n) time, O(n) space. State the two-pointer variant only when sorted.

## Q4: How do you reverse an array in place with two pointers?
**A:** Swap arr[l] and arr[r], then l++, r-- until they cross — O(n) time, O(1) space; the same idea reverses subarrays for rotation problems.

## Q5: How do you remove duplicates from a sorted array in place?
**A:** Slow pointer keeps the next unique position; fast scans; write arr[slow++]=arr[fast] whenever a new value appears — O(n), O(1).

## Q6: What is the container-with-most-water two-pointer solution?
**A:** Start l=0, r=n-1; track max area; move the SHORTER line inward (the only move that can increase the bound) — O(n), O(1).

## Q7: When does two pointers fail and you need another approach?
**A:** When there is no monotone ordering — e.g., arbitrary target sums without sortedness — the hash set/map is safer; justify the choice per problem.

## Q8: Give the three-pointer / Dutch flag technique.
**A:** For three-way partition (0s, 1s, 2s) keep low, mid, high: mid swaps and advances according to arr[mid] — one pass to sort the trio.

## Q9: Why is the two-pointer scan O(n) total?
**A:** Each pointer only moves in one direction, visiting each element at most once — the total work is bounded by 2n, making even nested loops feel linear.

## Q10: What is the merge step of merge sort as a two-pointer pattern?
**A:** Two sorted halves merged by comparing their fronts at i and j — the pointer-at-each-sequence technique generalises to k-way merges.

## Q11: What is the intuition behind the 02 two pointers technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q12: Write the brute-force approach for a typical 02 two pointers problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q13: State the time and space complexity of the optimal solution for most 02 two pointers problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q14: What common edge cases must be handled in 02 two pointers implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q15: How would you dry-run your 02 two pointers code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q16: Give a real-world analogy for 02 two pointers.
**A:** Analogy: 02 two pointers is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q17: How do you decide between a hash map, sorting, or two pointers as tools for 02 two pointers?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q18: What is the role of a prefix/suffix precomputation in 02 two pointers?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q19: Explain the optimisation step you would mention after writing the naive version for 02 two pointers.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
