# Arrays — Searching Interview Questions and Answers

## Q1: What is binary search and its precondition?
**A:** Halving a sorted array each step by comparing mid — O(log n) time, O(1) space; requires the array (or a monotone predicate) to be sorted.

## Q2: Write the binary-search loop invariant.
**A:** While lo <= hi, compute mid = lo + (hi-lo)//2; if arr[mid] == target return mid; < → lo=mid+1; > → hi=mid-1; otherwise return -1 — the invariant keeps the answer inside [lo,hi].

## Q3: How do you find the first occurrence of a value?
**A:** On a match, record it and still move hi = mid-1 to keep searching left; the last recorded match is the first occurrence — the boundary variant.

## Q4: What is search in a rotated sorted array?
**A:** Compare arr[mid] with arr[lo] to detect which half is sorted, then decide which side might contain the target — O(log n). One of the trickier search problems.

## Q5: What is binary search on the answer?
**A:** When a monotone predicate 'is answer ≤ x feasible?' exists, binary search the answer VALUE — e.g., minimum largest subarray sum, kth smallest median.

## Q6: What is exponential (galloping) search?
**A:** Probing indices 1,2,4,8,... to bracket the target, then binary search within — O(log i) where i is the target index; used in infinite/unknown-length arrays.

## Q7: What is interpolation search?
**A:** Estimating the next probe by linear interpolation instead of the middle — O(log log n) average on uniformly distributed data but O(n) worst.

## Q8: What are the pitfalls in binary-search implementations?
**A:** Infinite loops when hi=lo, off-by-one on the midpoint convention, overflow of lo+hi in fixed-width languages, and wrong inclusive/exclusive ranges — test 1-2 element cases.

## Q9: What is the complexity of linear search and when use it?
**A:** O(n) time; preferred for unsorted, small, or one-off lookups where sort-and-search costs more; binary search only pays off once sorting amortises.

## Q10: How does ternary search relate to binary search?
**A:** Ternary splits into thirds comparing two mids — O(log_3 n) but more comparisons per step; generally slower in practice than binary for the same problem.

## Q11: What is the intuition behind the 05 searching technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q12: Write the brute-force approach for a typical 05 searching problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q13: State the time and space complexity of the optimal solution for most 05 searching problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q14: What common edge cases must be handled in 05 searching implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q15: How would you dry-run your 05 searching code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q16: Give a real-world analogy for 05 searching.
**A:** Analogy: 05 searching is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q17: How do you decide between a hash map, sorting, or two pointers as tools for 05 searching?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q18: What is the role of a prefix/suffix precomputation in 05 searching?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q19: Explain the optimisation step you would mention after writing the naive version for 05 searching.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
