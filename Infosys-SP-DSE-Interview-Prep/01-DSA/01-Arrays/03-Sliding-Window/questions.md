# 03 Sliding Window — Arrays

**100 Interview Q&A — Infosys Specialist Programmer (SP) / Digital Specialist Engineer (DSE)**

1. **What is the sliding-window technique?**
   - Maintaining a contiguous window of the array with two indices and updating an aggregate incrementally — turning O(n^2) subarray recomputation into O(n).

2. **How do you find the maximum sum subarray of a fixed size k?**
   - Compute the first window's sum, then slide: sum += arr[r] - arr[l]; track the max — O(n) time, O(1) space.

3. **What is the difference between fixed and dynamic windows?**
   - Fixed: constant size k, straightforward slide. Dynamic: the window expands/shrinks while a constraint holds (e.g., longest subarray with sum ≤ target).

4. **Give the general dynamic sliding-window loop.**
   - while r < n: include arr[r]; while (condition violated): exclude arr[l], l++; update answer; r++ — the canonical two-pointer-in-loop skeleton.

5. **How do you count distinct elements in each window of size k?**
   - Keep a frequency counter; on slide decrement the leaving element and remove the key at zero, tracking distinct count — O(n) overall.

6. **Why is the sliding window always linear?**
   - Each element is added once (by r) and removed at most once (by l) — the inner while never makes the total loop exceed O(n) work.

7. **How does sliding window address the 'minimum window substring'?**
   - Expand r until the window contains all needed chars, then shrink l while still containing them, recording the minimum — the flagship application.

8. **How do you handle negative numbers in window-sum problems?**
   - Fixed-size sums still slide cleanly; dynamic 'sum ≤ target' needs care since adding a negative can be beneficial — the naive while-shrink pattern can miss valid windows.

9. **What is the monotonic-deque variant?**
   - For max/min in every window of size k, a deque holding candidate indices (maintained decreasing for max) yields answers in O(n) total.

10. **What edge cases do sliding-window solutions need?**
   - k > n, k = n, all-equal elements, empty array, and windows that never satisfy the constraint — every one changes return semantics.

11. **What is the intuition behind the 03 sliding window technique used in coding interviews?**
   - The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

12. **Write the brute-force approach for a typical 03 sliding window problem and analyse it.**
   - Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

13. **State the time and space complexity of the optimal solution for most 03 sliding window problems.**
   - The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

14. **What common edge cases must be handled in 03 sliding window implementations?**
   - Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

15. **How would you dry-run your 03 sliding window code on a small example in an interview?**
   - Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

16. **Give a real-world analogy for 03 sliding window.**
   - Analogy: 03 sliding window is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

17. **How do you decide between a hash map, sorting, or two pointers as tools for 03 sliding window?**
   - Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

18. **What is the role of a prefix/suffix precomputation in 03 sliding window?**
   - Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

19. **Explain the optimisation step you would mention after writing the naive version for 03 sliding window.**
   - First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
