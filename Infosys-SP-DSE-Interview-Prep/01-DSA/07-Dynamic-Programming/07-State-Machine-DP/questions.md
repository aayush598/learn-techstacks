# Dynamic Programming — State Machine Dp Interview Questions and Answers

## Q1: What is state-machine DP?
**A:** DP where the state encodes a phase/status (e.g., holding stock, cooldown, k transactions used), with transitions between statuses — tracking more than a scalar DP value.

## Q2: How do you solve 'best time to buy-sell with cooldown'?
**A:** States: rest, holding, sold — transitions between them after each price; the DP arrays (or four vars) encode the max profit by state. O(n).

## Q3: How do you solve 'best time to buy-sell with transaction fee'?
**A:** States hold/cash: cash[i]=max(cash[i-1], hold[i-1]+price[i]-fee); hold[i]=max(hold[i-1], cash[i-1]-price[i]). O(n).

## Q4: How do you solve 'best time with at most k transactions'?
**A:** dp[t][d]=max(dp[t][d-1], prices[d]+sellOffset) where sellOffset=best dp[t-1][j]-prices[j]; two-dimensional states. O(k·n).

## Q5: How do you formulate 'house robber' as state DP?
**A:** states of rob or skip: rob=prevSkip+nums[i]; skip=max(prev). Two rolling vars; the status is the binary take/skip. O(n) O(1).

## Q6: What is the 'two statuses of the same variable' pattern?
**A:** Any problem tracking both a value and whether the current element was chosen (include/exclude) — the generic 0/1 skip-or-take has a state-machine reading.

## Q7: How do you solve 'decode ways with zero rules' via status DP?
**A:** dp[i] carries whether a valid single/double take happened; the status distinguishes the two digit cases. O(n).

## Q8: How do you solve 'maximum alternating subsequence sum'?
**A:** States even/odd index with sign multiplier; dpOdd= max(dpOdd, dpEven-num), etc. — pure sign-state machine. O(n).

## Q9: How do you solve 'ugly number / counting with states'?
**A:** Usually arithmetic; the DP status is the smallest multiplier index per prime; simpler than a state machine but shows how status improves greedy.

## Q10: How do you combine state-machine DP with constraints?
**A:** Add constraint variables to the state (transactions used, stocks held). State explosion == dimension increase — communicate the trade-off to the interviewer.

## Q11: What is the intuition behind the 07 state machine dp technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q12: Write the brute-force approach for a typical 07 state machine dp problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q13: State the time and space complexity of the optimal solution for most 07 state machine dp problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q14: What common edge cases must be handled in 07 state machine dp implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q15: How would you dry-run your 07 state machine dp code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q16: Give a real-world analogy for 07 state machine dp.
**A:** Analogy: 07 state machine dp is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q17: How do you decide between a hash map, sorting, or two pointers as tools for 07 state machine dp?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q18: What is the role of a prefix/suffix precomputation in 07 state machine dp?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q19: Explain the optimisation step you would mention after writing the naive version for 07 state machine dp.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.

**A:** In the assessment only correctness/speed of the final code matters and hidden tests matter; in the live round the interviewer wants your thought process, complexity analysis, edge cases, and a hand trace — both must be practiced.

**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.
