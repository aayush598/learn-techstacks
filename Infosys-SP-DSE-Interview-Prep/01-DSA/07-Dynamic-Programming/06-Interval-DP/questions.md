1. **What is interval DP and its canonical state?**
   - dp[i][j] describes an optimal result over the contiguous segment [i,j]; transitions split segments (dp over k between i and j) or extend edges; fill by increasing length. O(n^3) typical.

2. **How do you solve 'burst balloons'?**
   - dp[i][j]=max over k of dp[i][k-1]+dp[k+1][j]+nums[k]*nums[i-1]*nums[j+1] with padded coins; fill by length ascending. O(n^3).

3. **How do you compute 'matrix chain multiplication' min operations?**
   - dp[i][j]=min over k (dp[i][k]+dp[k+1][j]+dims[i-1]*dims[k]*dims[j]); O(n^3). Canonical interval DP.

4. **How do you solve 'scramble string' or 'interleaving cut problems'?**
   - Interval over substrings: split at k and test both orientations — dp/I is the subarray pair feasibility. O(n^4) worst with straightforward formulation.

5. **How do you solve 'palindromic cuts (palindrome partitioning II)'?**
   - dpcuts[i]=min over palindromic j..i of dpcuts[j-1]+1; with the precomputed isPal table. O(n^2).

6. **How do you solve the 'minimum score triangulation' ?**
   - dp[i][j]=min over k of dp[i][k]+dp[k][j]+values[i]*values[k]*values[j] — triangle DP over polygon vertices. O(n^3).

7. **How does the length-ascending fill order avoid using unfilled states?**
   - Each larger interval depends only on strictly smaller intervals; filling by length guarantees sub-intervals are already computed — the key implementation detail.

8. **How do you solve 'egg drop' via interval/int-based DP?**
   - dp[k][m] moves using k eggs and m moves -> max floors tested; or dp over floors with binary-search k. The formula-based DP drastically reduces states.

9. **How do you reconstruct an optimal tree from matrix-chain DP?**
   - Record split k during DP; backtrack to print parenthesisation. Same store-the-decision trick used across interval DPs.

10. **How do you identify an interval-DP problem in an interview?**
   - When the answer involves breaking subarrays/substrings into parts and combining, or the recurrence uses a split index — think interval DP.

11. **What is the intuition behind the 06 interval dp technique used in coding interviews?**
   - The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

12. **Write the brute-force approach for a typical 06 interval dp problem and analyse it.**
   - Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

13. **State the time and space complexity of the optimal solution for most 06 interval dp problems.**
   - The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

14. **What common edge cases must be handled in 06 interval dp implementations?**
   - Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

15. **How would you dry-run your 06 interval dp code on a small example in an interview?**
   - Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

16. **Give a real-world analogy for 06 interval dp.**
   - Analogy: 06 interval dp is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

17. **How do you decide between a hash map, sorting, or two pointers as tools for 06 interval dp?**
   - Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

18. **What is the role of a prefix/suffix precomputation in 06 interval dp?**
   - Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

19. **Explain the optimisation step you would mention after writing the naive version for 06 interval dp.**
   - First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
