# Trees — Binary Tree Basics Interview Questions and Answers

## Q1: Define a binary tree.
**A:** A hierarchical data structure where each node has at most two children, conventionally labelled left and right. It has a root, and every non-root node has exactly one parent.

## Q2: What are the properties of a binary tree (levels, height)?
**A:** Level of root = 0; height = max edges from root to leaf; a tree with n nodes has at most n-1 edges, and height can range from ~log2(n) (balanced) to n-1 (skewed).

## Q3: Name the basic types of binary trees.
**A:** Full (each node 0 or 2 children), complete (all levels full except possibly last, filled left-to-right), perfect (all levels full), balanced (height O(log n)), and skewed.

## Q4: How do you count the number of nodes in a tree?
**A:** Recurrence: size(node)=size(left)+size(right)+1, base node is None returns 0. O(n).

## Q5: How do you compute the height of a tree?
**A:** height(node)=1+max(height(left),height(right)), None returns -1 (edges) or 0 (nodes) depending on convention. O(n).

## Q6: What is the time complexity of traversals and why?
**A:** Preorder/inorder/postorder/level-order each visit every node once: O(n) time; recursion stack or explicit queue adds O(h)/O(w) space.

## Q7: How do you identify leaves and internal nodes?
**A:** Leaf: left and right both None; internal: has at least one child. Check node.left is None and node.right is None.

## Q8: What is a 'skewed tree' and its traversal cost?
**A:** Each node has one child; height = n-1; recursion depth hits n which can overflow the stack for large trees — an interviewer favourite edge case.

## Q9: Explain the recursive base-case discipline for tree functions.
**A:** Always handle None first (the base case), then combine results of left/right subproblems. Every tree DFS follows this shape; forgetting the None check causes crashes.

## Q10: How do you check if a tree is balanced (height-balanced)?
**A:** Post-order: compute heights while verifying |hl-hr|≤1 at every node; propagate -1 on violation. O(n) time.

## Q11: What is the diameter of a binary tree and how to compute it?
**A:** Longest path between any two nodes (may pass through root). Post-order: track max(1+hl+hr) while returning height; O(n).

## Q12: How do you find the deepest/max-depth node?
**A:** Recurrence max_depth = 1 + max(depth(left), depth(right)) — same as height. For the Node value, carry it alongside.

## Q13: What is the intuition behind the 01 binary tree basics technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q14: Write the brute-force approach for a typical 01 binary tree basics problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q15: State the time and space complexity of the optimal solution for most 01 binary tree basics problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q16: What common edge cases must be handled in 01 binary tree basics implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q17: How would you dry-run your 01 binary tree basics code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q18: Give a real-world analogy for 01 binary tree basics.
**A:** Analogy: 01 binary tree basics is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q19: How do you decide between a hash map, sorting, or two pointers as tools for 01 binary tree basics?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q20: What is the role of a prefix/suffix precomputation in 01 binary tree basics?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q21: Explain the optimisation step you would mention after writing the naive version for 01 binary tree basics.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
