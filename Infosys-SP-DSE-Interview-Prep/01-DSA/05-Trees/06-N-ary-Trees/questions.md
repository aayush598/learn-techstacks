# Trees — N Ary Trees Interview Questions and Answers

## Q1: Define an N-ary tree and its typical node structure.
**A:** A general tree where each node can have up to N children (in practice any number); node stores a list of children. Traversals generalise from binary counterparts.

## Q2: How do DFS traversals change for N-ary trees?
**A:** Preorder visits node then each child recursively; postorder visits children then node; there is NO natural inorder for N-ary trees (ambiguity of 'middle').

## Q3: How do you implement level-order on an N-ary tree?
**A:** Same queue approach as binary: dequeue node, enqueue its children list. Children processed left-to-right. O(n).

## Q4: What is the maximum depth of an N-ary tree?
**A:** depth(node)=1+max(depth(child)) over all children; None→0. Run on each child list; recursion or iterative stack. O(n).

## Q5: How do you serialise an N-ary tree?
**A:** Preorder with a child-count marker per node (e.g., value, child_count, then children) enables unambiguous rebuild. O(n).

## Q6: How do you find the diameter of an N-ary tree?
**A:** Post-order track the two largest child heights; diameter = max(1 + top1 + top2); return top height upward. O(n).

## Q7: What is a 'nested integer list' problem and why is it tree-like?
**A:** The nested structure is an N-ary tree; weighted sum problems recursively flatten with depth. recursion + depth multiplier is the pattern. O(total integers).

## Q8: How do you clone an N-ary tree?
**A:** Recursive: create new node, recurse cloning each child. O(n). Classic on LeetCode-style 'clone graph too'.

## Q9: How do you represent a 'general tree as binary tree' (left-child right-sibling)?
**A:** Left pointer = first child, right pointer = next sibling. This canonical representation lets binary-tree algorithms work on general trees.

## Q10: How do you check subtree isomorphism for unrooted N-ary trees?
**A:** AHU algorithm: recursively compute sorted tuple-of-child-codes; two trees are isomorphic iff root codes equal. Polynomial time.

## Q11: What is the intuition behind the 06 n ary trees technique used in coding interviews?
**A:** The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

## Q12: Write the brute-force approach for a typical 06 n ary trees problem and analyse it.
**A:** Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

## Q13: State the time and space complexity of the optimal solution for most 06 n ary trees problems.
**A:** The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

## Q14: What common edge cases must be handled in 06 n ary trees implementations?
**A:** Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

## Q15: How would you dry-run your 06 n ary trees code on a small example in an interview?
**A:** Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

## Q16: Give a real-world analogy for 06 n ary trees.
**A:** Analogy: 06 n ary trees is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

## Q17: How do you decide between a hash map, sorting, or two pointers as tools for 06 n ary trees?
**A:** Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

## Q18: What is the role of a prefix/suffix precomputation in 06 n ary trees?
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q19: Explain the optimisation step you would mention after writing the naive version for 06 n ary trees.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.

## Q98: What is the role of a prefix/suffix precomputation in 06 n ary trees? Extend your answer with a second example.
**A:** Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

## Q99: Explain the optimisation step you would mention after writing the naive version for 06 n ary trees. Extend your answer with a second example.
**A:** First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
