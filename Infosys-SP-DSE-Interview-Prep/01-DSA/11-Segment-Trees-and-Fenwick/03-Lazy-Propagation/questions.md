# 03 Lazy Propagation — Segment / Trees / And / Fenwick

**100 Interview Q&A — Infosys Specialist Programmer (SP) / Digital Specialist Engineer (DSE)**

1. **What does lazy propagation solve?**
   - Range additions/assignments on a segment tree in O(log n) instead of touching all leaves — defer the update record to children until needed.

2. **Explain the lazy-tag mechanics with range-add.**
   - Node stores sum and lazy add value. If a range fully covers the node, apply sum += tag*len and record lazy += tag for children; when a partial query/update descends, push the tag first to children.

3. **What is the 'push' function?**
   - push(node,l,r): if lazy[node]!=0 then propagate to children (update child sums and child lazy), clear current lazy. Called before descending for partial updates/queries.

4. **What are the pitfalls of combining multiple lazy ops (multiplier + add)?**
   - Apply composite transforms in the correct order — (add then mul) vs (mul then add) differs; store both and update in the right sequence. Test with simple cases.

5. **How does lazy range assignment (not add) work?**
   - Overwrite semantics: on full-cover, set sum=tag*len and mark an assign-flag; push clears descendant assignment; combine must respect assignments over inherited tags.

6. **Why do you push before reading children?**
   - The parent's pending update must reach descending children first, or the query sees stale child values. Order: push → descend → recompute on unwind.

7. **What is the memory footprint of a lazy tree?**
   - Two arrays (tree + lazy) of size 4n each; lazy could be int64 for modulo-heavy updates — roughly 2*4*n*8 bytes at 64-bit.

8. **How do you apply lazy on segments with negative adds?**
   - The same arithmetic works: sum can decrease; record lazy add (can be negative); combining rules unchanged.

9. **When is lazy NOT needed?**
   - Point-only updates or pure static queries — lazy is only for range updates; Fenwick trees also support range-add via two BITs without lazy tags.

10. **How do you test a lazy tree quickly?**
   - Brute force against naive per-element updates on random small arrays — property-based verification catches tag-order bugs.

11. **What is the intuition behind the 03 lazy propagation technique used in coding interviews?**
   - The core idea is to avoid brute force by exploiting structure: leftover wasted compares are removed, and each element is processed a small constant number of times, driving complexity down to an optimal bound that interviewers expect you to justify.

12. **Write the brute-force approach for a typical 03 lazy propagation problem and analyse it.**
   - Brute force enumerates every candidate configuration, e.g., every subarray/combination/permutation, giving O(n^2), O(n^3) or O(2^n). It is correct but only useful for small inputs; the interview follow-up is to optimise it to linear or O(n log n).

13. **State the time and space complexity of the optimal solution for most 03 lazy propagation problems.**
   - The optimal solution is usually O(n) time with O(n) space, or O(n) time with O(1) space when a monotonic/pointer trick applies. Always state constants and best/worst cases explicitly.

14. **What common edge cases must be handled in 03 lazy propagation implementations?**
   - Empty input, single-element input, all-equal values, negative numbers, duplicates, off-by-one at the last index, and large values where intermediate sums/products can overflow — every one must be tested.

15. **How would you dry-run your 03 lazy propagation code on a small example in an interview?**
   - Pick a tiny input, walk index by index while updating each variable, and show the invariants hold at every step. This proves both correctness and that you truly understand the algorithm, which Infosys interviewers probe by asking you to trace code by hand.

16. **Give a real-world analogy for 03 lazy propagation.**
   - Analogy: 03 lazy propagation is like scanning a line of people for a specific property while remembering a few key facts — each person is visited once and relevant state is carried forward, exactly how the optimal solution behaves.

17. **How do you decide between a hash map, sorting, or two pointers as tools for 03 lazy propagation?**
   - Hash map when you need membership/paired lookup in O(1) and space is affordable; sorting when order gives a monotonic advantage (two pointers, binary search); pointers directly when the input is already sorted. Trade space for speed only when constraints allow.

18. **What is the role of a prefix/suffix precomputation in 03 lazy propagation?**
   - Precomputation turns repeated subcomputations into O(1) lookups, converting an O(n^2) nested loop into O(n). Common wherever the value at index i depends on an aggregate over a range around i.

19. **Explain the optimisation step you would mention after writing the naive version for 03 lazy propagation.**
   - First remove redundant recomputation via memoisation or prefix arrays; next, exploit monotonicity with two pointers/sliding window; finally, reduce space by keeping running variables instead of full tables — always closing with the improved complexity.
