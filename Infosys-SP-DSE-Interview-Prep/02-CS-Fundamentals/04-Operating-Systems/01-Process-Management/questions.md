1. **What is a process?**
   - A program in execution: code, data, heap, stack, registers, and state. Each process gets its own isolated address space; the OS schedules it, allocates resources, and switches between them.

2. **What is the difference between a process and a thread?**
   - Process: independent memory space, heavier to create/switch, isolated. Thread: lightweight unit within a process, shares the process's memory, cheaper context switch, prone to races.

3. **What are the process states?**
   - new → ready → running ↔ waiting/blocked → terminated (plus suspended/stopped variants). The diagram question — state transitions and what causes them.

4. **What is a process control block (PCB)?**
   - The kernel's record per process: PID, state, program counter, registers, memory info, open files, scheduler priority — everything needed to suspend and resume a process.

5. **What is context switching?**
   - Saving one process's state (into its PCB) and loading another's — the overhead of multitasking; frequent switches hurt throughput and cache locality.

6. **What is the difference between preemptive and non-preemptive scheduling?**
   - Preemptive: the scheduler can interrupt a running process (time quantum). Non-preemptive: the process runs until it blocks or finishes. Real-time systems care deeply.

7. **What is a zombie process?**
   - A child that has exited but whose parent hasn't yet called wait() — its PCB lingers to let the parent read the exit status. Parent must reap or the OS eventually orphans/reaps.

8. **What is an orphan process?**
   - A running process whose parent has exited first; it gets reparented to init (PID 1) in Unix, which reaps it when it finishes.

9. **What is fork()?**
   - The Unix system call that clones the current process (COW memory); children get a copy of memory, PID differs, and fork() returns 0 to the child and the child's PID to the parent.

10. **What are the components of a process address space in memory?**
   - Text (code), data (initialised/static), heap (grows upward via malloc), stack (grows downward for calls). Layout questions define memory-management depth.
