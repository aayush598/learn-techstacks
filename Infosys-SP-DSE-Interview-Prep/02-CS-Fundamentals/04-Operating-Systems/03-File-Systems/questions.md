1. **What is a file system?**
   - The OS layer organising and storing data on devices: inodes/directories in Unix, NTFS' MFT in Windows — providing namespaces, permissions, persistence.

2. **Explain the Unix inode concept.**
   - An inode stores metadata (size, mode, owner, timestamps) and block pointers to the file's data; file names live in directories pointing to inodes. Hard links share an inode.

3. **What is a hard link vs symbolic (soft) link?**
   - Hard link: another directory entry for the same inode (same file); can't cross filesystems/directories, increments link count. Symlink: a separate inode holding a path string — can point anywhere, may dangle.

4. **What is a file descriptor?**
   - An integer the process uses to reference an open file/stream; the kernel keeps an open-file table (mode, offset, buffers). Standard: 0 stdin, 1 stdout, 2 stderr.

5. **What is sequential vs random file access?**
   - Sequential reads the stream order (buffered efficiently); random jumps offsets (seek). Database workloads are heavily random → page-cache and index design matter.

6. **How does the OS cache file reads?**
   - Page cache keeps recently-read disk blocks in RAM, with dirty pages written back lazily — read/write performance improve dramatically; fsync forces durable flush.

7. **What is journaling in file systems?**
   - Logging metadata changes before committing them so a crash replays the journal and recovers consistency — ext4/APFS use it; trade-off: some write overhead.

8. **What are file permissions in Linux?**
   - r/w/x bits for owner/group/others (e.g., 755); applied via chmod/chown — the 'RWX 754' question every Linux-themed interview asks.

9. **How do you list files with sizes in Linux?**
   - ls -lah, du -sh *, df -h; find -size for criteria — practical admin commands used in DevOps interviews.

10. **What is the difference between a file system and a database?**
   - FS: unstructured bytes/files with path lookup. DB: structured, indexed, transactional, queryable data. Applications pick per need (blobs in FS, records in DB).
