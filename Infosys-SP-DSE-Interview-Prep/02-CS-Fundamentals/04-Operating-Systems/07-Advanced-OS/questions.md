# Operating Systems — Advanced Os Interview Questions and Answers

## Q1: What is the difference between a real-time and general OS?
**A:** RTOS guarantees deadlines/preemptive priority schedules; general-purpose aims for throughput/fairness. Hard vs soft real-time distinctions matter for embedded systems.

## Q2: What is virtual memory working set?
**A:** The set of pages a process actively references; if the working set fits RAM, paging stays low — Denning's theory underlies thrashing explanations.

## Q3: What is copy-on-write?
**A:** Fork/mmap pages are shared until written, then duplicated — huge fork() speedups and the mechanism behind COW in fork(), mmap, and virtualization.

## Q4: What is memory-mapped I/O / mmap?
**A:** Mapping files into the address space so reads/writes are plain memory access — zero-copy performance for large files (like SQLite mmap or data loaders).

## Q5: What is a kernel module vs a driver?
**A:** Modules are loadable kernel components; drivers are modules controlling hardware. Linux loads .ko modules into the running kernel — a systems-admin depth question.

## Q6: What is an interrupt vs a poll?
**A:** Interrupt: hardware signals the CPU asynchronously (efficient). Polling: CPU repeatedly checks status (busy). Interrupts dominate event-driven I/O.

## Q7: What is the difference between concurrency and parallelism?
**A:** Concurrency = multiple tasks making progress (interleaved, one CPU). Parallelism = simultaneous execution (multiple cores/CPUs). Python threads = concurrency (GIL); multiprocessing = parallelism.

## Q8: What is NUMA and why does it matter?
**A:** Non-uniform memory access: some memory is closer to a CPU than others; schedulers and allocators pin for locality — high-performance databases tune for this.

## Q9: What is a system call and how does it differ from a library call?
**A:** A syscall jumps into kernel mode (privileged) via a handler; a library call is user-space. Read/write/fork are syscalls; printf wraps a write syscall.

## Q10: What is the difference between kernel space and user space?
**A:** Kernel: privileged code (everything critical/trusted). User space: application code — isolated; transitions happen via syscalls. Security boundaries rely on this split.
