1. **What is the difference between a real-time and general OS?**
   - RTOS guarantees deadlines/preemptive priority schedules; general-purpose aims for throughput/fairness. Hard vs soft real-time distinctions matter for embedded systems.

2. **What is virtual memory working set?**
   - The set of pages a process actively references; if the working set fits RAM, paging stays low — Denning's theory underlies thrashing explanations.

3. **What is copy-on-write?**
   - Fork/mmap pages are shared until written, then duplicated — huge fork() speedups and the mechanism behind COW in fork(), mmap, and virtualization.

4. **What is memory-mapped I/O / mmap?**
   - Mapping files into the address space so reads/writes are plain memory access — zero-copy performance for large files (like SQLite mmap or data loaders).

5. **What is a kernel module vs a driver?**
   - Modules are loadable kernel components; drivers are modules controlling hardware. Linux loads .ko modules into the running kernel — a systems-admin depth question.

6. **What is an interrupt vs a poll?**
   - Interrupt: hardware signals the CPU asynchronously (efficient). Polling: CPU repeatedly checks status (busy). Interrupts dominate event-driven I/O.

7. **What is the difference between concurrency and parallelism?**
   - Concurrency = multiple tasks making progress (interleaved, one CPU). Parallelism = simultaneous execution (multiple cores/CPUs). Python threads = concurrency (GIL); multiprocessing = parallelism.

8. **What is NUMA and why does it matter?**
   - Non-uniform memory access: some memory is closer to a CPU than others; schedulers and allocators pin for locality — high-performance databases tune for this.

9. **What is a system call and how does it differ from a library call?**
   - A syscall jumps into kernel mode (privileged) via a handler; a library call is user-space. Read/write/fork are syscalls; printf wraps a write syscall.

10. **What is the difference between kernel space and user space?**
   - Kernel: privileged code (everything critical/trusted). User space: application code — isolated; transitions happen via syscalls. Security boundaries rely on this split.
