# Operating Systems — Memory Management Interview Questions and Answers

## Q1: What is virtual memory?
**A:** Faking a large logical address space backed by physical RAM + disk: each process sees a contiguous address space; pages map via the page table; the OS swaps pages in/out.

## Q2: What is paging?
**A:** Dividing memory and the address space into fixed-size frames/pages; the page table maps virtual pages to physical frames — enabling demand paging and protection.

## Q3: What is a page fault?
**A:** A referenced page is not in RAM → trap to the kernel, which loads it from disk and updates the page table. Frequent faults (thrashing) destroy performance.

## Q4: What is a TLB (translation lookaside buffer)?
**A:** A small cache of recent virtual→physical page mappings that avoids walking the page table on every access — the CPU's speed-up for address translation.

## Q5: What is segmentation?
**A:** Dividing an address space into variable-size logical segments (code, data, stack) with a segment table carrying base and limit — simpler than paging but causes external fragmentation.

## Q6: What is the difference between internal and external fragmentation?
**A:** Internal: wasted space inside allocated fixed-size blocks (paging). External: free chunks too small to satisfy requests scattered between allocations (segmentation).

## Q7: What is a memory allocation strategy (first-fit, best-fit, worst-fit)?
**A:** First-fit: first block big enough. Best-fit: smallest sufficient (minimises waste, slower). Worst-fit: largest block (leaves bigger gaps). Covered in classic OS interviews.

## Q8: What is thrashing?
**A:** The working set exceeds RAM so the system spends more time paging than executing; the CPU utilisation collapses — fix by increasing RAM/reducing processes or improving locality.

## Q9: What is demand paging?
**A:** Loading pages only when referenced, not upfront — processes start instantly and pay lazily; page faults on first touch.

## Q10: How does memory in Python relate to the OS concept?
**A:** Python allocates small objects from arenas (pymalloc) and maps large ones via malloc/OS pages; memory safety is tied to the runtime, not the OS directly.
