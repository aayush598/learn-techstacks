# Dbms — Database Design Interview Questions and Answers

## Q1: Walk me through designing a database for a blog platform.
**A:** Tables: users, posts (user_id FK), comments (post_id FK, user_id FK), tags + post_tags (many-to-many), likes. Normalise to 3NF, index on post_id/created_at, and keep counters denormalised only if profiling demands.

## Q2: How do you model a many-to-many relationship?
**A:** A junction table holding two FKs (e.g., student_course(student_id, course_id) with composite PK) — the standard relational solution.

## Q3: How do you design an e-commerce schema?
**A:** Customers, products, orders (header), order_items (line details, product FK, order FK), payments, addresses. Order totals can be derived; keep immutable line items intact.

## Q4: What is a soft delete and when do you use it?
**A:** Marking rows deleted (is_deleted flag/deleted_at) instead of removing them — preserves audit/history; query filters must exclude them; can slow scans if not partitioned.

## Q5: What is a UUID vs auto-increment PK?
**A:** Auto-increment: compact, ordered, but exposes counts and has global collisions across distributed shards. UUID: global uniqueness, unguessable, but larger and scattered (use UUIDv7 for time-ordering).

## Q6: What is schema migration and why it matters?
**A:** Version-controlled changes to schema applied in order (Alembic for SQLAlchemy). Without them, deploy-time divergence and data loss are guaranteed.

## Q7: How do you decide SQL vs NoSQL for a feature?
**A:** SQL: strong consistency, ACID, relational queries. NoSQL: scale-out, flexible schema, high write throughput. Polyglot persistence — pick per workload, not globally.

## Q8: What is database sharding?
**A:** Splitting data across multiple DB instances by key (user_id hash/range) to scale writes; complicates joins and transactions — done at scale after vertical scaling saturates.

## Q9: What is a time-series design option?
**A:** Store event rows with (event_time, metric) and partition by time; PostgreSQL range partitioning or dedicated TSDBs (TimescaleDB/InfluxDB) — index and archive hot/warm tiers.

## Q10: What is the CAP theorem and its DB choice implications?
**A:** Consistency, Availability, Partition tolerance — pick two under network partition. Relational DBs lean CP; AP systems like Cassandra choose availability; the partition is unavoidable in distributed systems.

## Q13: What are the advantages and disadvantages of 07 database design?
**A:** Advantages: predictability of behaviour, standardised semantics, widely understood patterns. Disadvantages: each design brings overhead or constraints, so it must be balanced against simplicity and project context whenever an alternative exists.

## Q14: Compare 07 database design with alternatives and state when to prefer which.
**A:** Compare by criteria: speed, memory, complexity, latency, consistency. There is no universal best — the winner depends on the workload (read-heavy vs write-heavy, scale, consistency requirements); state the decision matrix explicitly.
