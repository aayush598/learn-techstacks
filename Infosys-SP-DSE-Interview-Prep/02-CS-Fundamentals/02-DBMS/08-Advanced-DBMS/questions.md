# Dbms — Advanced Dbms Interview Questions and Answers

## Q1: What is a materialized view?
**A:** A view whose result set is physically stored and refreshed (manually/scheduled) — precomputed aggregates for fast reads at the cost of staleness.

## Q2: What is query optimisation and what does a query planner do?
**A:** Planner estimates costs of plans (index/full scan, join order, hash vs nested loop) and picks an execution plan; stats quality and indexes steer it. EXPLAIN shows the chosen plan.

## Q3: What are join algorithms?
**A:** Nested loop (small/inner), hash join (equi-join on moderate tables), merge join (sorted inputs) — the DB picks based on stats; knowing them helps you write joinable queries.

## Q4: What is partition pruning?
**A:** The planner skipping partitions that can't contain matching rows (via WHERE on the partition key) — crucial for huge time-series tables.

## Q5: What is a JSONB column and when would you use it?
**A:** PostgreSQL's binary JSON — flexible nested data with GIN indexing; use for naturally flexible/occasionally-queried shapes instead of over-splitting schema.

## Q6: What is a database paradigm 'ACID vs BASE'?
**A:** ACID = strict consistency; BASE (Basically Available, Soft state, Eventually consistent) = NoSQL's relaxed model for scale — the trade-off spectrum in distributed stores.

## Q7: What is replication and its types?
**A:** Copying data to replica DBs: synchronous (strong) vs asynchronous (eventual lag), streaming replication for read scaling and failover.

## Q8: What is a deadlock's resolution strategy?
**A:** Consistent lock ordering, timeouts (lock_timeout / innodb_lock_wait_timeout), and DB-level deadlock detection aborting one victim with retry.

## Q9: What is a database connection vs a connection pool size tuning?
**A:** Opening a connection is expensive (auth, memory); a pool resizes per workload. Oversized pools waste memory; undersized pools throttle — monitor active/inactive.

## Q10: How do you handle time zones in a DB?
**A:** Store TIMESTAMPTZ (UTC), convert on display; never store local time in a TIMESTAMP column — the classic silent-bug.
