# Dbms — Acid Properties Interview Questions and Answers

## Q1: What does ACID stand for?
**A:** Atomicity, Consistency, Isolation, Durability — the transaction guarantees that keep relational databases reliable.

## Q2: What is atomicity?
**A:** A transaction executes all-or-nothing: every operation commits or every one rolls back on failure — no partial effects survive. A bank transfer that debits must credit.

## Q3: What is consistency?
**A:** A transaction moves the database from one valid state to another, preserving all constraints (PK, FK, CHECK) — invalid intermediate states never become permanent.

## Q4: What is isolation?
**A:** Concurrent transactions execute as if run serially — one transaction's incomplete changes are invisible to others; levels (READ COMMITTED, REPEATABLE READ, SERIALIZABLE) trade strength for speed.

## Q5: What is durability?
**A:** Once committed, changes survive crashes/power loss — achieved by writing to disk/WAL records before acknowledging the commit.

## Q6: Give the classic bank transfer explanation.
**A:** Transfer ₹500 A→B: debit A, credit B. Atomic: both or none. Consistency: balances stay ≥ 0 per constraint. Isolation: another read never sees a half-transfer. Durability: after COMMIT the change survives a crash.

## Q7: What is COMMIT vs ROLLBACK?
**A:** COMMIT makes a transaction's changes permanent durably; ROLLBACK undoes all its changes back to the last commit, restoring the before-image — the atomicity mechanism.

## Q8: What is a WAL (write-ahead log)?
**A:** A log written before the actual data changes; on crash recovery the DB replays the WAL — the standard durability mechanism behind PostgreSQL.

## Q9: What are the isolation levels?
**A:** READ UNCOMMITTED (dirty reads), READ COMMITTED (no dirty reads), REPEATABLE READ (no non-repeatable reads), SERIALIZABLE (full serial order) — each loosens concurrency for speed.

## Q10: What is a dirty read, non-repeatable read, phantom read?
**A:** Dirty: reading another txn's uncommitted change. Non-repeatable: same row re-reads differently within a txn. Phantom: a query's result set gains/loses rows within a txn due to another commit.
