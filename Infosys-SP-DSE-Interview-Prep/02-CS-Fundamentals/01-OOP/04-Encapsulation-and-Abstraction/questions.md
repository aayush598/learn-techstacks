1. **What is encapsulation?**
   - Binding data and the functions that manipulate it inside one unit (class) while restricting outside access to internals, exposing safe interfaces instead — e.g., a capsule hiding medicine.

2. **How does Python implement encapsulation?**
   - Naming conventions: _private (convention) and __private (name mangled as _ClassName__private). True enforcement is by convention; Python trusts the developer.

3. **What is abstraction?**
   - Hiding implementation complexity and exposing only essential features — e.g., a car accelerator abstracts the engine: you press the pedal, not the fuel injectors.

4. **What is the difference between encapsulation and abstraction?**
   - Encapsulation bundles and controls access to internals (a mechanism); abstraction hides complexity at the design level (a concept). Encapsulation is used to implement abstraction.

5. **Why hide data (benefits of encapsulation)?**
   - Protects invariants, prevents accidental corruption, allows changing the implementation without breaking callers, and centralises validation in setters.

6. **What are getters/setters and when do you use them?**
   - Methods that expose or mutate attributes with checks. In Python, @property plus @x.setter gives controlled attribute access while keeping clean syntax.

7. **What is information hiding?**
   - The design principle that details not needed by callers stay hidden, minimising coupling — critical in module/API design and a close cousin of abstraction.

8. **Give an example where you used abstraction in your projects.**
   - In the RAG pipeline I wrapped embedding/vector-store/LLM behind a RetrievalService interface so downstream code didn't need to know which provider was in use — classic abstraction.

9. **What are the risks of over-encapsulation?**
   - Too many layers and getters/setters bloat code and hurt performance/readability; balance by exposing only what changes.

10. **What is the principle of least privilege in OOP terms?**
   - Expose the minimum interface needed — correlates with private members and well-scoped public APIs, reducing the attack surface and coupling.
