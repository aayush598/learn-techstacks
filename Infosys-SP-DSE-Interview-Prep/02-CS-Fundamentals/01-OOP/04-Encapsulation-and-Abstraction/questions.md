# Oop — Encapsulation And Abstraction Interview Questions and Answers

## Q1: What is encapsulation?
**A:** Binding data and the functions that manipulate it inside one unit (class) while restricting outside access to internals, exposing safe interfaces instead — e.g., a capsule hiding medicine.

## Q2: How does Python implement encapsulation?
**A:** Naming conventions: _private (convention) and __private (name mangled as _ClassName__private). True enforcement is by convention; Python trusts the developer.

## Q3: What is abstraction?
**A:** Hiding implementation complexity and exposing only essential features — e.g., a car accelerator abstracts the engine: you press the pedal, not the fuel injectors.

## Q4: What is the difference between encapsulation and abstraction?
**A:** Encapsulation bundles and controls access to internals (a mechanism); abstraction hides complexity at the design level (a concept). Encapsulation is used to implement abstraction.

## Q5: Why hide data (benefits of encapsulation)?
**A:** Protects invariants, prevents accidental corruption, allows changing the implementation without breaking callers, and centralises validation in setters.

## Q6: What are getters/setters and when do you use them?
**A:** Methods that expose or mutate attributes with checks. In Python, @property plus @x.setter gives controlled attribute access while keeping clean syntax.

## Q7: What is information hiding?
**A:** The design principle that details not needed by callers stay hidden, minimising coupling — critical in module/API design and a close cousin of abstraction.

## Q8: Give an example where you used abstraction in your projects.
**A:** In the RAG pipeline I wrapped embedding/vector-store/LLM behind a RetrievalService interface so downstream code didn't need to know which provider was in use — classic abstraction.

## Q9: What are the risks of over-encapsulation?
**A:** Too many layers and getters/setters bloat code and hurt performance/readability; balance by exposing only what changes.

## Q10: What is the principle of least privilege in OOP terms?
**A:** Expose the minimum interface needed — correlates with private members and well-scoped public APIs, reducing the attack surface and coupling.
