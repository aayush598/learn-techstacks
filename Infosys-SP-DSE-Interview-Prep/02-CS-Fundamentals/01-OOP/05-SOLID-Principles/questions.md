1. **What are the SOLID principles?**
   - Single Responsibility, Open-Closed, Liskov Substitution, Interface Segregation, Dependency Inversion — five principles for maintainable OO design.

2. **Explain Single Responsibility Principle.**
   - A class should have one reason to change — one responsibility. Splitting concerns keeps classes focused and testable (e.g., separate data access, business logic, presentation).

3. **Explain Open-Closed Principle.**
   - Software should be open for extension but closed for modification — add new behaviour via inheritance/strategies rather than editing existing class code.

4. **Explain Liskov Substitution Principle.**
   - Subtypes must be substitutable for their base types without breaking behaviour — a derived class must not weaken the base's contract (override that throws exceptions is a classic violation).

5. **Explain Interface Segregation Principle.**
   - Clients should not be forced to depend on methods they don't use — prefer several specific interfaces over one fat interface.

6. **Explain Dependency Inversion Principle.**
   - High-level modules should not depend on low-level modules; both should depend on abstractions. Inject dependencies rather than hard-coding implementations (e.g., pass an LLM client, don't import one).

7. **How do the SOLID principles apply to a FastAPI service?**
   - Separate routers/controllers, service (business) layer, repository (data) layer; abstract external clients behind interfaces so they can be swapped or mocked.

8. **Give an example of LSP used properly.**
   - If Rectangle has area(); Square extended from it would break expectations — the famous design smell. Use a Shape abstraction instead — each provides area() consistently.

9. **What is 'favour composition over inheritance'?**
   - Build behaviour by composing objects (has-a) instead of deep inheritance — more flexible at runtime and avoids fragile base-class coupling.

10. **How would you refactor a god class with SRP/OCP?**
   - Extract each responsibility into its own class (SRP), expose them through an interface (ISP), and enable extension via strategy/injection (OCP/DIP).
