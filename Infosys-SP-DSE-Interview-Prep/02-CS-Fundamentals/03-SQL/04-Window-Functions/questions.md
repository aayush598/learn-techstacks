1. **What is a window function?**
   - Computes a value across a set of rows (the window) related to the current row WITHOUT collapsing them into groups — ROW_NUMBER, RANK, SUM() OVER(...) etc.

2. **What is OVER and PARTITION BY?**
   - OVER defines the window; PARTITION BY splits rows into partitions per key; the function computes per partition while each row remains in the result.

3. **What is ORDER BY inside a window (frame)?**
   - ORDER BY defines the row order within a partition and default frame (ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW for running aggregates).

4. **What is ROW_NUMBER vs RANK vs DENSE_RANK?**
   - ROW_NUMBER gives unique sequential numbers even for ties; RANK gives equal ties with gaps; DENSE_RANK gives equal ties without gaps (1,2,2,3 vs 1,2,2,4).

5. **What is NTILE?**
   - Divides the partition into N buckets of as-equal-as-possible size; NTILE(4) assigns 1-4 per row — used for quartile analysis.

6. **What is LAG and LEAD?**
   - Access a row's value n positions before (LAG) or after (LEAD) in the ordering — for trends and differences (price vs previous day).

7. **What is the difference between aggregate with GROUP BY and window?**
   - GROUP BY collapses rows to one per group; window keeps every row and attaches the computed value — the one-line distinction to state first.

8. **Write a query for the nth highest salary using a window.**
   - SELECT DISTINCT salary FROM (SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) r FROM emp) t WHERE r = 2;

9. **What is a frame clause (ROWS vs RANGE)?**
   - ROWS counts actual rows; RANGE aligns by value (peers). Default frame with ORDER BY is RANGE UNBOUNDED PRECEDING TO CURRENT ROW — a gateway to subtle bugs.

10. **How do window functions solve running totals?**
   - SELECT date, amount, SUM(amount) OVER (ORDER BY date) FROM txn; — the running total per row.

11. **When doesn't a window function help?**
   - When the value depends only on a group arrow the GROUP BY/aggregate is the right tool, or when overall percentiles need NTILE/PERCENT_RANK but the query shape favours joins.
