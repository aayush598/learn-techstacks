# Sql — Sql Optimization Interview Questions and Answers

## Q1: List the common causes of slow queries.
**A:** Missing/inefficient indexes, table scans on large tables, SELECT *, heavy joins without stats, functions on indexed columns, the N+1 pattern, and lock contention.

## Q2: How do you improve a slow SELECT?
**A:** Add covering/sargable indexes, rewrite predicates to use them, avoid functions on columns (WHERE sal*2 vs WHERE sal), reduce columns returned, and check the query plan.

## Q3: What is sargability?
**A:** A predicate is sargable when the indexed column stands alone (col = ?, col >= ?); wrapping it (YEAR(col) = 2024 or col+1 = x) disables the index — a favourite optimisation answer.

## Q4: What is an index's role in ORDER BY?
**A:** An index matching the ORDER BY columns lets the planner return rows already sorted — avoiding a sort phase; covering indexes make it even cheaper.

## Q5: What is a query cache as opposed to an index?
**A:** Database/main tools caching result sets or query plans, bypassing reprocessing — differs from indexes (storage structures speeding reads). Only prudent when staleness is acceptable.

## Q6: How does SELECT * hurt performance?
**A:** Brings unneeded columns → wider scans, more I/O, breaks covering indexes, and hard-codes schema — always select only needed columns.

## Q7: How do you reduce JOIN cost?
**A:** Index the join keys (FKs), filter early with WHERE, keep the join order from small to large, and use exists that prevents oversized intermediate results.

## Q8: What is the effect of a high page miss on prepares?
**A:** Repeated identical queries benefit from prepared statements/plan caching — the DB skips planning; for dynamic predicates re-plans keep stats current.

## Q9: When is a full table scan acceptable?
**A:** Small tables, or predicates matching most rows (a full scan beats an index whose selectivity is low) — the planner decides; forcing with hints is an anti-pattern.

## Q10: How do you test the improvement?
**A:** EXPLAIN ANALYZE before/after with the same parameters and dataset — compare actual time and rows; verify the index is used and not just created.
