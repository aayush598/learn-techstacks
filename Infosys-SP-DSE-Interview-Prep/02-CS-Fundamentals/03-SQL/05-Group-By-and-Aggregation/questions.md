# Sql — Group By And Aggregation Interview Questions and Answers

## Q1: What does GROUP BY do?
**A:** Collapses rows into groups sharing the same values of the listed columns; aggregates then compute per group (COUNT, SUM, AVG, MIN, MAX).

## Q2: Write 'count of employees per department'.
**A:** SELECT dept, COUNT(*) FROM emp GROUP BY dept; — the canonical aggregating query.

## Q3: What is the rule about selecting non-aggregated columns?
**A:** In strict SQL, columns in SELECT must be in GROUP BY or wrapped in aggregates (PostgreSQL enforces this) — picking a bare non-grouped column is invalid.

## Q4: What is HAVING vs WHERE again?
**A:** WHERE filters pre-group rows; HAVING filters post-aggregation groups — use HAVING COUNT(*) > 3 or HAVING AVG(sal) > 4000.

## Q5: Write departments whose average salary is above 50000.
**A:** SELECT dept, AVG(salary) a FROM emp GROUP BY dept HAVING a > 50000;

## Q6: How do you count distinct values per group?
**A:** GROUP BY col; SELECT COUNT(DISTINCT other_col) — distinct counted within the group.

## Q7: What is the difference between GROUP BY and PARTITION BY?
**A:** GROUP BY collapses rows; PARTITION BY (window) preserves rows while computing per group — a favourite clarifying question.

## Q8: How do you get the department with the maximum total salary?
**A:** SELECT dept FROM emp GROUP BY dept ORDER BY SUM(salary) DESC LIMIT 1; — aggregate then order.

## Q9: What is the order of execution in a SQL query?
**A:** FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT — knowing this lets you reason about which clause can use which expression.

## Q10: How do you handle NULLs in aggregates?
**A:** COUNT(col) ignores NULLs; SUM/AVG ignore NULLs but AVG over all-NULL returns NULL; COALESCE before aggregating when a default is needed.
