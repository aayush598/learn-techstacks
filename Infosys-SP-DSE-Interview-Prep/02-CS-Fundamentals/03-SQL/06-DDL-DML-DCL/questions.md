# Sql — Ddl Dml Dcl Interview Questions and Answers

## Q1: What is DDL? Name the commands.
**A:** Data Definition Language: CREATE, ALTER, DROP, TRUNCATE, RENAME — defines and manages schema objects. Auto-commits in many DBs.

## Q2: What is DML? Name the commands.
**A:** Data Manipulation Language: INSERT, UPDATE, DELETE — manipulates data inside tables, filterable and transactional (WHERE clauses apply).

## Q3: What is DQL?
**A:** Data Query Language: SELECT — reads data; often grouped with DML for convenience but formally separate.

## Q4: What is DCL and TCL?
**A:** DCL: GRANT/REVOKE (permissions). TCL: COMMIT, ROLLBACK, SAVEPOINT — transaction control.

## Q5: Write an INSERT and an UPDATE.
**A:** INSERT INTO emp(name, dept) VALUES ('Aayush','AI'); UPDATE emp SET salary = 100 WHERE name='Aayush'; — the two bread-and-butter DML statements.

## Q6: What is the difference between UPDATE and DELETE with a WHERE missing?
**A:** UPDATE without WHERE changes EVERY row; DELETE without WHERE deletes ALL rows — the DML foot-guns. Always validate predicates.

## Q7: What happens on an ALTER TABLE ADD column?
**A:** Schema change adds a column (default fill per rules); existing rows get NULL (or the DEFAULT); the table's structure is altered — a DDL statement.

## Q8: How do you drop a table with cascading?
**A:** DROP TABLE orders CASCADE (PostgreSQL) drops dependent objects (views/FKs) too; WITHOUT CASCADE it errors when dependencies exist.

## Q9: What is the difference between DELETE and TRUNCATE for auto-increment?
**A:** TRUNCATE resets the auto-increment counter and is faster; DELETE keeps the counter where it is (gap continues) — a practical DDL/DML distinction.

## Q10: How do you grant and revoke privileges?
**A:** GRANT SELECT ON emp TO alice; REVOKE SELECT ON emp FROM alice; — the DCL pair governing who can do what on which object.
