# Api Design — Api Security Interview Questions and Answers

## Q1: What are the security layers of an API?
**A:** Transport (TLS), authentication (who), authorisation (what they may do), rate limiting (abuse), input validation, and logging/monitoring.

## Q2: What is authentication vs authorisation?
**A:** Authentication proves identity (JWT, API keys, OAuth). Authorisation decides permissions (roles/scopes) — the authN/authZ distinction is a classic interview question.

## Q3: What is OAuth2 and its flows?
**A:** An authorisation framework — authorization-code for user apps, client-credentials for server-to-server, password for first-party — issuing scoped tokens.

## Q4: What is different about a JWT (structure)?
**A:** Header.payload.signature (base64url + HMAC/RSA signature) — stateless verification once you trust the issuing key and check exp/aud/iss.

## Q5: What is an API key vs a JWT?
**A:** API key: static secret for machine clients (revocable, simple). JWT: self-contained claims, exp, scopes — dynamic and standardised.

## Q6: What is rate limiting and the common algorithms?
**A:** Token bucket, fixed/rolling window, sliding log/counter — usually Redis-backed, per key/IP/user; protects against bursts and abuse.

## Q7: What is input validation preventing?
**A:** Injection (SQL/XSS/command), malformed payloads, and schema attacks — Pydantic/validation layers plus ORM param binding handle most.

## Q8: What is the least-privilege principle in APIs?
**A:** Each token/role gets the minimum scopes needed; scopes are checked per endpoint, not globally — damage is bounded when a token leaks.

## Q9: What is a security header set for APIs?
**A:** CORS restrictions, Content-Security-Policy (when serving HTML), and HTTPS-only + HSTS — hardening beyond the request itself.

## Q10: What is an audit log and where do you log?
**A:** Authenticated actions with user, action, IP, and result — the evidence trail for breaches and the compliance requirement for enterprise APIs.

## Q11: What are OWASP API risks you'd list?
**A:** Broken object-level auth, excessive data exposure, and injection remain the top three — name them first, mitigation second.
