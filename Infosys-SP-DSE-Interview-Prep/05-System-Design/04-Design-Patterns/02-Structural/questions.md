1. **What are structural design patterns?**
   - Patterns composing objects and classes into larger structures while keeping them flexible: Adapter, Decorator, Facade, Proxy, Composite.

2. **What is an Adapter?**
   - Wrapping an incompatible interface into one the client expects — the 'translate' layer between APIs, DBs, and third-party SDKs.

3. **What is a Decorator?**
   - Wrapping an object to add behaviour without changing its class — Python implements it natively for functions (decorators); classes add fields/methods.

4. **What is a Facade?**
   - A simplified unified interface over a complex subsystem — hiding internals from callers; your service-layer over routers/repositories is a facade.

5. **What is a Proxy?**
   - A stand-in controlling access to the real object — lazy init, caching, auth checks, logging before the expensive/privileged call.

6. **What is a Composite?**
   - Treating individual objects and compositions uniformly (tree structure) — the foundation of recursive UI and file-system models.

7. **What is the difference between Adapter and Facade?**
   - Adapter single-class interface harmonising; Facade system-wide simplified face — scope is the distinction.

8. **How does Python's functools/caching relate to Proxy?**
   - lru_cache is a transparent proxy with memoisation — the pattern borrowed where Python users rarely name it.

9. **What is composition over inheritance?**
   - Wrapping/what-a objects instead of deep extends — flexibility at test time; the design recommendation you should state confidently.

10. **How do structural patterns help LLM tooling?**
   - Each tool adapter implements a uniform interface; a proxy guards rate limits/auth; a facade hides provider differences — your agent tool registry is this.
