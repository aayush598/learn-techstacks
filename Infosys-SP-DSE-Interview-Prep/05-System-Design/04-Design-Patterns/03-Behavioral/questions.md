1. **What are behavioral design patterns?**
   - Patterns managing communication/responsibilities between objects: Strategy, Observer, Command, State, Template Method, Iterator.

2. **What is a Strategy pattern?**
   - Encapsulating interchangeable algorithms behind an interface — swapping behaviour at runtime (sort key callables in Python are strategies).

3. **What is an Observer pattern?**
   - Objects subscribing to events and being notified on change — pub/sub in GUIs and message systems; in Python, event callbacks or asyncio signals.

4. **What is a Command pattern?**
   - Encapsulating an action as an object with execute/undo — enabling queues, retries, and undo history (the pattern behind task queues).

5. **What is a State pattern?**
   - An object changing behaviour when its internal state changes — vs if/else chains; token flows in agents map here.

6. **What is a Template Method?**
   - A base class defining the skeleton of an algorithm with overridable steps — subclasses specialise steps; frameworks use this daily.

7. **What is the relationship of Observer to message queues?**
   - A queue is the distributed, decoupled realisation of observer semantics — producers don't know consumers; classic patterns scale into systems.

8. **What is the Iterator pattern in Python?**
   - Iterators are language-native (__iter__/__next__); generators implement lazy iteration — the pattern is so absorbed Python developers know it implicitly.

9. **How do behavioral patterns map to agent frameworks?**
   - Strategy = pluggable planning; Observer = event hooks; Command = tool invocation objects with retries — the vocabulary transfers directly.

10. **When should you avoid formal patterns?**
   - Over-applying 'four framework diagnosis' adds indirection; use them where future change/tests justify — judgment over syllabus.
