1. **What is load balancing?**
   - Distributing incoming requests across multiple backend instances; improves availability and throughput and is the backbone of horizontal scaling.

2. **What are the load-balancing algorithms?**
   - Round-robin (even distribution), least-connections (busy-aware), weighted (capacity-aware), IP/consistent-hash (sticky) — pick by workload shape.

3. **What is a layer-4 vs layer-7 load balancer?**
   - L4 balances on IP/port (fast, opaque); L7 inspects HTTP (routing, headers, sticky sessions, TLS termination) — L7 powers modern APIs.

4. **What is a health check in load balancing?**
   - Periodic probes (TCP/HTTP) to mark instances up/down — the LB only routes to healthy nodes, enabling rolling deploys.

5. **What is session affinity / sticky sessions?**
   - Pinning a user to one instance via cookie/hash — avoids re-login but couples to instance state; stateless sessions (external store) remove the need.

6. **What is a reverse proxy vs load balancer?**
   - A reverse proxy fronts backends for one app (nginx: TLS, caching, routing); an LB distributes across many — often the same server does both.

7. **What is consistent hashing and its role?**
   - A hash ring assigning keys to nodes so adding/removing a node only remaps a fraction of keys — essential for cache shards and hash-key affinity.

8. **What happens when a backend dies mid-request?**
   - Retries on another healthy instance with timeout + idempotency keys — the resilience requirement of distributed request handling.

9. **What is a global (DNS/geo) load balancer?**
   - Routing users to the nearest region's LB via DNS policies (latency/geo-based) — cutting cross-region latency for global apps.

10. **How do you test a load-balancer setup?**
   - Synthetic load through the LB, health-check flapping tests, and rolling instance kills — verifying re-routing and failover behave under adversity.
