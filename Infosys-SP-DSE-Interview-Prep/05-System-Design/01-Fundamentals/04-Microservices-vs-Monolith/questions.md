# Fundamentals — Microservices Vs Monolith Interview Questions and Answers

## Q1: What is a monolith?
**A:** One deployable containing all features — simple to build/debug/start, but it scales as one unit and couples teams' releases.

## Q2: What is microservices?
**A:** Independent services, each owning its data, communicating over HTTP/messages, deployed separately — scalable, fault-isolated, and team-aligned.

## Q3: What are the trade-offs of microservices?
**A:** Pros: independent scaling/deploys, organisational alignment, tech freedom. Cons: distributed debugging, network latency, data consistency, ops complexity.

## Q4: What are the patterns for microservices communication?
**A:** Synchronous REST/gRPC for request-response; async message queues/events (Kafka) for decoupling; each has consistency and failure semantics.

## Q5: What is the database per service principle?
**A:** Each service owns its schema — no shared DB access, preserving autonomy; cross-service reads use APIs/events/eventual consistency.

## Q6: What is an API gateway's role?
**A:** Single entry: routing, auth, rate limiting, and aggregation for a family of services — the facade of the microservice mesh.

## Q7: What is service discovery?
**A:** Dynamic location of service instances via registries (Consul/etcd/cloud DNS) since IPs change with auto-scaling — the glue of distributed calls.

## Q8: What is the difference between orchestration and choreography?
**A:** Orchestration: a central coordinator drives steps (simple, single point of failure). Choreography: services react to events independently (decoupled, harder to trace).

## Q9: How do you decompose a monolith?
**A:** Start from boundaries: bounded-context seams (order vs inventory), extract the most-failed/hottest service first, and use the strangler pattern to incrementally replace.

## Q10: What is observability across services?
**A:** Distributed tracing (trace IDs across hops), structured logs, and metrics — joining a request across services; without it microservices are unoperable.

## Q11: When would you keep a monolith?
**A:** Small team, small company, exploratory stage, or strong domain cohesion — microservices' benefits only pay off past a scaling/org threshold.
