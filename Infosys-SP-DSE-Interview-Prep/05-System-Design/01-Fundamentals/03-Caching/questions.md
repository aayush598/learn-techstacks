# Fundamentals — Caching Interview Questions and Answers

## Q1: What is caching?
**A:** Storing frequently-read results closer to the request — in-memory, CDN, or at the DB — to cut latency and reduce downstream load.

## Q2: What is caching at which layers of a web app?
**A:** Browser caching (HTTP headers), CDN (static), app/in-memory (Redis/memcached for hot reads), DB query cache — each layer offloads the next.

## Q3: What is a cache-aside (lazy) pattern?
**A:** Read: check cache, on miss load from DB and populate. Write: update DB, invalidate the cache. Simple and eventually consistent — the most common pattern.

## Q4: What is write-through vs write-back caching?
**A:** Write-through: every write goes to cache then DB (stronger consistency, higher latency). Write-back: accumulate writes and flush (fast, risk of loss on crash).

## Q5: What is cache invalidation and the classic problems?
**A:** Stale reads after DB updates — solved by TTL, explicit invalidation, or versioned keys; invalidation bugs cause the meanest production bugs.

## Q6: What is a TTL and why set it?
**A:** Time-to-live expires entries automatically — bounding staleness; choose per data volatility (config: minutes, user profile: hours, posts: seconds).

## Q7: What is a cache stampede (thundering herd)?
**A:** A hot key expires and N requests all hit the DB — mitigated by locks/single-flight, stale-while-revalidate, or probabilistic expiry.

## Q8: What is an LRU cache?
**A:** Least-Recently-Used eviction: remove the oldest entry when capacity is exhausted — the standard in-memory eviction policy (Redis/LRU, your C++ LRU).

## Q9: What is Redis and its use as a cache?
**A:** A fast in-memory data store (strings/hashes/ttl) shared across instances — the backbone cache/queue/session store for scaled apps.

## Q10: What is the local vs distributed cache trade-off?
**A:** Local: zero network, per-instance duplication. Distributed (Redis): shared, consistent, one more failure domain — pick by scale and consistency needs.

## Q11: What do you cache in an AI API product?
**A:** Prompt/system prefixes, retrieved chunks, and generated response hashes — massive latency/cost savings in RAG and LLM products.
