# Ci Cd — Deployment Strategies Interview Questions and Answers

## Q1: What are the deployment strategies?
**A:** Recreate, rolling, blue/green, canary, and feature-flag/shadow — each trades deploy risk against speed and infrastructure cost.

## Q2: What is a rolling deploy?
**A:** Instances upgrade one-by-one while the service stays up — simple, no extra capacity, but partial-incompatibility window during the roll.

## Q3: What is blue/green deployment?
**A:** Two full environments; switch traffic atomically on the new (green) set — instant rollback to blue, at the cost of doubled capacity.

## Q4: What is a canary deployment?
**A:** Sending ~5-10% of traffic to the new version, watching metrics, then ramping to 100% — incremental trust with real-world verification.

## Q5: What is the rollback strategy and how does it work?
**A:** Every deploy should roll back: previous image is one command away; automated rollback triggers on error-rate/health degradation.

## Q6: What is a zero-downtime deploy?
**A:** Combining readiness probes/before-registration with rolling or blue-green so users never see 503s — the availability standard for production paths.

## Q7: What is database migration's special deploy risk?
**A:** Schema changes must be additive/backwards-compatible (expand-contract); deploys and migrations sequence separately to avoid breaking running versions.

## Q8: What is immutable infrastructure?
**A:** Servers/containers are never patched in place — deployments replace them wholesale with new images; drift is impossible by construction.

## Q9: What is a feature flag and why does it decouple deploys?
**A:** Code ships dormant behind flags, toggled at runtime — releasing features without redeploying and enabling instant kill-switches.

## Q10: What is a shadow deploy?
**A:** Writing the new version side-by-side, mirroring traffic without acting on it — comparing behaviour before exposing users (an advanced technique).

## Q11: What metrics gate a deploy?
**A:** Error rate, latency percentiles, CPU, and business metrics — auto-rollback thresholds are set before, not after, the deploy.
