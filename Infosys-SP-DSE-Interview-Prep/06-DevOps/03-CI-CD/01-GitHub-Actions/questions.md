# Ci Cd — Github Actions Interview Questions and Answers

## Q1: What is GitHub Actions?
**A:** GitHub's CI/CD platform running jobs from YAML workflows in .github/workflows — triggers on push/PR, on a schedule, or manually.

## Q2: What is a workflow vs a job vs a step?
**A:** Workflow: the YAML file. Jobs: parallel stages on runners. Steps: sequential commands within a job — the three-level hierarchy.

## Q3: What are events and how do you trigger workflows?
**A:** push, pull_request, schedule (cron), workflow_dispatch (manual), and paths/branches filters — trigger precision avoids CI noise.

## Q4: What is a matrix build?
**A:** Testing across OS/python-version combinations (matrix: {'os': [...], 'python': [...]}) — parallel coverage of versions.

## Q5: What are actions and where do they come from?
**A:** Reusable composites (checkout, setup-python) from the Marketplace; you can also inline run: steps or publish your own action.

## Q6: How do you pass secrets and environment to jobs?
**A:** secrets.X from repo/org settings (never printed), env: per-job variables, and concurrency to cancel stale runs — secret hygiene is the core skill.

## Q7: What is a cache in Actions?
**A:** actions/cache persists pip/uv caches between runs — cutting install time from minutes to seconds; the speed win every pipeline needs.

## Q8: How do you run tests and lint in CI?
**A:** steps: install deps -> run pytest -> upload coverage — any red job fails the build; quality gates wired into the merge path.

## Q9: How do you build and push an image in CI?
**A:** docker/login-action + build-push-action with tags derived from the ref and version — the containerised release path.

## Q10: What is a workflow_dispatch vs scheduled trigger?
**A:** manual vs cron — the two 'not every push' flavours you'll add for deploys and nightly jobs.

## Q11: How do you deploy from Actions?
**A:** After tests pass: SSH/cloud-deploy action or kubectl/helm — the CD half of CI/CD, with environment protection rules on main.
