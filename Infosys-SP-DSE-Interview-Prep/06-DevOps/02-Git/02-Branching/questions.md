# Git — Branching Interview Questions and Answers

## Q1: What is a branch in Git?
**A:** A movable pointer to a commit — cheap, lightweight parallel lines of work; the mechanism of feature isolation and teamwork.

## Q2: What is the difference between a branch and a tag?
**A:** Branch: evolving pointer moving with commits. Tag: immutable label on a commit (release v1.0) — time-travel markers vs moving lines.

## Q3: What is the checkout vs switch?
**A:** git checkout changes branches/history position; git switch (newer) only changes branches — cleaner separation of concerns.

## Q4: What is the main/master convention?
**A:** The default stable line; feature branches diverge and merge back — the trunk-and-branches shape of most projects.

## Q5: What are the common branching strategies?
**A:** GitFlow (develop/release/hotfix branches), GitHub Flow (short-lived feature branches to main), trunk-based (stack on main continuously) — choose by release cadence.

## Q6: How do you create, list, merge and delete a branch?
**A:** git branch name, git branch -a, git merge name, git branch -d name — the branch lifecycle commands.

## Q7: What is the difference between a local and remote-tracking branch?
**A:** Local: your line of work. remote-tracking (origin/main): cached remote position — push/pull sync them; branches disappear remotely without syncing.

## Q8: How do you pick a good branch name?
**A:** feature/login-flow, fix/payment-timeout — type/name conventions make history navigable and CI matching simple.

## Q9: What happens when you switch branches with uncommitted changes?
**A:** Git keeps them if they don't conflict; otherwise you must stash/commit first — the two common friction points of switching.

## Q10: What is git stash?
**A:** Temporarily shelving uncommitted changes (git stash pop to restore) — the 'I need to switch but not lose work' tool.

## Q11: What is the danger of long-lived branches?
**A:** Divergence → merge pain, integration surprises, and unreviewed drift — short-lived, frequently-integrated branches keep conflicts small.
