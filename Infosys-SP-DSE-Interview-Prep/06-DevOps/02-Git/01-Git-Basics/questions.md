1. **What is Git and how does it track history?**
   - A distributed version control system storing snapshots of the repository tree as commits — immutable history, each sha-1 pointing to tree+parent(s).

2. **What is a commit?**
   - A snapshot (tree hash + parent + author/message) — your atomic 'saved state'; amend/rebasing rewrites only unpublished history.

3. **What is the difference between working directory, staging, and repository?**
   - Working tree: your files. Staging (index): files `git add`-ed for the next commit. Repository: committed history — the three-state model.

4. **What is git add, commit, and status?**
   - add stages changes, commit records a snapshot with a message, status shows what's modified/staged/untracked — the daily trio.

5. **What is a HEAD?**
   - A pointer to the current commit/branch — your working position; moving it (checkout/reset) changes what you see and commit onto.

6. **What is a remote and how do you interact?**
   - Remote repositories (origin) — clone pulls, push sends commits, fetch pulls without merging, pull = fetch+merge — the sync vocabulary.

7. **What is the duty of .gitignore?**
   - Patterns telling Git to exclude untracked junk (venv, caches, .env, build/) — keeping the repo clean and secrets out.

8. **What is git log and reading history?**
   - git log --oneline --graph shows the commit DAG; blame/reflog reveal who changed what and recovery paths.

9. **What does git diff show?**
   - Uncommitted differences (working vs index) or commit-to-commit changes — the review surface before staging.

10. **What is the difference between git status and git log?**
   - status = working/staging state; log = committed history — living changes vs recorded history.

11. **What is a detached HEAD and how dangerous is it?**
   - Checking out a raw commit leaves HEAD detached; new commits become unreachable — fine to inspect, recover via a branch name is the safe pattern.
