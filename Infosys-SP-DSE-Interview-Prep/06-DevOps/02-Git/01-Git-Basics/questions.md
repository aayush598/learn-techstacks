# Git — Git Basics Interview Questions and Answers

## Q1: What is Git and how does it track history?
**A:** A distributed version control system storing snapshots of the repository tree as commits — immutable history, each sha-1 pointing to tree+parent(s).

## Q2: What is a commit?
**A:** A snapshot (tree hash + parent + author/message) — your atomic 'saved state'; amend/rebasing rewrites only unpublished history.

## Q3: What is the difference between working directory, staging, and repository?
**A:** Working tree: your files. Staging (index): files `git add`-ed for the next commit. Repository: committed history — the three-state model.

## Q4: What is git add, commit, and status?
**A:** add stages changes, commit records a snapshot with a message, status shows what's modified/staged/untracked — the daily trio.

## Q5: What is a HEAD?
**A:** A pointer to the current commit/branch — your working position; moving it (checkout/reset) changes what you see and commit onto.

## Q6: What is a remote and how do you interact?
**A:** Remote repositories (origin) — clone pulls, push sends commits, fetch pulls without merging, pull = fetch+merge — the sync vocabulary.

## Q7: What is the duty of .gitignore?
**A:** Patterns telling Git to exclude untracked junk (venv, caches, .env, build/) — keeping the repo clean and secrets out.

## Q8: What is git log and reading history?
**A:** git log --oneline --graph shows the commit DAG; blame/reflog reveal who changed what and recovery paths.

## Q9: What does git diff show?
**A:** Uncommitted differences (working vs index) or commit-to-commit changes — the review surface before staging.

## Q10: What is the difference between git status and git log?
**A:** status = working/staging state; log = committed history — living changes vs recorded history.

## Q11: What is a detached HEAD and how dangerous is it?
**A:** Checking out a raw commit leaves HEAD detached; new commits become unreachable — fine to inspect, recover via a branch name is the safe pattern.
