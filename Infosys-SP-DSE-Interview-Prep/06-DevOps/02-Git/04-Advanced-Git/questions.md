1. **What is the git object model?**
   - blobs (file content), trees (directories), commits (snapshots), tags — hashed by content; everything recoverable from the hashes.

2. **What is the git reflog?**
   - A local log of WHERE HEAD has been — the rescue tool to recover after a reset/rebase mishap; it's your undo for nearly everything.

3. **What does git reset --soft vs --mixed vs --hard do?**
   - --soft: move HEAD, keep staged; --mixed (default): move HEAD, keep working files unstaged; --hard: discard everything — the danger ladder.

4. **What is git bisect?**
   - Binary-search through history to find the commit that introduced a bug (git bisect start + good/bad + run) — a superpower for regressions.

5. **What is a submodule and its issues?**
   - A git repository pinned inside another — separating dependency repos, but updates/version-skew and cloning friction are notorious.

6. **What is git worktree?**
   - Multiple working directories for the same repo (a branch each) — parallel builds/hotfix contexts without stashing churn.

7. **What is hooking — pre-commit?**
   - Client-side hooks (commit-msg, pre-push) automate lint/format checks before commit; husky/pre-commit frameworks manage them.

8. **What is signing commits (GPG)?**
   - Signing verifies you authored the commit — supply-chain trust; GitHub flags verified status for signed commits.

9. **What is shallow cloning and its cost?**
   - --depth 1 fetches only the latest snapshot — fast CI clones, but no full history for blame/branches (mitigated by --depth+--no-single-branch when needed).

10. **What is a bare repository used for?**
   - A repo without a working tree (git init --bare) — the server-side storage for hosts; you push to it, never edit in it.

11. **What is git gc and why does it run?**
   - Garbage collecting unreachable objects packing efficiency — automatically triggered; manual gc --aggressive cleans pathological repos.
