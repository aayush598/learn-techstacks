# Git — Advanced Git Interview Questions and Answers

## Q1: What is the git object model?
**A:** blobs (file content), trees (directories), commits (snapshots), tags — hashed by content; everything recoverable from the hashes.

## Q2: What is the git reflog?
**A:** A local log of WHERE HEAD has been — the rescue tool to recover after a reset/rebase mishap; it's your undo for nearly everything.

## Q3: What does git reset --soft vs --mixed vs --hard do?
**A:** --soft: move HEAD, keep staged; --mixed (default): move HEAD, keep working files unstaged; --hard: discard everything — the danger ladder.

## Q4: What is git bisect?
**A:** Binary-search through history to find the commit that introduced a bug (git bisect start + good/bad + run) — a superpower for regressions.

## Q5: What is a submodule and its issues?
**A:** A git repository pinned inside another — separating dependency repos, but updates/version-skew and cloning friction are notorious.

## Q6: What is git worktree?
**A:** Multiple working directories for the same repo (a branch each) — parallel builds/hotfix contexts without stashing churn.

## Q7: What is hooking — pre-commit?
**A:** Client-side hooks (commit-msg, pre-push) automate lint/format checks before commit; husky/pre-commit frameworks manage them.

## Q8: What is signing commits (GPG)?
**A:** Signing verifies you authored the commit — supply-chain trust; GitHub flags verified status for signed commits.

## Q9: What is shallow cloning and its cost?
**A:** --depth 1 fetches only the latest snapshot — fast CI clones, but no full history for blame/branches (mitigated by --depth+--no-single-branch when needed).

## Q10: What is a bare repository used for?
**A:** A repo without a working tree (git init --bare) — the server-side storage for hosts; you push to it, never edit in it.

## Q11: What is git gc and why does it run?
**A:** Garbage collecting unreachable objects packing efficiency — automatically triggered; manual gc --aggressive cleans pathological repos.

## Q14: What are the advantages and disadvantages of 04 advanced git?
**A:** Advantages: predictability of behaviour, standardised semantics, widely understood patterns. Disadvantages: each design brings overhead or constraints, so it must be balanced against simplicity and project context whenever an alternative exists.
