# Docker — Docker Basics Interview Questions and Answers

## Q1: What is Docker?
**A:** A containerisation platform packaging an app + its dependencies/images into isolated, reproducible units that run anywhere Docker does.

## Q2: What is a container vs a virtual machine?
**A:** Container: shares the host kernel, process-level isolation, MB-sized, seconds to start. VM: full guest OS on a hypervisor, GB-sized, heavier — containers are lighter and more portable.

## Q3: What is an image vs a container?
**A:** An image is the immutable build artifact (layers + config); a container is a running instance of that image with its own writable layer.

## Q4: What are the benefits of containerisation?
**A:** Reproducibility (same image everywhere), dependency isolation, resource efficiency vs VMs, and standardised deploy targets for CI/CD.

## Q5: What are the core Docker concepts?
**A:** Image, container, Dockerfile, registry (Docker Hub), volume, network, docker-compose — the vocabulary for every Docker interview.

## Q6: How does Docker isolation work at a low level?
**A:** Linux namespaces (PID, net, mount, user...) + cgroups (CPU/memory limits) + union filesystems (layer sharing) — the kernel primitives under the hood.

## Q7: What is the lifecycle of a Docker container?
**A:** Created -> running -> paused -> stopped (exit) -> removed; docker run creates+starts; rm cleans up on exit.

## Q8: What is the difference between docker run, start, and exec?
**A:** run creates from an image and starts; start restarts an existing container; exec runs a command inside a running container — the operational three.

## Q9: What is a Docker registry?
**A:** A store for images (Docker Hub or private); docker pull/push moves them; image names encode registry/repo/tag (user/app:tag).

## Q10: What is the container port mapping?
**A:** -p host:container binds the host port to the container's internal port — making services reachable; networking inside is isolated otherwise.

## Q11: What is Docker's 'everything immutable, state external' rule?
**A:** Containers are disposable — writes are lost unless mounted as volumes; persistence belongs in volumes/DBs, not the container filesystem.
