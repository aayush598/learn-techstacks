# Docker — Advanced Docker Interview Questions and Answers

## Q1: What is Docker networking — bridge, host, none?
**A:** bridge (default, NAT isolation), host (shared host network), none (isolated), plus overlay for swarm — choose per exposure needs.

## Q2: What is Docker volume vs bind mount?
**A:** Volumes: managed, portable, stored by Docker. Bind mounts: host path mounted directly (dev). Volumes win for prod data; binds for config dev.

## Q3: What is an ephemeral vs persisted container?
**A:** Ephemeral: all config/state passed in, safe to recreate. Persisted: volumes house DB/upload data — the stateless-container principle in practice.

## Q4: What is the Docker lifecycle for garbage collection?
**A:** docker system prune (dangling images/containers/networks) and volume prune — housekeeping that keeps hosts from filling up.

## Q5: What are the resource limits you can impose?
**A:** --memory, --cpus, and runtime quotas enforce a container's cgroup limits — preventing one app starving the host.

## Q6: What is Docker's relationship to Kubernetes?
**A:** Docker builds/run containers; K8s orchestrates them across nodes — scheduling, service discovery, scaling, self-healing; the packaging vs platform distinction.

## Q7: What is containerd/runc and where do they sit?
**A:** runc creates containers from OCI specs; containerd is the daemon managing runc; Docker uses both underneath — the modern runtime stack.

## Q8: How do you optimise docker build caching?
**A:** Layer order, multi-stage, and BuildKit features (cache mounts for pip) — hitting the cache avoids re-downloading dependencies every build.

## Q9: What is BuildKit?
**A:** The modern Docker build engine — parallel stages, better caching, SSH/secret mounts, and provenance; enabled by default in Docker 23+.

## Q10: What is the security surface of Docker?
**A:** Non-root users, read-only rootfs, minimal images, secret handling, registry trust, and SBOM — from OS hardening to supply-chain hygiene.

## Q11: What is docker diff and debugging a container?
**A:** docker exec -it container sh (inspect), docker logs (stdout), and docker top/inspect — the diagnosing toolkit when something misbehaves.
