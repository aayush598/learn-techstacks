# Docker — Dockerfile Interview Questions and Answers

## Q1: What is a Dockerfile and its key instructions?
**A:** The build recipe: FROM (base), WORKDIR, COPY, RUN (build-time), ENV, EXPOSE, CMD/ENTRYPOINT — a declarative image definition.

## Q2: What is the difference between CMD and ENTRYPOINT?
**A:** ENTRYPOINT is the fixed process (can't be overridden casually); CMD supplies default args — combine (ENTRYPOINT + CMD) for a default-and-overridable command.

## Q3: How do you build and tag an image?
**A:** docker build -t myapp:1.0 . — the build context (.) is sent to the daemon; tag format repo:tag for registry push.

## Q4: How do you pass build-time vs runtime config?
**A:** ARG for build-time (FROM versions, build args), ENV for runtime; different use cases and caching implications.

## Q5: What is a multi-stage build and why use it?
**A:** Chaining FROM statements: one stage compiles (huge toolchains), the final stage copies only artifacts into a slim runtime image — dramatically smaller, safer images.

## Q6: Why is the order of instructions important for layer caching?
**A:** Docker caches layers; COPY requirements.txt before the rest, then RUN pip install — so dependency installs cache unless requirements change; frequent-changers last.

## Q7: What makes an image slim?
**A:** Slim base (python:slim/distroless/scratch), multi-stage builds, removing caches (pip --no-cache-dir apt lists), and non-root users — the size-optimisation checklist.

## Q8: What is the best practice of running as non-root?
**A:** USER appuser in the Dockerfile — containers running as root escalate host risk; security best practice shouted at interviews.

## Q9: How do you handle secrets at build vs runtime?
**A:** Never bake secrets into images — build args/COPY embed them, leaking in layers; inject via env/compose/K8s secrets at runtime.

## Q10: What is a healthcheck instruction?
**A:** HEALTHCHECK CMD tells Docker to probe the app (curl/health endpoint) — orchestrators/LB decide readiness from the result.

## Q11: What is .dockerignore and why is it critical?
**A:** Excluding .git, venv, __pycache__, caches from the build context — faster builds, smaller contexts, and no accidental secret copying.

## Q12: What is the difference between RUN vs CMD in building the app?
**A:** RUN executes during build (results become layers); CMD runs at container start — confusion here is a classic Docker interview trap.
