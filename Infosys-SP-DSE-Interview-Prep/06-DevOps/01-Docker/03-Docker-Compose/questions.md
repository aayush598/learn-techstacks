# Docker — Docker Compose Interview Questions and Answers

## Q1: What is docker compose?
**A:** A YAML orchestration file (docker-compose.yml) defining multi-container apps — services, networks, volumes — with one `docker compose up`.

## Q2: How do you define a service in compose?
**A:** services: {name: {image or build, ports, env, volumes, depends_on, healthcheck}} — the declarative unit of the app.

## Q3: What is the difference between image and build in a service?
**A:** image pulls a ready artifact; build builds from a Dockerfile (context) — combine build + image to use the built tag.

## Q4: How does compose networking work?
**A:** An implicit bridge network lets services resolve each other by service name (myapi) — internal DNS instead of IP juggling.

## Q5: How do volumes persist in compose?
**A:** Named volumes (declared under volumes:) survive container recreation; bind mounts (./host:path) share host files — the persistence mechanism.

## Q6: How do you set environment/config in compose?
**A:** environment: inline vars, env_file: for files, and ${VAR} interpolation — externalising config without editing YAML per env.

## Q7: What does depends_on do vs health gates?
**A:** depends_on orders start; real readiness needs condition: service_healthy with healthchecks — start-order isn't app-readiness.

## Q8: What is the difference between compose for dev and prod?
**A:** Dev: bind mounts for live reload + debug ports. Prod: built images, healthchecks, restarts — separate compose files override with -f.

## Q9: How do you scale a compose service?
**A:** docker compose up --scale api=3 (with ports mapped) — simple horizontal scaling for dev-stage, but production scale is orchestration (K8s) territory.

## Q10: How do you tear down without losing data?
**A:** docker compose down removes containers/networks; --volumes wipes named volumes — associate persistence with volume declarations.

## Q11: How would you compose an AI stack?
**A:** Services: API (FastAPI), Postgres, Redis, and a vector DB (Chroma) — each with healthchecks and internal-network links; the exact local RA stack.
