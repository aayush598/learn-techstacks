# Agentic Ai — Langgraph Interview Questions and Answers

## Q1: What is LangGraph?
**A:** A graph-based orchestration layer on LangChain — nodes and edges model agent control flow with state, cycles, and persistence; built for production agents.

## Q2: What is the difference between LangChain chains and LangGraph?
**A:** Chains are DAG pipes; LangGraph supports cycles and stateful branching — the 'while loop' agent workflows need that chains can't express.

## Q3: What is a graph state in LangGraph?
**A:** A shared typed state (usually TypedDict/Protocol) that all nodes read/update — the single source of truth threaded through the graph.

## Q4: What is a node vs an edge?
**A:** Nodes run logic (functions/model calls/tools); edges route between them — optionally conditional edges choosing the next node based on state.

## Q5: What is a conditional edge?
**A:** After a node, a function inspects state and picks among several next nodes — the decision routing that makes graphs dynamic.

## Q6: What is checkpointing/persistence in LangGraph?
**A:** Saving graph state between steps (SQLite/Postgres) enabling resume, human-in-the-loop, and time-travel debugging — major production win.

## Q7: What is the single graph 'supervisor' pattern?
**A:** A supervisor LLM node delegates to specialised subgraphs — applying the multi-agent pattern with graph topology.

## Q8: How does LangGraph compare to plain ReAct code?
**A:** ReAct-in-a-loop is a few lines; LangGraph formalises state, retries, persistence, and visualisation — worth the dependency at scale, overhead for one-offs.

## Q9: What is streaming in LangGraph?
**A:** Streaming per-node events (state updates, LLM tokens) — live progress in UIs and step-by-step observability.

## Q10: Why did you move from LangChain chains to LangGraph for agents?
**A:** Loops and tool-feedback branching need cycles + saved state — chains compose DAGs only; if you've built agents, this is your honest engineering answer.
