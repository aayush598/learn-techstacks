# Agentic Ai — Mcp And A2A Interview Questions and Answers

## Q1: What is MCP (Model Context Protocol)?
**A:** An open protocol standardising how LLM apps connect to tools/data sources — servers expose resources/tools/prompts; clients (agents/IDEs) consume them uniformly.

## Q2: How does MCP relate to function calling?
**A:** Function calling is model-level; MCP is application-level — a uniform transport (stdio/HTTP) to expose tools as a service to any MCP-capable client.

## Q3: What are the MCP primitives — tools, resources, prompts?
**A:** Tools: actionable functions the model may call. Resources: context/data retrievable (files, DB rows). Prompts: reusable instruction templates.

## Q4: What is the difference between a server and a client in MCP?
**A:** The server exposes capabilities; the client (Claude Desktop, an agent framework, an editor) discovers and invokes them — decoupling tools from apps.

## Q5: What is A2A (Agent-to-Agent)?
**A:** Google/community's Agent2Agent protocol defining deterministic contracts for agents to discover, negotiate, and cooperate across vendors.

## Q6: How do MCP and A2A differ in scope?
**A:** MCP connects an agent to tools/data; A2A connects agents to other agents — the tool protocol vs the inter-op protocol distinction.

## Q7: Why standardise agent protocols?
**A:** Every framework re-implementing tool wiring is waste; standards move the ecosystem — the engineering-economics argument interviewers respect.

## Q8: What would an MCP server for your project look like?
**A:** Given MigratorGen/ScriptVector: an MCP server exposing 'migrate_script', 'semantic_search_snippet', 'run_analysis' as tools — pluggable into any client.

## Q9: What are the security considerations for MCP?
**A:** Server provenance, tool permissions, and data exfiltration risks — least-privilege scoping per client; protocol adoption must include policy.

## Q10: What does the current MCP ecosystem baggage look like?
**A:** Fast-moving, version churn, and client incompatibility — evaluate lock-in versus openness when choosing an agent stack.
