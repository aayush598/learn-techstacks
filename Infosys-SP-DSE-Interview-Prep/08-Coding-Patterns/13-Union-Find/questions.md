# Coding Patterns — Union Find Interview Questions and Answers

## Q1: What is Union-Find (disjoint set)?
**A:** A data structure tracking partition membership with near-O(1) amortised find/union — the workhorse for connectivity and dynamic-grouping problems.

## Q2: What are the core operations?
**A:** find(x) returns the root/representative; union(a,b) merges two sets; often also connected(a,b) = find(a) == find(b) — maintained in O(alpha(n)) amortised.

## Q3: What are path compression and union by rank/size?
**A:** Path compression flattens nodes to their root during find; union by size/rank attaches the smaller tree to the larger — together they give the inverse-Ackermann bound.

## Q4: Why is the union-find so fast?
**A:** Both heuristics make trees nearly flat—so find is essentially O(1)—and the amortised bound is O(alpha(n)), effectively constant for all practical inputs.

## Q5: What are the classic applications?
**A:** Graph connectivity (is there a path?), number of connected components, detecting cycles in Kruskal's MST, and dynamic equivalence queries — the standard roster.

## Q6: How does union-find detect cycles in undirected graphs (Kruskal)?
**A:** Before adding an edge, if find(u) == find(v) the edge creates a cycle — skip it; otherwise union. That single check powers Kruskal's MST algorithm.

## Q7: What is the difference between union-find and BFS/DFS for connectivity?
**A:** Union-find supports dynamic connections and incremental queries without re-traversal; BFS/DFS gives an O(V+E) one-shot answer when the graph is static.

## Q8: What is the number-of-provinces problem?
**A:** Union-find over nodes; after processing all connections the number of components = distinct roots — a direct application with a child/rank implementation.

## Q9: What is the implementation shape in Python?
**A:** parent = list(range(n)); rank = [0]*n; find with while-parent-loop + path compression; union compares ranks then attaches — about 15 lines, tested on classic inputs.

## Q10: What are the edge cases?
**A:** n == 0 or 1, disconnected nodes, self-loops, duplicate edges, and nodes added after unions — the boundary set that finds off-by-ones in init/tracking.

## Q11: When is union-find NOT the right choice?
**A:** When you need path details (the actual route), shortest distances, or weighted ordering — BFS/Dijkstra/MST handle those; union-find only answers membership queries.
