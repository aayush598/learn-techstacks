# Coding Patterns — Dynamic Programming Patterns Interview Questions and Answers

## Q1: What is the dynamic programming pattern?
**A:** Solving problems by combining solutions to overlapping subproblems, storing them in a table — beating exponential recursion by avoiding recomputation.

## Q2: What are the two implementation styles?
**A:** Top-down (memoised recursion: recursive call + cache) and bottom-up (iteration filling a table in dependency order) — equivalent results; pick by clarity and recursion limits.

## Q3: How do you recognise a DP problem?
**A:** Optimal substructure (the best solution uses best solutions of subproblems) + overlapping subproblems (same subproblem solved repeatedly) — the two required properties.

## Q4: What is the standard DP framework?
**A:** 1) Define state (what am I computing?), 2) recurrence/transition (how to express state in smaller states), 3) base cases, 4) answer location, 5) complexity — in that order.

## Q5: What is the difference between DP and greedy?
**A:** Greedy makes a locally optimal choice once with no backtracking; DP evaluates all choices via subproblem optimums — valid only when greedy's simple rule provably works.

## Q6: What are the classic 1-DP patterns?
**A:** Climbing stairs, house robber (take/skip with state), longest increasing subarray — single-array transitions ending 'at i' — the entry point to recurrence design.

## Q7: What is the knapsack (0/1) pattern?
**A:** State dp[i][w] = best using first i items within capacity w; transition take/skip; the template for subset-sum, partition, and coin-change constrained variants.

## Q8: What is the 2D-grid DP pattern?
**A:** dp[i][j] from dp[i-1][j] and dp[i][j-1] (paths) or dp[i-1][j-1] (edit distance) — the matrix-problem template with row-major bottom-up filling.

## Q9: What is the state-machine DP pattern?
**A:** Maintain a few states per step (hold/sold/cool) transitioning between them — multi-state 1-DP that handles buy-sell-stock and sequential-decision problems.

## Q10: What is the time/space trade-off in DP?
**A:** Full tables are O(states) space; many transitions only need the previous row — rolling arrays cut space to O(1) or O(n) while keeping time equal.

## Q11: When does DP fail?
**A:** When subproblems aren't overlapping (divide-and-conquer instead) or the optimal substructure doesn't hold — e.g., longest simple path — and when state space explodes (your choice vs greedy/backtracking).
