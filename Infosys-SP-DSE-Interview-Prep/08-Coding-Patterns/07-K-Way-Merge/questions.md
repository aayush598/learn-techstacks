# Coding Patterns — K Way Merge Interview Questions and Answers

## Q1: What is the k-way merge pattern?
**A:** Merging k sorted lists/arrays in O(n log k) using a heap of k heads — extending the standard two-way merge to arbitrary k inputs.

## Q2: What is the algorithm?
**A:** Push each list's head (value,list_index) into a min-heap; repeatedly pop the min, add it to output, and push that list's next element — O(n log k).

## Q3: What is the complexity and why?
**A:** Each output element costs O(log k) for one push/pop; with n total elements it's O(n log k) time and O(k) heap space — versus O(nk) naive scanning.

## Q4: When does k-way merge beat flatten-and-sort?
**A:** When inputs are already sorted (very often in interview problems): merge is O(n log k), sort is O(n log n) — win when k << n and inputs are ready.

## Q5: How do ties and duplicate values across lists get handled?
**A:** Heap tuples compare lexicographically — include the list index in the tuple so equal values from different lists both emerge in stable order.

## Q6: What is merge-k-sorted-lists's classic solution?
**A:** A min-heap holding one node per list; pop-min appends to result, then push that list's next node — the canonical LeetCode 23 solution, O(n log k).

## Q7: How does this connect to external merge sort?
**A:** In disk sorting you merge many sorted runs with an external k-way merge — the same heap frontier, bounded by run buffers instead of RAM.

## Q8: What is the two-way merge relationship?
**A:** k=2 reduces to the classic merge step of merge sort — the pattern generalises it; combining batched merges (divide-and-conquer pairwise) gives the same O(n log k).

## Q9: What are the edge cases?
**A:** Empty lists among the k inputs, a single non-empty list, k == 0, and lists of drastically different lengths — skip empties upfront.

## Q10: When would you NOT use a heap?
**A:** When k is small and lists are tiny — a flattened sort (O(n log n)) or pairwise merges may be simpler and faster in constants; state the trade-off.
