1. **What is binary search?**
   - Halving a sorted search space each step via a mid comparison — O(log n) time, the canonical divide-and-conquer search algorithm.

2. **What is the standard invariant?**
   - Before every iteration, the answer is known to lie in [lo, hi]; comparing mid decides which half to discard while preserving the invariant — the proof that we never lose the answer.

3. **What are the boundary and index conventions?**
   - Lo = 0, hi = n (exclusive) vs hi = n-1 (inclusive) — pick one and be consistent: inclusive [lo,hi] with lo<=hi and mid=(lo+hi)//2 is the popular variant.

4. **How do you avoid overflow computing mid?**
   - In Python there's no int overflow, but the general idiom mid = lo + (hi - lo)//2 teaches the skill for fixed-width languages.

5. **How do you find the first (or last) occurrence of a value?**
   - Continue searching left after a match (first) or right (last) instead of returning early — binary search over 'where does the true region start'.

6. **What is binary search on the answer?**
   - When a predicate is monotone over a numeric range (is this chunk size feasible?), binary search the value, not an index — e.g., minimum capacity or max of k-subarrays.

7. **What is the difference between finding a value and finding a boundary?**
   - Value search returns on equality; boundary search (lower/upper bound) keeps searching until lo crosses hi, always maintaining the invariant — the harder-but-standard variant.

8. **What are the edge cases?**
   - Empty array, single element, value smaller/larger than all, duplicates, and the boundary at index 0 or n-1 — tests that expose off-by-one.

9. **What is the time/space complexity and why is it unbeatable here?**
   - O(log n) comparisons, O(1) space — necessary because each comparison catches (kills) at most half of a sorted candidate set.

10. **What is the binary-search pattern in real systems?**
   - Inverted-index ranked retrieval, database low/high bounds, version bisection (git bisect), and any monotone feasibility check — the same O(log n) core everywhere.
