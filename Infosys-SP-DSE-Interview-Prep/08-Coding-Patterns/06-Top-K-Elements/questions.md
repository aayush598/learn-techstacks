# Coding Patterns — Top K Elements Interview Questions and Answers

## Q1: What is the top-k pattern?
**A:** Finding the k largest/smallest/most-frequent elements efficiently — heap-based O(n log k) selection that beats full sorting when k is small.

## Q2: What is the min-heap approach for top-k largest?
**A:** Maintain a min-heap of size k; for each element, push it and pop the smallest when size exceeds k — the heap always holds the current top-k, O(n log k) total.

## Q3: When would you sort instead of heap?
**A:** When k is comparable to n (sorting is O(n log n) same order) or you need the full order; heap wins decisively when k << n (e.g., top-10 of 1M).

## Q4: How do you find top-k frequent using a Counter plus heap?
**A:** Build counts via Counter (O(n)), then push (count, element) into a min-heap keeping size k — O(n log k); compare with bucket sort for O(n) when k ~ categories.

## Q5: What is the quickselect alternative?
**A:** Hoare-partition selection on the array of scores, discarding the half that can't contain the answer — O(n) average time, O(1) space but not stable.

## Q6: What is the priority queue key ordering convention?
**A:** Python heapq is a min-heap on tuples lexicographically — (count, item) keeps lowest count on top as desired, or use negative keys for max behaviour.

## Q7: What is the difference between this and the heap-pattern?
**A:** The top-k pattern IS the heap pattern applied to selection; the heap pattern additionally covers merge-k-sorted and sliding-window-maximum style applications.

## Q8: How do you return the k closest points to origin?
**A:** Push (squared-distance, point) into a max-heap of size k and evict the farthest — equivalently a min-heap with negatives; O(n log k).

## Q9: What is the time/space profile?
**A:** O(n log k) time, O(k) space for heap approaches — vs O(n log n)/O(n) for sort; giving both and justifying the choice is the expected interview behaviour.

## Q10: What edge cases need handling?
**A:** k == 0, k >= n (return everything sorted), duplicates and ties in frequency, and negative values (they sort normally but ordered-heap keys need consistent polarity).
