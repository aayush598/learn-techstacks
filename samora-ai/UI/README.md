# UI Interview Questions and Answers (Top 100)

## Q1: What is the difference between UI and UX?
**A:** UI (User Interface) is the visual and interactive layer—buttons, layouts, typography—that users see and touch. UX (User Experience) is the overall feel and journey, covering research, flow, and usability; UI is a subset of UX.

## Q2: What does UI stand for and what does it encompass?
**A:** UI stands for User Interface; it encompasses everything a user interacts with on a screen or device, including visual elements, input controls, and feedback mechanisms.

## Q3: Name the main types of user interfaces.
**A:** The main types are GUI (graphical), CLI (command line), VUI (voice/user interface), gesture-based (touch/ motion), and menu-driven interfaces.

## Q4: What is a GUI?
**A:** A GUI (Graphical User Interface) uses windows, icons, and pointers so users interact via visual elements rather than text commands, e.g., Windows or a web app.

## Q5: What is a CLI and when is it useful?
**A:** A CLI (Command Line Interface) lets users type commands to control software; it is useful for power users, automation, and server administration where speed and scripting matter.

## Q6: What is a VUI (voice user interface)?
**A:** A VUI lets users interact through spoken language, like Siri or Alexa, relying on speech recognition and natural language processing instead of visual controls.

## Q7: What is a gesture-based interface?
**A:** A gesture-based interface interprets touch, swipe, pinch, or motion as input, common on smartphones and devices like the Nintendo Wii or AR/VR headsets.

## Q8: State Nielsen's 10 usability heuristics.
**A:** 1) Visibility of system status, 2) match between system and real world, 3) user control and freedom, 4) consistency and standards, 5) error prevention, 6) recognition rather than recall, 7) flexibility and efficiency of use, 8) aesthetic minimalist design, 9) help users recognize/recover from errors, 10) help and documentation.

## Q9: What is the principle of consistency in UI design?
**A:** Consistency means using the same patterns, colors, labels, and behaviors across the product so users can transfer knowledge and predict outcomes, reducing cognitive load.

## Q10: What is clarity in UI design?
**A:** Clarity means every element has an obvious purpose and the interface communicates information without ambiguity, using plain language and unmistakable visuals.

## Q11: Why is feedback important in UI?
**A:** Feedback confirms an action was received (e.g., a spinner, toast, or color change), reassuring users the system is working and preventing repeated or confused inputs.

## Q12: What is an affordance?
**A:** An affordance is a property of an object that suggests how it should be used, like a button looking pressable or a handle looking grabbable.

## Q13: What is a signifier?
**A:** A signifier is a cue (label, icon, color) that communicates where an affordance exists, such as underlined text signaling a link.

## Q14: Explain Fitts's Law.
**A:** Fitts's Law states that the time to reach a target depends on its distance and size—larger and closer targets are faster to click; apply it by making primary buttons big and near the cursor.

## Q15: Explain Hick's Law.
**A:** Hick's Law says decision time increases with the number of choices; limit options, group related items, and use progressive disclosure to speed decisions.

## Q16: What is visual hierarchy?
**A:** Visual hierarchy arranges elements so the eye is drawn to the most important content first, using size, color, contrast, spacing, and position.

## Q17: How do you establish visual hierarchy?
**A:** Use contrast in size and color for headings, place key actions prominently, group related content, and employ whitespace to separate levels of importance.

## Q18: What is a grid system?
**A:** A grid system divides a layout into columns and rows to align content consistently, improving structure and readability (e.g., 12-column grids in Bootstrap).

## Q19: What is whitespace and why is it important?
**A:** Whitespace (negative space) is the empty area between elements; it improves readability, focuses attention, and makes interfaces feel clean and uncluttered.

## Q20: What is alignment in layout design?
**A:** Alignment places elements along common edges or axes to create order and connection; misaligned items feel chaotic and harder to scan.

## Q21: What is proximity in design?
**A:** Proximity groups related items close together so users perceive them as a unit, reducing confusion about what belongs together.

## Q22: What are the core principles of spacing systems?
**A:** Use a consistent spacing scale (e.g., 4px or 8px base) for margins and padding so layouts feel rhythmic and predictable across screens.

## Q23: What is color contrast and why does it matter?
**A:** Contrast is the difference in luminance between foreground and background; it ensures text is readable, especially for low-vision users, and is required by WCAG.

## Q24: What are the WCAG contrast ratio requirements?
**A:** WCAG 2.1 requires 4.5:1 for normal text and 3:1 for large text (AA); AAA requires 7:1 and 4.5:1 respectively.

## Q25: What is the difference between hue, saturation, and value?
**A:** Hue is the color itself (red, blue), saturation is its intensity/purity, and value (lightness) is how light or dark it is; together they define a color's appearance.

## Q26: What is a complementary color scheme?
**A:** It pairs colors opposite on the color wheel (e.g., blue and orange) to create high contrast and visual energy, useful for call-to-action emphasis.

## Q27: Why avoid relying on color alone to convey meaning?
**A:** About 8% of men have color blindness; use icons, text, or patterns alongside color so information is accessible to everyone.

## Q28: What is typography in UI?
**A:** Typography is the style and arrangement of text—font choice, size, weight, line height, and spacing—that affects readability and tone.

## Q29: What is the difference between serif and sans-serif fonts?
**A:** Serif fonts have decorative strokes (good for print/headings), while sans-serif fonts lack them and read cleaner on screens, making them common for UI body text.

## Q30: What is font pairing?
**A:** Font pairing combines two complementary typefaces (e.g., a bold display font for headings with a neutral sans for body) to create contrast while staying harmonious.

## Q31: What is the difference between rem and em units?
**A:** `em` is relative to the parent element's font size, while `rem` is relative to the root (html) font size, making `rem` more predictable for consistent scaling.

## Q32: What is a good line length for readable text?
**A:** Aim for 45–75 characters per line (ideal ~66); too long or too short strains reading and breaks rhythm.

## Q33: What is line-height and why does it matter?
**A:** Line-height is the vertical space between text lines; 1.4–1.6 for body text improves readability by preventing lines from feeling cramped.

## Q34: What is a button and what makes a good one?
**A:** A button triggers an action; a good one has clear labeling, sufficient size (min 44×44px touch target), visible affordance, and distinct primary/secondary hierarchy.

## Q35: What are the differences between primary, secondary, and tertiary buttons?
**A:** Primary buttons are high-emphasis for the main action; secondary support it with less contrast; tertiary (text buttons) are low-emphasis for minor actions.

## Q36: What are best practices for form design?
**A:** Use clear labels, inline validation, logical grouping, minimal required fields, helpful placeholder hints, and visible error messages near the field.

## Q37: What is a modal and when should you use one?
**A:** A modal is a focused dialog overlaying the page for critical tasks (confirmation, forms); use it sparingly since it interrupts the user's flow.

## Q38: What is a card component?
**A:** A card is a contained, padded surface grouping related content (image, title, text, action) into a scannable unit, common in dashboards and feeds.

## Q39: What is a navigation bar best practice?
**A:** Keep it persistent, limited to 5–7 items, clearly indicate the active page, and ensure it collapses gracefully on mobile (e.g., hamburger menu).

## Q40: How should you design data tables?
**A:** Use zebra striping or row hover, align numbers right and text left, sticky headers for scroll, and clear sorting/filtering controls.

## Q41: What is a design system?
**A:** A design system is a collection of reusable components, patterns, and guidelines (tokens, docs) that keep a product visually and behaviorally consistent.

## Q42: Name popular component libraries/design systems.
**A:** Google Material Design, Microsoft Fluent, Ant Design, IBM Carbon, Atlassian Design System, and Apple Human Interface Guidelines.

## Q43: What is Material Design?
**A:** Google's design system using grid-based layouts, responsive animations, depth (elevation/shadows), and components like FABs to create a unified Android/web look.

## Q44: What is IBM Carbon?
**A:** Carbon is IBM's open-source design system focused on enterprise products, emphasizing clarity, efficiency, and accessible data-heavy interfaces.

## Q45: What is Ant Design?
**A:** Ant Design is a React UI library/design system from Alibaba offering polished, enterprise-grade components with sensible defaults.

## Q46: What are design tokens?
**A:** Design tokens are named variables (e.g., `color.primary`, `space.md`) storing design decisions so values stay consistent across code and platforms.

## Q47: What is the benefit of design tokens?
**A:** They centralize theming—change a token once and it updates everywhere—enabling theming, brand switching, and design-dev alignment.

## Q48: What is responsive design?
**A:** Responsive design uses fluid grids, flexible images, and media queries so a layout adapts to any screen size from one codebase.

## Q49: What are common breakpoints?
**A:** Typical breakpoints: mobile (<576px), tablet (576–768px), desktop (768–1200px), large (1200px+), though content-based breakpoints are preferred over device ones.

## Q50: What is mobile-first design?
**A:** Mobile-first means designing for small screens first, then progressively enhancing for larger ones, ensuring core content works on constrained devices.

## Q51: What is a fluid layout?
**A:** A fluid layout uses relative units (%, vw, fr) and `clamp()` so elements resize smoothly rather than jumping at fixed breakpoints.

## Q52: What is the difference between responsive and adaptive design?
**A:** Responsive design flows continuously with one flexible layout; adaptive design serves distinct fixed layouts for specific device ranges.

## Q53: What is accessibility (a11y) in UI?
**A:** Accessibility ensures people with disabilities (visual, motor, cognitive) can perceive, operate, and understand the interface, often via WCAG standards.

## Q54: What is semantic HTML and why does it matter?
**A:** Semantic tags (`<header>`, `<nav>`, `<button>`, `<main>`) convey meaning to browsers and screen readers, improving accessibility and SEO.

## Q55: What is ARIA and when should you use it?
**A:** ARIA (Accessible Rich Internet Applications) adds roles, states, and properties to make dynamic content accessible, but use native HTML first and ARIA only to fill gaps.

## Q56: How do you make a UI keyboard navigable?
**A:** Ensure logical tab order, visible focus rings, skip links, and that all actions (menus, modals) are operable via keyboard (Enter, Escape, arrow keys).

## Q57: What is a screen reader and how do you support it?
**A:** A screen reader (VoiceOver, NVDA) reads UI aloud; support it with semantic HTML, alt text, ARIA labels, and proper heading order.

## Q58: How do you handle images for accessibility?
**A:** Use descriptive `alt` text for meaningful images, empty `alt=""` for decorative ones, and ensure text in images isn't the sole conveyer of info.

## Q59: What is focus management in modals?
**A:** Trap focus inside the modal, move focus to it on open, return focus to the trigger on close, and allow Escape to dismiss.

## Q60: What is the 44px touch target guideline?
**A:** Apple and WCAG recommend interactive targets be at least 44×44 CSS px so they're easily tappable on touch devices without mis-taps.

## Q61: What are the four common UI states?
**A:** Loading, empty, error, and success states—each should be designed so users always understand what's happening and what to do next.

## Q62: Why design empty states?
**A:** Empty states (no data yet) guide users with helpful copy and a clear next action, turning a dead-end into onboarding or encouragement.

## Q63: What makes a good error state?
**A:** Clear, human language explaining what went wrong and how to fix it, without blame, plus a path to recover (retry, undo).

## Q64: What is a microinteraction?
**A:** A microinteraction is a small, focused moment of feedback (like a toggle animating or a like button bursting) that confirms an action and adds delight.

## Q65: Give examples of microinteractions.
**A:** A button press ripple, a password strength meter, a pull-to-refresh spinner, or a checkbox tick animation are common microinteractions.

## Q66: What is the purpose of animations in UI?
**A:** Animations guide attention, show relationships (e.g., element expanding from a button), and provide feedback, making changes feel smooth rather than jarring.

## Q67: What is easing in animation?
**A:** Easing controls the acceleration curve (e.g., `ease-out` starts fast then slows); it makes motion feel natural instead of linear and robotic.

## Q68: How do you respect reduced-motion preferences?
**A:** Use `@media (prefers-reduced-motion: reduce)` to disable or simplify animations for users who get motion sickness or prefer calm interfaces.

## Q69: What is dark mode?
**A:** Dark mode renders the UI with a dark background and light text, reducing eye strain in low light and saving battery on OLED screens.

## Q70: What are challenges in implementing dark mode?
**A:** Avoid pure black/white (use near-values), maintain contrast, reverse shadows to elevation, and ensure images and tokens adapt correctly.

## Q71: What is theming?
**A:** Theming uses tokens and CSS variables to swap visual treatments (brand colors, light/dark) without changing component logic.

## Q72: How do CSS custom properties help theming?
**A:** CSS variables (`--color-bg`) let you redefine values at runtime for themes or modes, scoped globally or per-component, with no rebuild.

## Q73: What is a design handoff?
**A:** Handoff is transferring designs (Figma, Sketch) to developers with specs, assets, and tokens so implementation matches intent.

## Q74: How do you hand off from Figma to code?
**A:** Use Figma's Inspect panel for measurements/colors, export assets, share design tokens via plugins, and document component behavior and states.

## Q75: What is prototyping and why is it useful?
**A:** Prototyping builds an interactive mock-up to test flow and feel early, validating ideas cheaply before committing engineering effort.

## Q76: What is the difference between low-fi and high-fi prototypes?
**A:** Low-fi uses sketches/wireframes to test structure fast; high-fi mimics final visuals/interactions to test look, feel, and usability.

## Q77: What is infinite scroll and when should you use it?
**A:** Infinite scroll auto-loads more content as users reach the bottom; ideal for exploratory feeds (social) but poor for findable, countable results.

## Q78: When should you use pagination instead?
**A:** Use pagination for search results, tables, or tasks needing reference points, location awareness, or deep linking where users jump between pages.

## Q79: What is progressive disclosure?
**A:** Progressive disclosure reveals information gradually, hiding advanced options until needed, reducing initial complexity (e.g., "Advanced settings").

## Q80: What is a hamburger menu?
**A:** A hamburger menu is the three-line icon that collapses navigation on small screens; convenient but can hide discoverability of key links.

## Q81: What is the tab bar pattern in mobile UI?
**A:** A bottom tab bar gives persistent access to 3–5 top destinations on mobile, leveraging thumb reach at the screen bottom.

## Q82: What is consistency vs creativity in UI?
**A:** Consistency aids learnability; creativity differentiates a brand—balance by innovating within familiar, predictable interaction patterns.

## Q83: What are common UI mistakes?
**A:** Inconsistent labeling, poor contrast, tiny touch targets, no empty/error states, cluttered layouts, and ignoring accessibility are frequent mistakes.

## Q84: How should designers and developers collaborate?
**A:** Share design tokens, agree on component APIs, involve devs early in design reviews, and use tools (Figma, Storybook) as a shared source of truth.

## Q85: What role do frontend frameworks play in UI?
**A:** Frameworks like React and Vue manage component state and rendering, enabling reusable, data-driven UI components and efficient updates.

## Q86: How does React help build UI?
**A:** React uses declarative components and a virtual DOM so you compose UIs from reusable pieces and efficiently re-render on state changes.

## Q87: What is a component in modern frontend UI?
**A:** A component is a self-contained, reusable UI unit (markup + style + logic) like a `<Button>` or `<Card>` that encapsulates its own behavior.

## Q88: How does CSS contribute to UI implementation?
**A:** CSS controls layout (Flexbox/Grid), visual styling, responsiveness, and theming (variables), translating design into rendered pixels.

## Q89: What is the difference between Flexbox and Grid?
**A:** Flexbox lays out items in one dimension (row or column) for components; Grid handles two-dimensional layouts (rows and columns) for full pages.

## Q90: What is perceived performance?
**A:** Perceived performance is how fast an interface feels, improved via optimistic UI, skeletons, and instant feedback even before data loads.

## Q91: What is a skeleton screen?
**A:** A skeleton screen shows a grayed placeholder mimicking the layout while content loads, reducing perceived wait versus a blank or spinner.

## Q92: When should you use a toast versus an alert/dialog?
**A:** Use a toast for non-blocking, transient confirmations (saved!); use an alert/dialog for blocking, critical decisions requiring acknowledgment.

## Q93: What is optimistic UI?
**A:** Optimistic UI updates the interface immediately as if the action succeeded, then reconciles if the server responds with an error, feeling instant.

## Q94: What is onboarding in UI?
**A:** Onboarding guides new users to first value via tooltips, walkthroughs, or empty-state prompts, reducing drop-off and teaching key features.

## Q95: What are best practices for onboarding?
**A:** Keep it short, contextual, skippable, and action-oriented—let users learn by doing rather than long tutorials.

## Q96: What is iconography and why use icons?
**A:** Icons are visual symbols that speed recognition and save space, but should be paired with labels when meaning isn't universally clear.

## Q97: What are mobile UI guidelines (iOS HIG / Material)?
**A:** iOS HIG emphasizes clarity, deference, and depth with safe areas and SF fonts; Material uses bold color, elevation, and motion for Android/web.

## Q98: What is cross-platform UI?
**A:** Cross-platform UI delivers a consistent experience across web, iOS, and Android, using shared design systems and frameworks like Flutter or React Native.

## Q99: What is visual regression testing?
**A:** Visual regression testing captures screenshots and compares them across builds to catch unintended UI changes (e.g., with Percy or Chromatic).

## Q100: How do you test UI usability?
**A:** Combine usability testing (watch real users), heuristic evaluation, A/B tests, and accessibility audits to validate that the UI is effective and pleasant.
