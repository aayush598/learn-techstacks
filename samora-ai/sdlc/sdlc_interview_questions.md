# SDLC Interview Questions (Top 100)

## 1. What is SDLC?
Software Development Life Cycle is a structured process for building software through defined phases.

## 2. Why is SDLC important?
It provides a plan, reduces risks, improves quality, controls cost, and ensures stakeholder alignment.

## 3. What are the main phases of SDLC?
Requirement analysis, planning, design, implementation (coding), testing, deployment, maintenance.

## 4. What is requirement gathering?
Collecting and documenting what the users and business need from the software.

## 5. What is the difference between functional and non-functional requirements?
Functional define what the system does; non-functional define how well (performance, security).

## 6. What is a feasibility study?
Assessing technical, economic, and operational viability of a proposed project.

## 7. What is the Waterfall model?
A linear sequential SDLC where each phase completes before the next begins.

## 8. Advantages of Waterfall?
Simple, well-documented, clear milestones, easy to manage for stable requirements.

## 9. Disadvantages of Waterfall?
Inflexible to change, late testing, high risk if requirements shift.

## 10. What is the Agile model?
An iterative, incremental approach delivering working software in short cycles (sprints).

## 11. What are Agile principles?
Customer collaboration, responding to change, working software, individuals and interactions.

## 12. What is a sprint?
A fixed short iteration (usually 1-4 weeks) producing a potentially shippable increment.

## 13. What is Scrum?
A popular Agile framework with roles (PO, Scrum Master, Team), events, and artifacts.

## 14. What are Scrum roles?
Product Owner, Scrum Master, Development Team.

## 15. What are Scrum artifacts?
Product Backlog, Sprint Backlog, Increment.

## 16. What are Scrum ceremonies?
Sprint Planning, Daily Standup, Sprint Review, Sprint Retrospective.

## 17. What is a Product Backlog?
A prioritized list of features, bugs, and work maintained by the Product Owner.

## 18. What is a user story?
A short description of a feature from the user's perspective: "As a [role], I want [goal] so that [benefit]."

## 19. What is a use case?
A description of interactions between actors and the system to achieve a goal.

## 20. What is the difference between Agile and Waterfall?
Agile is iterative and adaptive; Waterfall is sequential and plan-driven.

## 21. What is the V-Model?
A verification and validation model where each development phase has a corresponding testing phase.

## 22. What is the Spiral model?
A risk-driven model combining iterative development with systematic risk analysis.

## 23. What is the Iterative model?
Development happens in repeated cycles, refining the product each iteration.

## 24. What is the Incremental model?
Software is built and delivered in small functional increments.

## 25. What is the RAD model?
Rapid Application Development focuses on quick prototyping and user feedback.

## 26. What is DevOps in SDLC?
Practices combining development and operations for continuous delivery and automation.

## 27. What is CI slash CD?
Continuous Integration (frequent merging or testing) and Continuous Delivery or Deployment (automated release).

## 28. What is Continuous Integration?
Developers frequently merge code; automated builds and tests run to catch issues early.

## 29. What is Continuous Deployment?
Every passing change is automatically deployed to production.

## 30. What is Continuous Delivery?
Code is always in a releasable state; deployment is manual but automated-ready.

## 31. What is the difference between verification and validation?
Verification checks "are we building it right?" (process); validation checks "are we building the right thing?" (product).

## 32. What is a software requirement specification (SRS)?
A document detailing functional and non-functional requirements of the system.

## 33. What is design phase in SDLC?
Translating requirements into architecture, data models, interfaces, and algorithms.

## 34. What is high-level design (HLD)?
Overall system architecture: modules, components, and their interactions.

## 35. What is low-level design (LLD)?
Detailed design of modules: classes, functions, data structures, logic.

## 36. What is coding or implementation phase?
Writing the actual source code following design and coding standards.

## 37. What is software testing?
Evaluating software to find defects and verify it meets requirements.

## 38. What are the levels of testing?
Unit, Integration, System, Acceptance testing.

## 39. What is unit testing?
Testing individual components or functions in isolation (often automated, for example, JUnit).

## 40. What is integration testing?
Testing interactions between integrated modules or components.

## 41. What is system testing?
Testing the complete integrated system against requirements.

## 42. What is acceptance testing?
Confirming the system meets business needs; includes UAT (user acceptance testing).

## 43. What is regression testing?
Re-testing to ensure new changes did not break existing functionality.

## 44. What is the difference between white-box and black-box testing?
White-box tests internal logic (code-aware); black-box tests functionality without code knowledge.

## 45. What is grey-box testing?
Combines black-box and white-box approaches with partial internal knowledge.

## 46. What is test-driven development (TDD)?
Writing tests before code, then implementing to pass them (Red-Green-Refactor).

## 47. What is behavior-driven development (BDD)?
Extending TDD using natural-language scenarios (Given-When-Then) for collaboration.

## 48. What is a bug or defect?
A flaw causing software to behave incorrectly versus requirements.

## 49. What is a bug lifecycle?
New to Assigned to Open to Fixed to Retest to Closed (or Reopened).

## 50. What is a test case?
A set of conditions, inputs, and expected results to verify a feature.

## 51. What is a test plan?
A document outlining testing scope, approach, resources, and schedule.

## 52. What is deployment?
Releasing the software to a production or staging environment for users.

## 53. What is a release?
A version of the software made available to users.

## 54. What is maintenance phase?
Fixing bugs, enhancing features, and adapting software after deployment.

## 55. What is corrective maintenance?
Fixing defects found after release.

## 56. What is adaptive maintenance?
Modifying software to work in changed environments (OS, hardware).

## 57. What is perfective maintenance?
Improving performance or adding enhancements requested by users.

## 58. What is preventive maintenance?
Refactoring to prevent future problems.

## 59. What is software prototyping?
Building an early model to validate requirements and design with users.

## 60. What is a throwaway prototype?
A prototype discarded after learning, used to explore requirements.

## 61. What is an evolutionary prototype?
A prototype refined into the final product over time.

## 62. What is risk management in SDLC?
Identifying, assessing, and mitigating risks that could impact the project.

## 63. What is a milestone?
A significant point marking progress (for example, design sign-off).

## 64. What is a deliverable?
A tangible output of a phase (for example, SRS document, tested build).

## 65. What is scope creep?
Uncontrolled expansion of project scope without adjustments to time or cost.

## 66. What is a change request?
A formal proposal to modify requirements, design, or scope.

## 67. What is configuration management?
Controlling changes to software artifacts (versions, baselines) via tools like Git.

## 68. What is version control?
Tracking and managing changes to code (for example, Git, SVN).

## 69. What is a baseline?
An agreed, fixed reference point in the SDLC (for example, approved design).

## 70. What is the role of a project manager in SDLC?
Planning, scheduling, resource allocation, risk management, and stakeholder communication.

## 71. What is the role of a business analyst?
Eliciting requirements, bridging business needs and technical teams.

## 72. What is the role of a QA engineer?
Designing and executing tests to ensure quality and report defects.

## 73. What is the role of a developer?
Designing, coding, and unit-testing software components.

## 74. What is a software metric?
A quantitative measure of a software attribute (for example, LOC, defect density).

## 75. What is defect density?
Number of defects per size unit (for example, per KLOC), indicating quality.

## 76. What is code review?
Peer examination of code to find defects and ensure standards before merge.

## 77. What is pair programming?
Two developers working together at one workstation (one drives, one reviews).

## 78. What is refactoring?
Improving internal structure of code without changing external behavior.

## 79. What is technical debt?
Compromise in code quality taken for speed, accruing future maintenance cost.

## 80. What is the difference between iterative and incremental?
Iterative refines via cycles; incremental adds functionality in pieces (often combined).

## 81. What is Kanban?
A flow-based Agile method using a board with WIP limits (no fixed iterations).

## 82. Difference between Scrum and Kanban.
Scrum has fixed sprints or roles; Kanban is continuous flow with WIP limits.

## 83. What is a burndown chart?
A chart showing remaining work over time in a sprint or project.

## 84. What is a burnup chart?
Shows completed work and total scope over time, highlighting scope changes.

## 85. What is definition of done (DoD)?
Agreed criteria a user story must meet to be considered complete.

## 86. What is definition of ready (DoR)?
Criteria indicating a backlog item is clear and actionable before sprint start.

## 87. What is MoSCoW prioritization?
Must, Should, Could, Won't — a method to prioritize requirements.

## 88. What is the difference between SRS and a design document?
SRS states WHAT is needed; design documents state HOW to build it.

## 89. What is UML?
Unified Modeling Language: visual diagrams (use case, class, sequence) for design.

## 90. What is a class diagram?
A UML diagram showing classes, attributes, methods, and relationships.

## 91. What is a sequence diagram?
A UML diagram showing object interactions over time.

## 92. What is the importance of documentation in SDLC?
Captures knowledge, aids onboarding, supports maintenance and compliance.

## 93. What is the difference between alpha and beta testing?
Alpha is internal pre-release testing; beta is limited external user testing.

## 94. What is a pilot deployment?
Releasing to a small group first to validate before full rollout.

## 95. What is blue-green deployment?
Running two identical environments; switch traffic to the new one for zero-downtime release.

## 96. What is canary release?
Gradually rolling out a change to a subset of users before full deployment.

## 97. What is rollback?
Reverting to a previous stable version after a failed deployment.

## 98. What is the difference between maintenance and evolution?
Maintenance fixes or adapts; evolution adds significant new capabilities over time.

## 99. What is software quality assurance (SQA)?
Processes ensuring quality throughout the SDLC, not just testing at the end.

## 100. How do you choose an SDLC model?
Based on project size, requirement stability, risk, team distribution, and need for speed.
