# SDLC (Software Development Life Cycle) — 100 Interview Q&A

---

## Q1: What is SDLC?
**A:** Software Development Life Cycle is a structured process for building software through defined phases.

## Q2: Why is SDLC important?
**A:** It provides a plan, reduces risks, improves quality, controls cost, and ensures stakeholder alignment.

## Q3: What are the main phases of SDLC?
**A:** Requirement analysis, planning, design, implementation (coding), testing, deployment, maintenance.

## Q4: What is requirement gathering?
**A:** Collecting and documenting what the users and business need from the software.

## Q5: What is the difference between functional and non-functional requirements?
**A:** Functional define what the system does; non-functional define how well (performance, security).

## Q6: What is a feasibility study?
**A:** Assessing technical, economic, and operational viability of a proposed project.

## Q7: What is the Waterfall model?
**A:** A linear sequential SDLC where each phase completes before the next begins.

## Q8: Advantages of Waterfall?
**A:** Simple, well-documented, clear milestones, easy to manage for stable requirements.

## Q9: Disadvantages of Waterfall?
**A:** Inflexible to change, late testing, high risk if requirements shift.

## Q10: What is the Agile model?
**A:** An iterative, incremental approach delivering working software in short cycles (sprints).

## Q11: What are Agile principles?
**A:** Customer collaboration, responding to change, working software, individuals and interactions.

## Q12: What is a sprint?
**A:** A fixed short iteration (usually 1-4 weeks) producing a potentially shippable increment.

## Q13: What is Scrum?
**A:** A popular Agile framework with roles (PO, Scrum Master, Team), events, and artifacts.

## Q14: What are Scrum roles?
**A:** Product Owner, Scrum Master, Development Team.

## Q15: What are Scrum artifacts?
**A:** Product Backlog, Sprint Backlog, Increment.

## Q16: What are Scrum ceremonies?
**A:** Sprint Planning, Daily Standup, Sprint Review, Sprint Retrospective.

## Q17: What is a Product Backlog?
**A:** A prioritized list of features, bugs, and work maintained by the Product Owner.

## Q18: What is a user story?
**A:** A short description of a feature from the user's perspective: "As a [role], I want [goal] so that [benefit]."

## Q19: What is a use case?
**A:** A description of interactions between actors and the system to achieve a goal.

## Q20: What is the difference between Agile and Waterfall?
**A:** Agile is iterative and adaptive; Waterfall is sequential and plan-driven.

## Q21: What is the V-Model?
**A:** A verification and validation model where each development phase has a corresponding testing phase.

## Q22: What is the Spiral model?
**A:** A risk-driven model combining iterative development with systematic risk analysis.

## Q23: What is the Iterative model?
**A:** Development happens in repeated cycles, refining the product each iteration.

## Q24: What is the Incremental model?
**A:** Software is built and delivered in small functional increments.

## Q25: What is the RAD model?
**A:** Rapid Application Development focuses on quick prototyping and user feedback.

## Q26: What is DevOps in SDLC?
**A:** Practices combining development and operations for continuous delivery and automation.

## Q27: What is CI slash CD?
**A:** Continuous Integration (frequent merging or testing) and Continuous Delivery or Deployment (automated release).

## Q28: What is Continuous Integration?
**A:** Developers frequently merge code; automated builds and tests run to catch issues early.

## Q29: What is Continuous Deployment?
**A:** Every passing change is automatically deployed to production.

## Q30: What is Continuous Delivery?
**A:** Code is always in a releasable state; deployment is manual but automated-ready.

## Q31: What is the difference between verification and validation?
**A:** Verification checks "are we building it right?" (process); validation checks "are we building the right thing?" (product).

## Q32: What is a software requirement specification (SRS)?
**A:** A document detailing functional and non-functional requirements of the system.

## Q33: What is design phase in SDLC?
**A:** Translating requirements into architecture, data models, interfaces, and algorithms.

## Q34: What is high-level design (HLD)?
**A:** Overall system architecture: modules, components, and their interactions.

## Q35: What is low-level design (LLD)?
**A:** Detailed design of modules: classes, functions, data structures, logic.

## Q36: What is coding or implementation phase?
**A:** Writing the actual source code following design and coding standards.

## Q37: What is software testing?
**A:** Evaluating software to find defects and verify it meets requirements.

## Q38: What are the levels of testing?
**A:** Unit, Integration, System, Acceptance testing.

## Q39: What is unit testing?
**A:** Testing individual components or functions in isolation (often automated, for example, JUnit).

## Q40: What is integration testing?
**A:** Testing interactions between integrated modules or components.

## Q41: What is system testing?
**A:** Testing the complete integrated system against requirements.

## Q42: What is acceptance testing?
**A:** Confirming the system meets business needs; includes UAT (user acceptance testing).

## Q43: What is regression testing?
**A:** Re-testing to ensure new changes did not break existing functionality.

## Q44: What is the difference between white-box and black-box testing?
**A:** White-box tests internal logic (code-aware); black-box tests functionality without code knowledge.

## Q45: What is grey-box testing?
**A:** Combines black-box and white-box approaches with partial internal knowledge.

## Q46: What is test-driven development (TDD)?
**A:** Writing tests before code, then implementing to pass them (Red-Green-Refactor).

## Q47: What is behavior-driven development (BDD)?
**A:** Extending TDD using natural-language scenarios (Given-When-Then) for collaboration.

## Q48: What is a bug or defect?
**A:** A flaw causing software to behave incorrectly versus requirements.

## Q49: What is a bug lifecycle?
**A:** New to Assigned to Open to Fixed to Retest to Closed (or Reopened).

## Q50: What is a test case?
**A:** A set of conditions, inputs, and expected results to verify a feature.

## Q51: What is a test plan?
**A:** A document outlining testing scope, approach, resources, and schedule.

## Q52: What is deployment?
**A:** Releasing the software to a production or staging environment for users.

## Q53: What is a release?
**A:** A version of the software made available to users.

## Q54: What is maintenance phase?
**A:** Fixing bugs, enhancing features, and adapting software after deployment.

## Q55: What is corrective maintenance?
**A:** Fixing defects found after release.

## Q56: What is adaptive maintenance?
**A:** Modifying software to work in changed environments (OS, hardware).

## Q57: What is perfective maintenance?
**A:** Improving performance or adding enhancements requested by users.

## Q58: What is preventive maintenance?
**A:** Refactoring to prevent future problems.

## Q59: What is software prototyping?
**A:** Building an early model to validate requirements and design with users.

## Q60: What is a throwaway prototype?
**A:** A prototype discarded after learning, used to explore requirements.

## Q61: What is an evolutionary prototype?
**A:** A prototype refined into the final product over time.

## Q62: What is risk management in SDLC?
**A:** Identifying, assessing, and mitigating risks that could impact the project.

## Q63: What is a milestone?
**A:** A significant point marking progress (for example, design sign-off).

## Q64: What is a deliverable?
**A:** A tangible output of a phase (for example, SRS document, tested build).

## Q65: What is scope creep?
**A:** Uncontrolled expansion of project scope without adjustments to time or cost.

## Q66: What is a change request?
**A:** A formal proposal to modify requirements, design, or scope.

## Q67: What is configuration management?
**A:** Controlling changes to software artifacts (versions, baselines) via tools like Git.

## Q68: What is version control?
**A:** Tracking and managing changes to code (for example, Git, SVN).

## Q69: What is a baseline?
**A:** An agreed, fixed reference point in the SDLC (for example, approved design).

## Q70: What is the role of a project manager in SDLC?
**A:** Planning, scheduling, resource allocation, risk management, and stakeholder communication.

## Q71: What is the role of a business analyst?
**A:** Eliciting requirements, bridging business needs and technical teams.

## Q72: What is the role of a QA engineer?
**A:** Designing and executing tests to ensure quality and report defects.

## Q73: What is the role of a developer?
**A:** Designing, coding, and unit-testing software components.

## Q74: What is a software metric?
**A:** A quantitative measure of a software attribute (for example, LOC, defect density).

## Q75: What is defect density?
**A:** Number of defects per size unit (for example, per KLOC), indicating quality.

## Q76: What is code review?
**A:** Peer examination of code to find defects and ensure standards before merge.

## Q77: What is pair programming?
**A:** Two developers working together at one workstation (one drives, one reviews).

## Q78: What is refactoring?
**A:** Improving internal structure of code without changing external behavior.

## Q79: What is technical debt?
**A:** Compromise in code quality taken for speed, accruing future maintenance cost.

## Q80: What is the difference between iterative and incremental?
**A:** Iterative refines via cycles; incremental adds functionality in pieces (often combined).

## Q81: What is Kanban?
**A:** A flow-based Agile method using a board with WIP limits (no fixed iterations).

## Q82: Difference between Scrum and Kanban.
**A:** Scrum has fixed sprints or roles; Kanban is continuous flow with WIP limits.

## Q83: What is a burndown chart?
**A:** A chart showing remaining work over time in a sprint or project.

## Q84: What is a burnup chart?
**A:** Shows completed work and total scope over time, highlighting scope changes.

## Q85: What is definition of done (DoD)?
**A:** Agreed criteria a user story must meet to be considered complete.

## Q86: What is definition of ready (DoR)?
**A:** Criteria indicating a backlog item is clear and actionable before sprint start.

## Q87: What is MoSCoW prioritization?
**A:** Must, Should, Could, Won't — a method to prioritize requirements.

## Q88: What is the difference between SRS and a design document?
**A:** SRS states WHAT is needed; design documents state HOW to build it.

## Q89: What is UML?
**A:** Unified Modeling Language: visual diagrams (use case, class, sequence) for design.

## Q90: What is a class diagram?
**A:** A UML diagram showing classes, attributes, methods, and relationships.

## Q91: What is a sequence diagram?
**A:** A UML diagram showing object interactions over time.

## Q92: What is the importance of documentation in SDLC?
**A:** Captures knowledge, aids onboarding, supports maintenance and compliance.

## Q93: What is the difference between alpha and beta testing?
**A:** Alpha is internal pre-release testing; beta is limited external user testing.

## Q94: What is a pilot deployment?
**A:** Releasing to a small group first to validate before full rollout.

## Q95: What is blue-green deployment?
**A:** Running two identical environments; switch traffic to the new one for zero-downtime release.

## Q96: What is canary release?
**A:** Gradually rolling out a change to a subset of users before full deployment.

## Q97: What is rollback?
**A:** Reverting to a previous stable version after a failed deployment.

## Q98: What is the difference between maintenance and evolution?
**A:** Maintenance fixes or adapts; evolution adds significant new capabilities over time.

## Q99: What is software quality assurance (SQA)?
**A:** Processes ensuring quality throughout the SDLC, not just testing at the end.

## Q100: How do you choose an SDLC model?
**A:** Based on project size, requirement stability, risk, team distribution, and need for speed.
